## 컨셉

**점성 슬라임** — 모든 표면에 달라붙는 것이 자연 상태. 이동은 크롤링과 차징 발사로 수행.
WASD + Space 키로 조작. 모든 시간 단위는 **초(seconds)** 기준.

**장르 지향**: 점프킹, Egging On, 셀레스트, 구구피자 계열의 정밀 플랫포머.
조작 반응성과 예측 가능성이 최우선. 소프트바디 비주얼은 게임플레이에 영향을 주지 않음.

## 구현 아키텍처 — 2단계 분리

- **Phase 1** (완료): 단일 원형 콜라이더 플랫포머. 충돌, 이동, 차징, 발사, 에어 컨트롤 — 전부 원 하나.
- **Phase 1.5** (완료): 절차적 변형 비주얼 — 코드 기반 squash/stretch. 물리와 완전 분리. 상세 [features/slime/visual-deformation.md](features/slime/visual-deformation.md).
- **Phase 2** (미구현): 소프트바디 비주얼 오버레이 — 중심 + 6개 노드 스프링. Phase 1.5를 교체 가능한 장기 옵션.

- Tilt — 라이더 무게로 기울어지는 시소 판자. v1(`TiltPlatform`)은 라이더 위치에 비례한 **목표 각도로 수렴하는 스프링**이라 라이더가 중앙을 지나면 목표가 0 이 되어 즉시 복원한다 — 반대쪽 끝까지 건너갈 시간이 없다. v2(`TiltPlatformV2`, 신규 파일 · v1 무수정)는 목표 각도를 버리고 **토크를 적분**한다: 팔 길이 → 각가속도 → 각속도 → 각도. 각속도가 상태로 남으니 라이더가 반대쪽으로 이동하는 동안에도 판자는 처음 밟은 쪽으로 계속 기울고, 반대쪽을 밟아 토크가 뒤집혀도 그 각속도를 먼저 죽여야 방향이 바뀐다. 게임플레이용 유예 항 `leverLag` 이 유효 팔 길이를 라이더 실제 위치의 지수 추종으로 만들어 뒤집힘을 한 번 더 늦춘다. 수평 복원 스프링은 기본 **0**(꺼짐)이고, 켜도 `(1−|lever|)` 로 가중돼 팔 길이가 감쇠하는 만큼만 페이드인한다 — 라이더 유무로 껐다 켜면 슬라임이 점프하는 프레임에 `-θ·k` 가 계단으로 들어와(15°·6 = +90 °/s², 라이더 토크의 2배) 판자가 즉시 평평해지고, 하중 아래에서 돌면 그게 v1 의 평형 수렴이라 적분기의 존재 이유가 사라진다. 한편 `|θ|>max` 하드 스톱이 `ω=0` 을 만들므로, 차징이 끝나기 전에 판자가 바닥에 닿으면 발사 후 물려줄 각속도가 애초에 없다 — 잔여 스윙을 보이게 하려면 `tiltAccel` 을 낮추거나 `maxTiltAngle` 을 올린다.

- [Bamboo](features/platforms/bamboo.md) — 수직 대나무. SpringyBranch 물리 식 + vertical 적용, N-segment collider polyline + single shader-bent cylinder visual (sub-pixel coincident). 기본적으로 visible node frequency를 physics `segmentCount`에 동기화해 보이는 마디/구간 경계가 물리 segment와 일치. 마디 bulge + sheath scar 지오메트리, Quibli-style 2-tone + height gradient color. `BambooSettings.enableTipGrab` / `enableSideReboundV2` 독립 bool 2개 (예전 상호배타 `interactionMode` enum 제거 — 둘 다 켜면 옆구리 V2 반동 + 꼭대기 tip-grab 동시 동작, 스프링 계수 우선순위 grab>v2>기본). V2는 측면 충돌을 더 크게 휘게 한 뒤 Space charging release 방향으로 발사한다. **발사 부스트 = 화면에 보이는 스윙(`ω × arm`)의 carrier 상속뿐** — charge power에 속도를 직접 더하던 raw 보너스 그래프(`v2ChargedLaunchBonus*`)는 대나무 휨 상태와 무관해 예측 불가라 삭제(2026-07-24), SpringyBranch와 같은 모델로 통일. 천장 = `maxTipSpeed × velocityTransferScale × v2CarrierScale`, 그리고 SpringyBranch/TautLine과 동일한 `boostFalloffStart/EndSpeed` 게이트로 이미 빠른 발사 위에는 스택되지 않는다. V2 launch-release 반작용은 전용 접촉 높이 보정 노브를 받아 아래쪽 점프는 덜 흔들리고 위쪽 점프는 더 크게 흔들린다. 루트 Transform Z 회전으로 **기울여 배치 가능** — tip-grab 진입 dot, V2 side-contact 판정, slam guard, bend pump 입력 속도가 모두 world up 대신 대나무 자신의 rest 축(`StalkUp`)/가로 속도 기준이라 기울여도 겉모습만이 아니라 판정까지 따라간다 (수직일 때는 이전과 수치 동일). 대나무 하강 jitter 원인 추적용 `BambooSurfaceJitterDebugger`를 슬라임에 붙여 segment switch / normal jump / carry residual / probe churn을 관측한다.
- [Bamboo V3](features/platforms/bamboo-v3.md) — **물리 기반 점프대 대나무 (신규 게임플레이용, v1은 그대로 유지).** 정직한 캔틸레버 ODE 하나 + 진짜 임펄스 3개(무게 `r×mg` / 착지 완전비탄성 포획 / 발사 뉴턴3법칙)로만 휜다 — 투영도 커브도 높이 보정도 없다(`r×J` 외적이 입사각을, `|r|`이 접촉 높이를 이미 처리). 비물리 규칙은 **접착 파단 하나**: 접촉점 표면 가속도 `a = |r|·√(α²+ω⁴)`가 `adhesionBreakAccel`을 넘으면 표면 속도 `ω×arm`을 들려 자동으로 튕겨낸다 → **세게 박으면 스페이스 없이 발사, 약하게 닿으면 그냥 발판.** 튕기는 타이밍은 스프링에서 저절로 나옴(rest 통과 직후 감속 최대 = 트램펄린 지점). 라이더 유무로 스프링/캡/감쇠가 안 바뀐다(v1이 발사 반동을 죽이던 주범). 발사 반작용은 `RemoveRider`가 아니라 **`OnLaunch` 이벤트**로 잡는다 — 붙은 슬라임의 `velocity`가 carrier 운반분을 빠뜨려서 detach 시점 속도로는 발사/기어감/hazard/teleport를 구분할 수 없기 때문. **노브 26→5** (`naturalFreqHz` 2.0, `dampingRatio` 0.3, `maxDeflectionDeg` 60, `maxTipSpeed` 18, `adhesionBreakAccel` 40). SlimeController 수정 0 — 기존 `OnAfterMotion`/`ForceAirborneWithVelocity`/`OnLaunch`/`ISurfaceAnchorProvider` 훅만 사용. 발사 부스트는 `launchBoostScale`에 SpringyBranch/TautLine과 동일한 `boostFalloffStart/EndSpeed` pre-bonus 게이트(2026-07-26)를 곱해, 이미 빠른 발사 위에는 줄기 부스트가 스택되지 않는다. **밑면 매달림은 "던져질 수 있나"로 갈린다**: 대나무 표면은 글로벌 천장 한계를 180°로 덮어써서 밑에서 때린 슬라임이 부착하고 스프링이 로드될 동안 붙어 있는다. 지금 스윙이 throw 게이트(peak bend·사출 속도)를 만족시킬 수 있으면 던져질 때까지 매달리고, 못 던지는 스윙이면(약한 접촉·링다운으로 소진된 스윙·스프링 없는 쓰러진 장대) `underhangClingTime` 0.2초만 붙어 있다 미끄러진다 — 매달리기가 영구 상태가 되지 않는다. **착지 피드백은 "이 착지가 얼마나 크게 던질 것인가"로 갈린다**: 플레이어는 삐걱 소리를 충격이 아니라 **뒤따르는 점프**에 견줘 듣는다. 착지 프레임에 스윙의 위상공간 진폭 `√(θ² + ((ω+Δω)/ω_n)²)` 을 구해 팁속도 `A·ω_n·L` 로 환산하고, 그 값으로 삐걱 소리 **한 클립의 음량**을 정하며(크게 던질수록 크게) 접촉점 먼지 퍼프의 개수·크기도 같은 값에 비례한다. 휨각만 보면 안 된다 — 스윙을 밀어주는 약한 착지는 크게 던지고, 되돌아오는 줄기를 때리는 센 착지는 못 던진다 — 실제 최대 휨은 1/4 주기 뒤라 그때 울리면 별개 사건으로 들린다. 소리는 **한 번만 울고, 줄기가 거의 멈추거나(|각속도| < 문턱) 라이더가 떠나면 페이드아웃한다** — 조금만 움직이는 줄기는 소리를 내지 않으므로, 착지 후 휘어 들어가는 구간에서 울고 되돌아오는 구간은 조용하다. 피드백 컴포넌트는 **각 스탈크에 붙고**(슬라임에는 디버그 컴포넌트만 붙인다) 튜닝은 전부 공유 `BambooLandingFeedbackConfig`. 발사·통통 소리는 대나무 SurfaceMaterial 슬롯(`launchSound`/`hopSound`)에 얹혀 있다. 표면 사운드는 기본적으로 슬라임 자체 소리를 **대체**하지만 `layerOverSlimeSound` 를 켜면 **겹쳐서** 난다(몸통 소리 + 표면 소리 2레이어) — 대나무·철근 시소·나뭇가지 3종이 켜져 있다.
- Bamboo On ThinIce — **BambooV3 × ThinIceV2 결합.** 얼음 위에 선 대나무: 대나무 착지 N회(기본 3)마다 밑의 얼음이 한 단계씩 금 가고, 단계마다 **전용 금 소리(단계별 SoundDef 배열)와 얼음 부스러기 버스트**가 터진다. **마지막 착지는 발 밑에서 바로 깨지지 않는다** — 도화선만 붙고, 슬라임이 장대를 떠난 뒤 `shatterFuseSeconds`(0.2초) 지나야 얼음이 내려앉는다(점프든 미끄러져 떨어지든 이탈이면 된다). 장대에 계속 머물면 `shatterMaxHoldSeconds`(3초) 상한 뒤 그냥 무너진다. 얼음이 깨지면 — 대나무 점프 때문이든 슬라임이 얼음을 직접 밟아서든 — 대나무가 Falling Train 방식으로 물리 낙하한다(현재 스윙 각속도를 물려받아 넘어지고, 라이더는 태운 채 떨어지며, 안착하면 밟을 수 있는 데브리로 굳음). 쓰러진 corpse는 장대 전체 길이를 따라 먼지 퍼프를 터뜨리며 "뿅" 사라진다(포프 — 착지 먼지와 동일한 퍼프). 사라지는 조건은 셋 중 먼저 오는 것: 붕괴 후 `corpseMaxLifeSeconds`(4초) 경과 / 멈춘 뒤(Box2D 수면 또는 지면 Static 안착) `corpseRestPoofSeconds`(2초) 경과 / zone 밖으로 완전히 굴러 나감. 원래 대나무가 다시 설 때도 **똑같은 퍼프**가 새로 선 장대의 길이를 따라 터진다. corpse 수명은 재생성 타이밍과 독립이라, 떨어진 장대와 다시 선 대나무가 한동안 **동시에 존재할 수 있다**. 쓰러진 corpse가 다른 살아있는 대나무 위에 얹히면 그 대나무가 무게로 휘고(전용 bambooMass 노브), 슬라임이 corpse 위에서 점프하면 반동으로 corpse가 밀린다(corpseRecoilImpulse). **그 위의 슬라임도 받침 대나무까지 전달된다**(`ridingSlimeMass`): 올라타 있는 동안의 무게, 착지하는 순간의 충격, 발사로 떠날 때의 반동 3채널 — 다리처럼 두 대나무에 걸쳐 있으면 각 받침이 절반씩 받는다. 얹힌 corpse는 **라이더가 아니라 외부 하중**으로 전달되므로(라이더 슬롯은 슬라임 전용), corpse가 얹혀 있어도 슬라임이 그 대나무에 착지하면 평소와 똑같이 랜딩킥이 들어가 휜다. 쓰러진 대나무는 붕괴 `respawnDelaySeconds`(2초) 뒤 얼음과 함께 자동 복구되고, 그 전에 슬라임이 존을 벗어나면 그 즉시 복구된다. 낙하 중인 corpse는 자기 라이더(붙어 있는 슬라임)와 물리 충돌하지 않는다 — 라이더는 표면 앵커가 잡고 있고, 밑면에 매달린 슬라임과의 접촉은 낙하를 제동만 했다. 부분적으로 금 간 얼음은 슬라임이 respawn zone을 벗어나면 초기화되고, 존 안에 있어도 대나무에 접촉이 `crackHealSeconds`(2초)간 없으면 금이 회복된다 — 부분 진행분이 무기한 남아 있지 않는다. **기존 파일 0 수정** — 신규 `BambooOnThinIce` 컴포넌트(얼음 GO에 부착)가 public 표면 폴링 + corpse 클론 스왑으로만 구현, 파일 삭제 = 완전 롤백. 노브는 per-instance `jumpsToShatter` 하나.

- Swinging Bell — 슬라임이 몸통박치기하면 흔들리는 매달린 종 (`SwingingBell : PlatformMotor`). 소리는 충돌이 아니라 **추가 종 내벽에 닿을 때** 난다: 슬라임 충격 → 종 스윙(φ₁) → 추가 뒤늦게 따라옴(φ₂) → `|φ₁−φ₂| = α` 에서 타종. yoke-bell-clapper 이중 물리진자 (Brzeski/Kapitaniak/Perlikowski, arXiv:1505.04389 §2.2–2.3 — 실측 2633kg 종으로 검증된 모델) 를 그대로 적분하고, 타격은 각운동량 보존 + 에너지 반발계수 k=0.05 로 푼다. 조인트 없음 — 링 피벗 기준 강체 회전을 `MovePosition`+`MoveRotation` 으로 직접 씀 (Box2D 힌지는 이 타격법을 표현 못 하고, repo 가 이미 두 번 기각한 경로). 추는 콜라이더 없는 비주얼 전용이고 타격 판정은 기하 조건. 슬라임 접촉은 **파고드는 속도 한 문턱으로 갈린다**(`hardHitSpeed`) — 종 표면에 대한 상대 접근 성분만 세므로 타고 미끄러지는 건 아무리 빨라도 타격이 아니고, 문턱을 넘으면 속도와 무관하게 항상 같은 풀 스윙 + 종 축 바깥으로 사출(대나무의 "빠른 도착은 붙지 않는다"와 같은 `ForceAirborneWithVelocity` 경로) + `reattachBlockSeconds`(0.3s) 동안 이 종에 재부착 금지, 문턱 아래는 소리 없이 살짝 미는 반응만. 판정은 **방문(visit) 단위 1회** — 슬라임이 종에 올라온 순간 딱 한 번 재고, 붙어서 기어다니든 미끄러지든 재판정 없으며, 종에서 떨어져 `impactCooldown`(0.3s) 만큼 공백이 생겨야 다음 방문이 성립한다. 방문 경계는 접점과 캐리어를 **둘 다** 봐야 잡힌다: SurfaceProbe 가 물리 접점보다 한 틱 먼저 붙이므로 접점만 보면 도착을 놓치고, 캐리어만 보면 공중으로 나간 슬라임을 못 놓아준다. 도착 속도는 캐리어가 부착 순간 넘겨주는 실제 속도를 쓴다(착지 캡처 재구성은 딴 데 착지한 값이 남아 유령 슬램을 냈다). 종 위에서 발사해 떠날 때도 반작용으로 종이 흔들린다 — 훅은 `SlimeController.OnLaunch`. *(2026-08-06: 예전엔 `RemoveRider` 에 걸려 있었는데 정반대로 동작했다 — 진짜 발사 때는 Detach 시점 상태가 Charging 이라 안 터지고, 종에서 흘러내려 **다른 표면에 착지하는 순간** 터졌다.)* 튜닝 = `BellConfig` SO
- Swinging Bell V2 — 같은 매달린 종을 **접촉 프레임 기준**으로 다시 만든 것 (`SwingingBellV2 : PlatformMotor` + `BellV2Config` SO). 닿으면 그 틱에 소리·사출·스윙이 전부 확정된다 — 스윙은 타격의 *결과를 보여주는 것*이지 타격 여부를 정하는 것이 아니다. V1 은 추가 내벽에 닿아야 소리가 나서 접촉과 소리 사이에 0.3~2초가 벌어졌고, 이미 흔들리는 종을 반대 위상에 치면 스윙이 상쇄돼 아무 일도 안 일어났다 (구름↔종 왕복 리듬 맵을 만들 수 없던 이유). **방향 조건은 없다** — 종이 어느 쪽으로 흔들릴지는 접점이 종 축의 어느 쪽에 있는지만 보고 정하고 슬라임의 진행 방향을 안 읽는다. **모든 접촉은 종과 슬라임을 둘 다 움직인다**: 슬라임은 종에 절대 붙지 않고(종 축 바깥으로 튕겨나감, 세기는 `bounceRestitution`), 종은 최소 `softSwingDegrees` 만큼은 반드시 흔들린다. **속도가 정하는 건 "소리가 나느냐"뿐** — `minRingSpeed` 아래면 종은 움직이되 무음이고, 스윙 각도는 `minRingSpeed`~`fullSwingSpeed` 사이에서만 soft→full 로 램프한 뒤 고정이라 세게 쳐도 다른 종처럼 보이지 않는다. 속도 판정은 **슬라임 자기 도착 속력의 크기**로 재지, 면을 파고드는 성분으로도 종의 스윙을 뺀 상대속도로도 재지 않는다 — 그래야 수직 낙하 타격이 수평 타격과 같은 값을 받고(V1 이 조용히 기각하던 케이스), 흔들리는 종과 멈춘 종이 같은 반응을 준다. **사출 방향은 접점이 앉은 종 축 바깥쪽 하나로 고정**이고 도착 방향은 전혀 안 읽는다 — 반사로 두면 접선 성분이 남아 종 밑면을 치면 아래로 던져지는 등 결과를 미리 못 읽는다. 도착 속도는 방향을 통째로 버리고 **크기만** 사출 속력에 쓴다: 세게 치면 멀리, 살살 치면 조금 튕긴다. 붙지 않게만 `minSeparationSpeed` 바닥을 깐다. **예외는 스커트 안쪽 접촉 하나** — 종 축 바깥쪽은 안에서는 벽을 향하므로, 안쪽 타격은 종 축을 따라 **입구 밖으로** 사출한다(종이 흔들릴 방향은 그대로 접점의 플랭크가 정한다). 안/밖 판정은 슬라임 중심에서 종 축을 따라 위로 쏜 레이캐스트가 종 자신에게 걸리느냐 — 종 외곽은 위로 갈수록 좁아지므로 플랭크 접촉은 위가 비어 있다. 나가는 동안 `mouthExitTime` 만큼 종을 통과 처리해 림에 걸리거나 닫힌 입구에 막히지 않게 한다. 스윙 물리(이중진자 + 추 내벽 접촉)는 V1 에서 그대로 이식했고 이제 순수 비주얼 — 추가 벽을 때려도 소리를 안 낸다. 방문당 1회(`retriggerCooldown` + 캐리어 rider 플래그 래치), 차징 중엔 사출 안 함. 배치 = 기존 종 GO 에 컴포넌트만 추가 — `SwingingBell` 은 지우지 않고 비활성 상태로 남겨 리빌 배선(`BellSoundWave`/`BellRevealCamera` 가 타입 참조로 물고 있음)을 유지하고, V2 가 접촉 시 그 ring 표면을 리플렉션으로 구동한다 (파일 삭제 = 완전 롤백)
- Bell Sound Wave Reveal — 종의 **소리 난 타종마다** 원형 음파가 퍼지고, 평소 투명한 발판이 파면이 지나는 순서대로 픽셀 단위로 드러났다 hold → fade 로 사라진다 (`BellSoundWave` 가 `SwingingBell.Struck` + `LastRingResult` 구독 → 파장 최대 8슬롯을 셰이더 전역으로 push). 발판 = **렌더러 2개 분리**: 본체 `Quibli/Stylized Lit (Bell Reveal)`(알파 = 파장 reveal 만, 트레일 무관) + 자식 goo 오버레이 `SlimeJumping/TrailGooOverlay`(기존 로컬 트레일 계약 그대로, goo 픽셀만) — **투명 상태에서도 goo 자국은 항상 보임** (유일한 상시 위치 힌트, `LocalTrailReceiver.stampStrengthMultiplier`/`stampRadiusMultiplier` 로 이 발판만 자국 강도·크기 배율). 콜라이더는 항상 solid — 비주얼만 게이팅. **완전히 드러난 발판은 원래 머티리얼과 같은 입체감으로 보인다** — ForwardLit 이 ZWrite On + 투명 픽셀 clip 이라 오목한 메시(패인 장식면)의 뒤쪽 면이 앞면을 통과해 비치지 않고, Quibli 그라디언트 램프를 물려 노멀별 명암이 살아난다. 파동 비주얼 = 전용 `BellWave_Distortion.shader` 굴절 링 — 얇은 환형 밴드만 그리고 안쪽(지나간 자리)/바깥은 완전 무효과, 크리스프 에지로 원형 외곽이 확실히 읽힘 (SpaceWarp 인프라 `SpaceWarpSourceFeature`+`SpaceWarpEffect.Trigger()` 쿼드 4개 라운드로빈은 그대로, reveal 파면과 속도 동기). 튜닝 = `BellSoundWaveConfig` SO, 테스트 = `SlimeJumping/Bell/Spawn Sound Wave Test Set` 메뉴 (씬 원본 무수정 복제 스폰). 맵에 **종 여러 개 배치 가능** — `BellSoundWave` 는 종 GO 에 붙고(`bell` 비우면 `GetComponentInParent` 자동 해석) 종을 복제하면 발신기까지 따라온다. 8슬롯은 전 종이 공유하는 static 풀, 매 프레임 첫 번째로 도는 인스턴스만 aging+push — 단 **파장 모양(속도/파면폭/hold/fade/최대반경)은 슬롯마다 그 슬롯을 채운 종의 config 를 따라가므로 종마다 config 를 다르게 물려 유지시간·속도를 갈라도 된다** (겹쳐 있는 두 파장이 서로 다른 hold 로 사라진다). **어느 종이 어느 발판을 드러내는지는 하이어라키가 정한다** — 종과 부모를 공유하는(그 그룹 GO 아래 임의 깊이) 리빌 발판이 그 종의 묶음이고, 다른 종 그룹의 발판은 이 종이 울려도 그대로 숨어 있다. 발판을 다른 그룹으로 드래그하면 소속이 바뀌고, 어느 종 그룹에도 없으면 영영 안 드러난다. 종 여럿이 한 부모를 공유하면 같은 묶음 — 어느 종을 울려도 같은 발판이 드러난다. 배선 = 번들 루트(부모)마다 부여받는 group id 를 파장 슬롯 `.w` 로 보내고 같은 id 를 묶음 렌더러에 `_BellWaveGroup` MPB 로 찍어 셰이더가 자기 종 파장만 채택. 종 렌더러 자체도 리빌 대상이 된다 — 번들 안 종에 리빌 머티리얼(`Mat_Bell_Reveal`)을 물리면 발판처럼 파면 따라 드러나고, 원본 URP Lit 종과 같은 look = 선형 `saturate(2u−1)` 램프(half-Lambert 좌표 보정) + Receive Shadows ON. 트레일 stamp 배율도 같은 묶음에서 나온다 — 수동 배선 배열(`hiddenPlatformReceivers`)은 낡은 발판을 가리키며 새 발판엔 config 값이 안 닿아 삭제, 이제 리빌 렌더러 위 `LocalTrailReceiver` 를 로드 시 모아 쓴다. 종은 OffscreenSleeper 명시적 제외 — 화면 밖에서 비활성되면 파장 슬롯이 비어 드러나 있던 발판이 즉시 사라진다. 왜곡 쿼드는 Awake 에서 부모 해제 — 흔들리는 종에 매달려 있으면 살아 있는 링이 끌려간다 **직접 그린 도형도 리빌 발판으로 설치할 수 있다** — TerrainShape2D(TerrainMaker) 인스펙터 맨 아래 "Bell Reveal Platform" 섹션의 버튼 하나로 메시 저장 → 리빌 머티리얼 → Z=0 단면 콜라이더 래퍼 → goo 오버레이 → `LocalTrailReceiver` 까지 테스트 리그와 같은 배선으로 스폰(설치 후 종 부모 밑으로 옮겨야 묶인다). 색은 머티리얼의 Quibli Gradient 로 정한다 — Quibli 는 램프 샘플이 곧 조명색이라 그라디언트 양끝이 밝은면/그늘색이고, 생성 메시엔 아틀라스 UV 가 없으므로 `_TextureImpact` 는 0 으로 둔다.
- Bell Reveal Camera — 소리 난 타종마다 카메라가 슬라임을 잠시 떠나 고정 영역(위쪽 temple 미로)을 보여주고 `revealSeconds` 후 돌아온다 (`BellRevealCamera` 가 `SwingingBell.Struck` + `LastRingResult` 구독 → 리빌 VCam Priority 를 200 으로 올렸다 내림). RainWorldZone 과 같은 메커니즘(VCam Priority + Brain 의 authored 블렌드)이지만 트리거가 슬라임 위치가 아니라 이벤트 — 드러낼 영역은 슬라임이 없는 곳이라 서브룸 판정으로는 못 고른다. 보여줄 영역은 **박스로 그린다** — 컴포넌트가 든 BoxCollider2D 를 씬에서 끌고 늘리면 VCam 이 그 박스가 화면에 꽉 차는 거리까지 물러난다(perspective 면 거리, ortho 면 OrthographicSize, 종횡비는 Brain 의 출력 카메라 것). 박스를 안 주면 VCam transform 이 그대로 화면. **전환 시간은 이 기능이 소유한다** — `BellRevealCameraConfig`(Resources 오토로드) 의 blendIn/blendOut/style 을 전환 구간 동안만 Brain 의 DefaultBlend 에 밀어넣고 끝나면 복원하므로(RainWorldZone 의 Cut 스냅샷 수법 그대로), 리빌 블렌드를 바꿔도 존 진입/이탈 블렌드는 안 변한다. 홀드는 기본적으로 **도착 시점부터** 세므로 노브 값 = 미로가 실제로 멈춰 있는 시간(총 이탈 = blendIn + hold + blendOut). 홀드는 타이머가 끝나도 **플레이어가 손 놓고 있는 동안 계속** 유지되고 첫 입력에 복귀한다. 그 동안 **음파의 투명화 시계도 멈춘다** — 파면이 다 퍼진 음파의 age 를 고정하므로(파면 진행 자체는 안 건드림) 드러난 발판이 카메라 앞에서 사라지지 않는다. **소리는 카메라를 안 따라간다** — AudioListener 가 Main Camera 에 붙어 있어 카메라가 40유닛 날아가면 3D 사운드(종 소리 자체)가 감쇠·팬 어긋남이 나므로, 리빌 동안만 임시 리스너로 넘겨 슬라임 쪽 청취 지점을 유지하고 끝나면 카메라 리스너로 되돌린다(동시에 켜지지 않게 끄고 켠다). 배선 누락·우선순위 패배·RainWorldZone 이 Brain 을 Cut 으로 물고 있는 순간의 하드컷은 각각 1회 로그로 드러난다.
- Afterimage Zone (잔상 존) — 존 트리거 안에서 슬라임 궤적이 그 순간 모습 그대로의 반투명 "잔상"으로 남고(시간 간격 + 최소 이동량 필터 — 제자리 차징/대기는 안 찍힘), 각 잔상은 등장 딜레이 0.3s 뒤에 나타나고(그 전엔 안 보임), 고스트 0.4s(콜라이더 없음, 슬라임과 겹친 동안은 굳지 않음 = 갇힘 방지) → 굳음(전면 부착 가능한 원형 콜라이더, 반경·레이어 config) → 생성 5s 에 소멸. 투명도 = 남은 수명(굳는 순간 짧은 선명 펄스 → 점점 흐려짐), 밟고 있어도 타이머는 흐른다. **잔상을 밟고 런치하면 충격파**: 은은한 물결(SpaceWarpEffect 쿼드 2개 라운드로빈) + 반경 내 잔상 전부 소거 + 그 영역 잠시 기록 침묵 — 반경 ≥ 잔상발 도약 높이로 튜닝하면 잔상 사다리 래칫 상승이 구조적으로 불가(재사용 = 문자 그대로 1회). 수동 이탈(마찰/외력 `ForceAirborneWithVelocity`)은 충격파를 안 쏨 = 의도된 비대칭. **점프 클리어 부채꼴**: 슬라임 기준 중력 반대 방향 부채꼴(길이·각도 config, gizmo 시각화) 안의 잔상은 굳은 상태 그대로 두되 슬라임만 통과(충돌+부착 무시) — 자기 arc 밑에 착지해도 점프가 자기 궤적 천장에 안 막힘. 비주얼 = `SlimeVisual3d` 서브트리 클론 + 얼굴 클론(그 순간 표정 스냅샷, 같은 알파 곡선) + MPB 명시 복사(변형이 전부 셰이더/TRS 라 필수) + 전용 투명 셰이더 `SlimeJumping/SlimeAfterimage`(SlimeBody_Quibli ForwardLit 사본, `_GhostAlpha` MPB 구동), 콜라이더는 슬라임 반경 원형 근사로 완전 분리. 구성 = `AfterimageZone : EnvironmentalZone` + `AfterimageStamp` + `AfterimageConfig` SO, SlimeController 무수정(OnLaunch/SurfaceCollider public API + 코요테 CachedSurfaceCollider 폴백), 테스트 = `SlimeJumping/Afterimage/Spawn Afterimage Zone Test Set` 메뉴

ESC 옵션 Actions = `Resume`(닫기)/`Quit`(메인 메뉴 복귀)/`New Game`(`GameFlow.NewGame` = 세이브·Trail 삭제 후 재시작) — 2026-08-13; 같은 날 시도한 메뉴 없는 부팅은 원복. **사당 엔딩 진입도 삭제**(2026-08-14) — `ShrineInteractable` 이 EndScene 전환 직전 `DeleteSave()`, 안 그러면 신전 앞 위치가 저장돼 다음 `Load Game` 이 엔딩 직전으로 복원된다

## 설계 원칙

1. **원 하나가 게임 전부**: 단일 원형 콜라이더로 모든 게임플레이. 소프트바디는 비주얼 오버레이.
2. **점성 슬라임**: 표면에 닿으면 붙는다. 바운스 없음. 운동량 전부 흡수.
3. **판정원이 파워와 방향을 동시 결정**: 조준점 위치 하나로 발사 벡터 결정. 별도 계수 없음.
4. **불안정함은 시간이 만든다**: 벽/경사 슬라이드로 차징 시간 제한. 안정도 시스템 없음.
5. **차징은 커밋**: 캔슬 불가. WASD로 발사까지 능동적 조절.
6. **사전 커밋 보상**: 에너지 전환은 부딪히기 전에 Space를 미리 누른 플레이어가 보상받음.
7. **조준 관성은 기하학적**: 가장자리에서 방향 전환이 어려움. 파라미터 불필요.
8. **플레이어 조절 중력**: W/S로 중력 스케일 조절. 에너지 전환은 에너지 보존 공식으로 정규화.
9. **마찰 해체**: 이동 속도, 관성, 미끄러짐을 독립 파라미터로 분리.
10. **시스템 분리**: 중력 → 접선 분해. 에어 컨트롤 → 방향 회전. 차징 → 판정원 내부. 드리프트 → 표면 법선. 각각 독립.
11. **상호작용 오브젝트 비주얼은 물리에서 유도**: Transform 이동, 수학 기반 변형, 스프링-댐퍼 3가지로만 표현. 외부 애니메이션 클립(rig+keyframe)은 AI 캐릭터, 배경 장식, 시네마틱에만.
