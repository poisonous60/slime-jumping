이전에 A/D 공중 컨트롤을 수평방향 속도 증가로 했는데 이게 하면 할 수록 속도가 의도치 않게 과하게 증가하는 현상이 있었어. 그것 때문에 공중 컨트롤을 하면 궤적만 바뀌고 전체 속도는 바뀌지 않게 했는데 지금 이걸 해보니까 이게 직관적이지가 않아.

주요 플랫포머들의 공중 컨트롤
수평 가속 + 수평 속도 캡 — Celeste, Hollow Knight, Super Meat Boy, Jump King 전부 이 계열이야. 공중에서 A/D를 누르면 velocity.x에 가속도를 더하되, velocity.x의 절댓값이 maxAirHorizontalSpeed를 넘지 않게 클램프해. 수직 속도는 건드리지 않아. 지상보다 가속도를 낮추는 게 보통이고 (Celeste는 지상의 약 65%), 최대 속도도 지상보다 같거나 약간 낮아.
네가 했던 두 가지 방식의 문제점:
첫 번째 (수평 속도 추가, 캡 없음)는 캡만 없었던 거지 방향은 맞았어. 클램프만 넣으면 해결돼.
두 번째 (벡터 회전, 속력 보존)가 부자연스러운 이유는, A/D를 누르면 수평뿐 아니라 수직 속도까지 같이 바뀌기 때문이야. 오른쪽을 누르는데 낙하 속도가 느려지거나, 상승 속도가 줄어드는 게 체감돼. 플레이어는 "좌우 = 수평 이동"이라는 직관이 있는데 회전 모델은 이걸 깨.
SlimeJumping에 맞는 제안
너 게임은 차징-커밋 구조라서 공중 컨트롤이 "미세 보정" 수준이어야 하잖아. 수평 가속 + 캡으로 돌아가되, 두 가지만 신경 쓰면 돼:
csharp// Airborne에서 A/D 처리
float targetVx = input.x * airMaxHorizontalSpeed;
float accel = (Mathf.Abs(targetVx) > Mathf.Abs(velocity.x)) 
    ? airAcceleration 
    : airDeceleration;
velocity.x = Mathf.MoveTowards(velocity.x, targetVx, accel * dt);

// 수직은 기존 키네마틱 중력 그대로
velocity.y += gravity * dt;
airMaxHorizontalSpeed를 baseLaunchPower보다 충분히 낮게 잡으면 (예: 발사 최대 속도의 30~40%) 강하게 쏜 궤적을 에어컨트롤로 뒤집는 건 불가능하고, 약하게 쏘거나 포물선 꼭대기 근처에서만 의미 있는 보정이 돼. 이게 커밋 원칙도 지키면서 직관적인 조작감을 줘.
한 가지 더 — 발사 직후 수평 속도가 이미 airMaxHorizontalSpeed를 넘고 있을 수 있어. 이때 캡을 강제하면 발사 순간 속도가 뚝 떨어지니까, "현재 속도보다 더 빠르게 만들지 않는다"로 처리하는 게 자연스러워:
csharp// 에어컨트롤은 현재 수평속도를 넘겨서 가속하지 않음
if (Mathf.Abs(velocity.x) > airMaxHorizontalSpeed)
{
    // 반대 방향 입력만 허용 (감속)
    if (input.x * velocity.x < 0)
        velocity.x = Mathf.MoveTowards(velocity.x, targetVx, airAcceleration * dt);
}
else
{
    velocity.x = Mathf.MoveTowards(velocity.x, targetVx, accel * dt);
}
이러면 강한 발사의 수평 성분은 보존하면서, 플레이어가 반대쪽으로 "브레이크"를 걸 수는 있어. 속도 폭발도 없고, 커밋 원칙도 유지돼.
