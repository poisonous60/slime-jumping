> 작성일: 2026-05-09
> 범위: `SlimeJumping_v2/Assets/Scripts/Controller/` + `Assets/Scripts/Physics/` + `Assets/Settings/`
> 목적: (1) 코드 아키텍처의 추상적 구조 정리, (2) `SlimeSettings.asset` 실측값 audit으로 효과 없는 필드 식별, (3) Stage 2 핵심 기믹 Ice surface가 활성화하는 코드 경로의 deep-dive.

## 1. 개요

슬라임은 모든 표면(바닥/벽/천장)에 점착하며, 차지-앤-슬링샷으로 추진력을 얻는 2.5D 플랫포머 캐릭터다. 단일 GameObject(`SlimeController`)가 4-상태 머신을 돌리며, 옆에 SurfaceProbe(접촉 감지) · SurfaceMaterial(표면별 튜닝) · 외부 시스템 인터페이스 묶음(플랫폼, Zone, Hazard, Rope, Override)을 끼우고 동작한다.

핵심 설계 원칙은 세 가지다:

1. 상태머신은 단일 클래스에서 dispatch만 한다. 상태별 처리·외부 시스템 통합은 `SlimeController.{X}.cs` 13개 partial 파일로 격리되어 있다.
2. 속도(velocity)는 9개 채널로 분리되어 매 FixedUpdate에 합성된다. 단일 `Vector2 velocity` 필드를 직접 쓰는 것이 아니라, slide / crawl / external / platform / rope 채널이 각자 적립되고 마지막에 한 번 합쳐진다.
3. 표면 특성은 `SurfaceTag → SurfaceMaterial → SurfaceModifiers struct` 변환을 거쳐 매 프레임 LIFO 블렌드된다. Snow patch와 Zone override가 호스트 머티리얼 위로 쌓여 합성된다.

### 2.2 상태머신

```
                  Hazard.cs                   Stunned.cs
    ┌──────────┐  ──────────►  ┌─────────┐   ──────►  ┌──────────┐
    │ Attached │               │ Stunned │           │ Airborne │
    │          │  ◄──────────  └─────────┘           │          │
    └────┬─────┘   timer end                         └─────┬────┘
         │ Input.cs (Jump 누름)                            │ Airborne.cs
         ▼                                                 │ (착지)
    ┌──────────┐                                           │
    │ Charging │  ───────────────────────────────────────► │
    │          │  Launch.cs (auto-launch / Jump release /  │
    └──────────┘  CancelChargingToAirborne)                │
                                                           │
         ┌─────────────────────────────────────────────────┘
         │ DragZone (volume charging)
         ▼
    Airborne 유지 + isVolumeCharging 플래그
```

전이는 항상 `ChangeState(...)` 단일 진입점을 통과한다. Charging은 Attached로 되돌아가지 않는다 — 항상 launch / hop / cancel-to-airborne으로 종료된다 (회상 메모: "Charging state must always end in launch").

### 2.3 FixedUpdate 파이프라인

```
1. Override 가로채기 검사 → 있으면 ExternalFixedUpdate로 위임 후 종료
2. Gravity field 스택 평가 → gravityUp / gravityRight 계산
3. ignoredColliderList tick (런치 직후 무시 콜라이더 만료 처리)
4. DecideProbeMode (Single ↔ Multi, 주변 SurfaceProbeModeOverride 스캔)
5. Rope pre-lock (이미 부착된 로프면 probe 전에 rb.position 잠금)
6. surfaceProbe.CheckSurface → isTouchingSurface, primaryNormal, surfaceCollider
7. EffectiveNormal 저역통과 필터 → surfaceNormal / surfaceTangent
8. Surface 변경 시: PlatformCarrier.Attach + UpdateSurfaceModifiers / RefreshSnowBlend
9. Rope reference 추적 갱신
10. switch(currentState) → FixedUpdate{Attached/Charging/Airborne/Stunned}
11. ApplySnowDrag (눈 위 지수감쇠)
12. Rope.ReportRiderContact (체중 보고 → 다음 프레임 sag 예약)
13. externalDeltaV 합성 (Attached/Charging는 tangent로 투영)
14. platformVel + ropeVel + carry delta 합성
15. 최종 출력 분기:
    · Multi probe(Attached/Charging) → rb.position += delta·dt + SnapToSurface + linearVelocity = 0
    · 그 외 → rb.linearVelocity = finalVel (Unity 물리 적분에 위임)
```

## 3. 핵심 서브시스템

### 3.1 SurfaceProbe — 접촉 감지 추상

`Assets/Scripts/Physics/SurfaceProbe.cs` 추상 베이스 + 두 구현:

| 모드 | 특성 | 용도 |
|------|------|------|
| Single (`SurfaceProbeMode.Single` = 0) | 콜라이더당 `ClosestPoint` 1회 | Unity 네이티브 CCD가 필요한 얇은 회전 콜라이더(SpringyBranch 등) |
| Multi (`SurfaceProbeMode.Multi` = 1) | 슬라임 둘레에 N개 링 샘플 → 콜라이더당 다중 접점 | 멀티-패스 폴리곤(deformable platform), 곡면. SnapToSurface로 직접 위치 제어 |

핵심 출력 API:
- `bool CheckSurface(out normal, out collider, ...)` — 접촉 여부 + 대표 콜라이더
- `EffectiveNormal` — soft band 가중 평균 normal (천장 임계 + smoothstep ramp)
- `ProjectVelocityAgainstContacts(ref velocity, fallbackNormal)` — 모든 활성 접점에 대해 노말 성분 0 클립 (concave 코너 다중 제약)
- `SnapToSurface(collider, normal)` — Phase A 디페너트레이션 루프

`SurfaceProbeModeOverride` 컴포넌트로 특정 콜라이더 부근에서만 모드 자동 스위칭한다.

### 3.2 Velocity 9채널

매 FixedUpdate에 다음 채널이 합성된다:

| 채널 | 자료형 | 작동 상태 | 적분 방식 |
|------|--------|-----------|-----------|
| `velocity` | Vector2 | 모든 상태 | 상태 핸들러가 매 프레임 덮어씀 (Attached: `surfaceTangent × (slide+crawl)`) |
| `crawlVelocity` | float (tangent) | Attached/Charging | 가속/감속 모델, WASD 입력, stick 시 약화 |
| `slideVelocity` | float (tangent) | Attached/Charging, `useInertialSlide=true`만 | 중력의 tangent 성분을 가속도로 적분, friction은 m/s² 감속 |
| `externalDeltaV` | Vector2 | 모든 상태 | 매 FU 누적 후 0으로 소비. 부착 상태에선 tangent로 투영 |
| `airDashActiveTimer` | float | Airborne | 활성 중 중력·에어컨트롤 정지 |
| 플랫폼 carrier | Vector2 | Attached/Charging | `PlatformCarrier.GetEffectiveVelocity() × carrierFriction` |
| 로프 sample | Vector2 | Attached/Charging + 로프 부착 시 | `ropeVel = SampleVelocityAt(pos)`, `MaxReboundSpeed` 캡 |
| 로프 carry delta | Vector2 (위치 보정) | 같은 조건 | `rb.position += ConsumeRiderCarryDelta()` (V3 only) |
| Gravity | Vector2 | Airborne/Stunned | `-gravityUp × |gravity| × scale` (rising/falling/W/S/inFluid 비대칭) |

### 3.3 SurfaceMaterial 블렌딩

```
SurfaceTag (콜라이더 부착)
   ↓
hostMaterial (SurfaceMaterial ScriptableObject)
   ↓ + snow patch 위라면 snowMaterial Lerp
   ↓ + Zone PushSurfaceMaterialOverride 가 있다면 LIFO top
   ↓
surfaceMod (SurfaceModifiers struct, 매 프레임 갱신)
```

`AngleScaledValue` 커브로 floor↔wall 각도별 다른 값을 부드럽게 블렌드 가능. `useInertialSlide` 같은 discrete 필드는 lerp 대신 snap되며, 전환 순간 `SlimeController.SurfaceModifiers.cs`의 마이그레이션 로직이 `crawlVelocity ↔ slideVelocity` 채널을 보존한다.

| 인터페이스 | 위치 | 역할 | 사용 예 |
|------------|------|------|---------|

## 4. 활성 vs 비활성 기능 audit (`SlimeSettings.asset`)

`SlimeSettings.asset`의 모든 필드를 코드 사용 맥락과 대조하여, 현재 게임플레이 출력에 영향이 없는 필드를 식별했다. 곱셈자 1, 0 토글, 미선택 enum 분기, 코드 자체 dormant를 분리.

### 4.1 명시 토글 OFF (master 토글)

| 필드 | 자산값 | 코드 위치 | 효과 |
|------|--------|-----------|------|
| `enableHop` | 0 (OFF) | `Input.cs` HandleHop 게이트 + `Launch.cs` ApplyHop | W-키 hop 메커니즘 자체 비활성. 아래 모든 hop* 필드(Power/Min/MaxAngle/Cooldown/BufferDuration/LandingRetention/MomentumBonus/MomentumMaxSpeed/AlongSurfaceNormal)가 작동하지 않음 |
| `allowChargeAirHold` | 0 (OFF) | `Input.cs` HandleSurfaceChargeEntry | 공중에서 Space 홀드만으로는 착지 시 차지 진입 X. `chargeInputBuffer` 윈도우의 press 만 사용 |

### 4.2 곱셈자 1배 = 효과 없음

배수가 1이면 출력이 변하지 않는다. 인스펙터에 표시되어 있어 디자이너가 "활성 기능"으로 오인할 수 있어 별도 분류.

| 필드 | 자산값 | 코드 위치 | 비고 |
|------|--------|-----------|------|
| `notJumpConversionBonus` | 1 | [`Airborne.cs:139, 270`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Airborne.cs#L139) — `if (launchSpeed == 0f) spawnDistance *= settings.notJumpConversionBonus;` | hop이 아닌 단순 낙하 후 차지 보너스. 1이면 무효. 소스 default는 1.3 — 자산이 디폴트보다 약화됨 |
| `chargingSlideGravityScale` | 1 | [`Charging.cs:170`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Charging.cs#L170) — `gravAlongTangent *= settings.chargingSlideGravityScale;` | 차지 중 슬라이드 시 중력 tangent 스케일. 소스 default는 0.5 (차지 중에는 슬라이드 약화 의도) — 자산이 의도된 약화를 비활성화함 |
| `floatGravityScaleRising` | 1 | [`Airborne.cs:55`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Airborne.cs#L55) | W-홀드 상승 시 중력 스케일. 1이면 무효. 소스 default도 1 (의도된 정상값) |
| `floatGravityScaleFalling` | 1 | 동일 | W-홀드 하강 시 중력 스케일. 1이면 float 메커니즘 무효. 소스 default는 0.5 — 자산이 W-부유 메커니즘을 무력화 |
| `risingGravityScale` | 1 | [`Airborne.cs:62`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Airborne.cs#L62) | 비대칭 중력 (apex 전). 1이면 무효. 소스 default도 1 (정상) |
| `surfaceNormalSmoothRotatingMultiplier` | 1 | [`SlimeController.cs:611`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.cs#L611) — `smoothRate *= settings.surfaceNormalSmoothRotatingMultiplier;` | 회전 플랫폼에서 surfaceNormal 추가 smoothing. 1이면 무효. `[Min(1)]` 어트리뷰트로 1이 사실상 OFF의 의미. 현재는 회전 플랫폼 특별처리 없음 |
| `tangentInheritanceFactor` | 1 | Launch.cs hyper dash | 1 = 100% 상속. 소스 default 0.7. 자산이 hyper dash 손실을 0으로 설정 (의도일 가능성) |
| `hyperDashDeduction` | 1 | Launch.cs | 임계 이하 tangent 무시 deadzone. 1 m/s 미만 무시. 소스 default 5 — 자산이 deadzone을 거의 제거 |
| `hopConversionBonus` | 1.1 | Airborne 착지 | 거의 1 (10% 보너스). 의도적 활성으로 분류 가능 |

`risingGravityScale`(=1)과 `floatGravityScaleRising`(=1) 두 필드는 소스 default도 1이므로 "정상 무효" 케이스다. 보고만 하고 정리 대상은 아니다. 반면 `floatGravityScaleFalling`(=1)·`chargingSlideGravityScale`(=1)·`notJumpConversionBonus`(=1)는 소스 default가 비-1 → 디자이너가 의도적으로 비활성화한 것으로 보임.

> 두 값은 마찰-detach 공식이 "dTheta + convex sustain frames" → "centrifugal + horizon raycast" 로 리팩터링된 흔적이다. 인스펙터에서 옛 공식 재활성용으로 유지된 것으로 보이나, 현 코드 경로상 효과 없음. 정리 시 제거 또는 명시적으로 `[Header("Debug Only")]` 분리 권장.

### 4.6 Default SurfaceModifiers (untagged 콜라이더 fallback)

`SurfaceTag`가 없는 콜라이더는 `SlimeSettings.BuildDefaultModifiers()`로 만든 `SurfaceModifiers`를 사용한다. 자산값은 거의 전부 "효과 없는 디폴트"로 설정됨:

| 필드 | 자산값 | 의미 |
|------|--------|------|
| `crawlSpeedMultiplier` | base/full = 1 | 곱셈자 1 = 효과 없음 |
| `crawlAccelerationMultiplier` | 1 | 동일 |
| `crawlDecelerationMultiplier` | 1 | 동일 |
| `crawlOverspeedDecelerationMultiplier` | 1 | 동일 |
| `slideResistanceMultiplier` | 1 | 동일 |
| `slideGravityMultiplier` | 1 | 동일 |
| `slideRampUpTime` | 0 | 0 = 즉시 풀-속도 (효과 없음) |
| `slideLinearDrag` | 0 | 0 = drag 없음 |
| `slideDownhillGain` | 1 | 곱셈자 1 = 효과 없음 |
| `slideUphillBrake` | 1 | 동일 |
| `landingVelocityRetention` | 0 | 착지 시 tangent 속도 0% 보존 (= 항상 sticky stop). 이 값이 0이라 거의 모든 머티리얼이 retention=1로 override 해야 활성화됨 |
| `landingExcessGain` | 1 | 곱셈자 1 = 효과 없음 |

| `hopPowerMultiplier` | 1 | 곱셈자 1 |

### 4.7 audit 종합

- 명백한 dormant 후보 (정리 대상): `cornerBigSpikeAngle`, `cornerDetachSustainFrames` (4.5)
- 엔진은 살아있지만 자산이 비활성화: `enableHop`, `allowChargeAirHold`, `chargeEntryStickBonus`, `chargingSlideGravityScale`, `floatGravityScaleFalling`, `notJumpConversionBonus`, `crawlSpeed` (4.1~4.3)
- 모드 enum 결정으로 미사용: `cornerVelocityThreshold`, `cornerOmegaThreshold` (4.4)
- 소스 default와 일치하는 정상 무효: `floatGravityScaleRising`, `risingGravityScale`, `surfaceNormalSmoothRotatingMultiplier` 등

특히 `crawlSpeed = 0`과 `enableHop = 0` 두 결정이 슬라임의 기본 이동 어휘를 크게 좁힌다 — 표면에서는 슬라이드/ground dash, 공중에서는 air control/launch 만 남는다. Stage 1-2의 차지 슬링샷·관성 중심 디자인 의도와 일치하는 것으로 보인다.

## 5. Ice Surface Deep-Dive

Stage 2의 핵심 기믹은 얼음이다. `Ice.asset`은 슬라임의 표면 거동을 가장 광범위하게 변형하는 머티리얼이다.

### 5.1 Ice가 디폴트와 다른 모든 필드

| 필드 | Default | Ice | 분류 | 효과 |
|------|---------|-----|------|------|

### 5.2 Ice가 활성화하는 코드 경로

#### A. `useInertialSlide = true` 가 깨우는 분기

| 위치 | 분기 동작 |
|------|-----------|
| [`Attached.cs:83`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Attached.cs#L83) | 슬라이드 적분: `slideVelocity += gravAlongTangent * slideGravityScale * slideGravity * slopeGain * dt`. `slideResistance`가 m/s² 마찰 감속, `slideLinearDrag`가 지수 drag |
| [`Attached.cs:367`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Attached.cs#L367) | 정지 시점 처리 (`velocity.sqrMagnitude < 0.01f` 분기) |
| [`Charging.cs:136, 173`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Charging.cs#L136) | 차지 중 슬라이드도 동일 적분 경로. stick 해제 시 `slideVelocity = postStickTangent` |
| [`Airborne.cs:167, 235`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Airborne.cs#L167) | 착지 시 `landedTangent`를 `slideVelocity`로 라우팅 (legacy는 `crawlVelocity`로 보냄) |
| [`Launch.cs:314, 334`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Launch.cs#L314) | ground dash 임펄스를 `slideVelocity`에 적립. hyper dash 관성 상속도 inertial 채널로 |

| [`SurfaceModifiers.cs:217`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.SurfaceModifiers.cs#L217) | snow는 host의 `useInertialSlide`를 그대로 상속 (얼음 위 눈은 여전히 inertial) |

#### B. `enableLandingTangentSpeedRemap = true` + remap 곡선

[`Airborne.cs:402`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Airborne.cs#L402)에서 `ComputeLandingCrawlVelocity` 끝에 비선형 변환:
```
landed = sign(landed) * remapCurve.Evaluate(|landed|)
```
얼음의 곡선은 saturating shape — 50 m/s 임팩트도 30 m/s로 압축. 수직 hop이 이상하게 빠른 미끄럼으로 폭주하는 현상을 방지.

#### C. `impactRedirectRatio = 1`

[`Airborne.cs:162, 229`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Airborne.cs#L162)에서 `effectiveTangent = tangentSpeed + normalSpeed * impactRedirect * redirectSign * redirectScale`. 얼음 벽에 비스듬히 충돌한 normal 운동량을 100% tangent로 환산 → 미끄러져 흐른다.

#### D. `stickDurationMultiplier = 0`

`CalculateStickDuration(impactSpeed) * surfaceMod.stickDuration.Evaluate(angle)` → 0. 얼음 착지에는 stick timer 부여 없음. 즉시 슬라이드 적분 시작.

#### E. `landingVelocityRetention = 1`

`ComputeLandingCrawlVelocity` 내부에서 hop landing retention 분기를 통해 100% tangent 보존. 일반 표면(0)과 달리 얼음 착지 후에도 들어온 속도를 그대로 가지고 미끄러진다.

#### F. `launchInertiaBlendMode = PNorm (p=2)`

[`Launch.cs:272`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Launch.cs#L272):
```
blendedMag = (launchMag^2 + inheritedMag^2)^(1/2)
```
얼음 위 launch는 aim 파워와 상속 관성을 단순 합 대신 유클리드 norm으로 합성 → 빠른 슬라이드 중 launch 가 아주 폭주하지 않도록 압축. 60 m/s + 30 m/s 시 Sum=90 vs PNorm=67.

#### G. `overrideCeilingAngle + 150°/140°`

[`SlimeController.SurfaceModifiers.cs`](SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.SurfaceModifiers.cs)에서 `surfaceMod.ceilingThresholdOverride`가 ceiling 검사에 주입. 얼음 천장은 일반 천장보다 더 가파른 각도까지 부착 가능 — 얼음 동굴/터널 천장 슬라이드 시나리오를 위한 튜닝.

### 5.3 Ice 활성화 게임플레이 시스템 묶음

| 게임플레이 효과 | 활성 메커니즘 |

#### 머티리얼별 한 줄 요약

- Default_Surface: 모든 효과 무효화된 baseline. SurfaceTag 없는 표면과 동일.
- Mud: 슬라이드 중력 1/5 (느림) + 마찰 1.3배 (들러붙음) + hop 속도 불보존 + 벽 점착 무시. 걸쭉한 진흙.
- Snow: hop 속도 0% 보존 + 벽 점착 무시 + impact redirect 켜짐. 기본 슬라이드는 정상이지만 hop으로 빠져나가기 어려움. 사운드 클립이 유일한 머티리얼 (snow 사운드 4종).
- Water: 거의 모든 운동성 0 (carrier 0, crawl 0, hop power 0, ground dash 0). 유체 — 이동 자체가 거의 봉쇄. 단 `useInertialSlide=ON`에 `landingRetention=1`로 부유체 미끄럼은 가능.
- Rope_Surface: `useInertialSlide=ON` + `landingRetention=1` + `overrideEnergyConversionCoyoteTime=1s` (긴 grace). 로프 위 라이딩 + 차지 진입 grace 1초.
- SpringlyBranch_Surface: `slideResistance=5` (매우 강한 마찰로 가지 위에 붙어있도록) + `useInertialSlide=ON` + `landingRetention=1` + coyote 1초. 튕기는 가지에 잠시 머무는 동작.

> 얼음만이 `enableLandingTangentSpeedRemap`, `launchInertiaBlendMode=PNorm`, `overrideCeilingAngle`, `slideDownhillGain≠1`을 사용한다. Stage 2 핵심 기믹답게 가장 풍부한 튜닝 surface다.

## 6. 정리 권장 사항

1. Dormant 필드 제거 — `cornerBigSpikeAngle`, `cornerDetachSustainFrames` 두 필드는 디버그 외 효과 없음. 옛 공식을 살릴 계획이 없다면 SlimeSettings에서 제거하거나 `[Header("Debug Only")]`로 명시 분리.
2. 모드 미선택 파라미터 그룹핑 — `cornerVelocityThreshold` / `cornerOmegaThreshold`는 `frictionDetachFormula`에 따라 사용 여부가 결정됨. 인스펙터 커스텀 에디터 (`SlimeSettingsFrictionDetachEditor.cs`)가 이미 있으므로, 비활성 모드의 파라미터는 회색 처리 권장.
3. `floatGravityScaleFalling=1` / `chargingSlideGravityScale=1` 의도 검증 — 소스 디폴트가 비-1인데 자산이 1로 설정됨. W-홀드 부유 메커니즘이 사실상 꺼져있는 상태가 디자인 의도인지 확인 필요. 의도라면 `Tooltip`에 "현재 비활성" 명시.
4. `crawlSpeed=0` 의도 문서화 — 슬라임이 표면에서 자력으로 좌우 이동을 못하는 것은 디자인 결정으로 보이나, `프로토타입_구현_현황.md`에 명시 권장. 신규 디자이너가 "버그"로 오인할 가능성 큼.
5. Ice 튜닝 방향성 — saturating remap curve의 (10,10)→(20.7,17.9)→(32.7,24.6)→(50,30.4) 구간이 잘 작동하는지 Stage 2 플레이테스트로 검증. PNorm(p=2)이 너무 보수적이면 LerpMaxToSum(factor 0.5~0.7)로 옮겨 Sum과 PNorm 사이 중간점 탐색 가능.
6. 머티리얼 시스템 활용도 균형 — 7개 머티리얼 중 Mud/Snow/Water는 토글 1~2개만 변경하는 단순 머티리얼. Ice 한 개에 토글이 집중되어 있어, Stage 3 이후 추가 surface 추가 시 Ice 패턴(전 분야 재정의)을 표준 템플릿으로 삼을지, 단순 머티리얼 패턴을 유지할지 가이드 필요.
