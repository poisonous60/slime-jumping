# 슬라임 비주얼/애니메이션 진행 현황 및 계획

## 목적

그레이박스 단계에서 슬라임의 비주얼 공백을 채우고, 프로덕션 단계로 자연스럽게 확장 가능한 구조 마련.

---

## 접근 방식 결정: 절차적 변형 (Procedural Deformation)

### 선택한 방식

**방사 대칭 스프라이트 + 코드 기반 squash/stretch/관성 제어**

- 본체(body)는 완전 방사 대칭 원형 이미지 한 장
- 얼굴(eyes, mouth)은 본체와 분리된 별도 레이어
- 모든 "말랑함", "눌림", "늘어짐", "출렁거림"은 코드가 매 프레임 localScale/position을 조작해서 생성
- 전통적 프레임 애니메이션(Idle 클립, Walk 클립 등)은 사용하지 않음

### 고려했던 다른 선택지

**1. 풀 소프트바디 (노드-스프링 시뮬레이션)**

- 장점: 모든 각도에 자연스럽게 대응, 진짜 물리적 젤리 느낌
- 단점: 과거에 시도했다가 버그로 포기한 경험 있음, 구현 복잡도 높음, 주변 지형 충돌까지 고려하면 작업량 큼
- 판단: 그레이박스 단계에서 선행 투자하기엔 리스크 큼. Phase 2(프로덕션) 후보로 보류.

**2. 본/메시 디폼 (Spine 스타일)**

- 장점: 전통적 애니메이션과 절차적 제어를 동시에 가능
- 단점: Spine 학습 필요, 메시 리깅 작업량, 슬라임에 오버킬
- 판단: 제외.

**3. 프레임 애니메이션 (스프라이트 시트)**

- 장점: 러닝커브 낮음
- 단점: 모든 각도(바닥/벽/천장/경사) 대응하려면 프레임 수 폭증, 절차적 제어와 섞기 어려움
- 판단: 제외.

### 절차적 변형을 선택한 근거

**1. 기존 아키텍처와 궁합이 좋음**

현재 `SlimeController`는 `CircleCollider2D` 하나 + 수동 velocity 관리 구조. 비주얼 레이어를 별도 자식 GameObject로 두면 물리와 완전히 분리되어 Interpolation 충돌 없음. localScale을 마음대로 변형해도 물리에 영향 없음.

**2. 모든 각도에 한 장으로 대응 가능**

방사 대칭 이미지는 어느 방향으로 회전/변형시켜도 실루엣이 깨지지 않음. `surfaceNormal` 한 벡터로 모든 표면(바닥, 벽, 천장, 경사) 대응.

**3. 레퍼런스 확인**

Dicey Dungeons의 젤리, Downwell의 캐릭터, Hollow Knight의 작은 슬라임류 모두 이 접근으로 말랑한 느낌을 구현함. 소프트바디 없이도 슬라임 정체성 유지 가능함이 입증됨.

**4. Phase 2 전환 비용이 낮음**

나중에 소프트바디로 업그레이드하더라도, "SlimeController로부터 위치/상태/법선을 받아 비주얼을 만드는 레이어"라는 구조는 그대로 유지됨. 변형 로직만 교체하면 됨.

**5. 슬라임 느낌의 핵심 4요소가 모두 코드로 가능**

- 호흡 (Idle breathing): `sin` 기반 미세 scale 진동
- 관성 지연 (Motion lag): SmoothDamp로 본체가 물리 위치를 지연 추종
- 속도 기반 stretch: 속도 벡터 방향으로 늘리고 수직 방향으로 누름 (부피 보존)
- 충격 squash: 착지/충돌 시 법선 방향 순간 squash + 탄성 복원

## 이미지 에셋 설계 원칙

### 본체(body)

- 완전 방사 대칭 원형 (1:1 비율)
- 위아래 구분 없는 셰이딩 (방사형 그라데이션 또는 플랫)
- 방향성 있는 하이라이트 금지 (위에서 내려오는 빛 없음)
- 얼굴 없음
- 균일한 두께의 아웃라인
- 근거: 어떤 각도로 회전시켜도 어색하지 않아야 함. 셰이딩에 방향이 박혀 있으면 벽/천장에서 빛이 반대로 가는 이상한 상태 발생.

### 얼굴(eyes, mouth)

- 본체와 분리된 별도 레이어
- 본체가 stretch/squash 중에도 얼굴은 독립적으로 관리
- 근거:
  - 본체와 함께 찌그러지면 눈/입이 납작해져서 어색함
  - 표정 변화(차징/충격/놀람)를 얼굴 스프라이트 스왑으로 구현 가능
  - 본체는 회전(surfaceNormal 기준), 얼굴은 항상 정립(화면 위 기준)의 분리 처리 가능

### "기본 눌림"은 이미지가 아닌 코드로

평지에서의 "가로로 퍼진 슬라임 모습"을 이미지에 그리지 않는 이유:

- 이미지에 눌림이 있으면 "지금 눌린 게 이미지 때문인가 변형 때문인가?" 수학적으로 분리 불가
- 중립 = 원형으로 정의해야 모든 상태 변형(표면 squash + 속도 stretch + 충격 squash)이 독립적으로 합산 가능
- 공중 = 원형, 표면 접촉 = 법선 방향 squash 라는 원칙이 물리적으로도 일관됨

## 앞으로의 계획

### Phase C-0: 정적 배치 ✅ 완료

이미지가 씬에 보이고, 플레이 모드에서 슬라임이 움직일 때 이미지가 따라다님.

### Phase C-1: 얼굴 추종 + 생명감 ✅ 완료

Body와 Face를 분리 제어. SlimeVisual 자체 transform은 identity 유지.

**Body 회전 (deformation axis):**
- 본체는 완전 방사 대칭이라 회전 자체는 시각적으로 보이지 않음.
- 회전은 "변형 축 정렬" 용도로만 사용: localScale이 body-local X/Y 축으로만 작용하므로, squash/stretch 방향에 맞춰 body.up을 정렬해야 함.
- Attached/Charging: `body.up = surfaceNormal` (Slerp 보간). 법선 방향 squash가 body Y축으로 정렬됨.
- Airborne: 속도 > threshold이면 `body.up = velocity.normalized` 쪽으로 Slerp (teardrop 자세). 속도 < threshold(정점 근처)이면 마지막 축 유지 (떨림 방지).

**Face 위치 오프셋 (회전 아님):**
- Charging: 2-레이어 슬링샷 — body 전체가 `-AimDirection * bodyChargingAimPull`로 당겨지고, face는 body 위에 `-AimDirection * faceChargingScale` 추가 오프셋. chargingCurve 미적용 (각도 즉시 반응)
- Attached/Airborne: `Velocity * faceOffsetScale` — 이동 방향으로 쏠림
- 방향 잔상: 정지 시 즉시 중앙 복귀가 아닌 마지막 방향에서 `faceLingerDecay` 속도로 서서히 감쇠
- 아이들 드리프트 (idle 시에만 작동): X축은 `tanh(sin(t) * sharpness)` — 한쪽에 머물다 휙 전환하는 사코드(saccade) 패턴. Y축은 sin으로 부드럽게. X/Y 주파수를 다르게 해 기계적 느낌 방지.
- `SmoothDamp`로 부드럽게 보간, `ClampMagnitude`로 최대 거리 제한
- `face.localRotation = identity` (항상 정립)

**깜빡임:**
- `eyes_closed.png` 스프라이트 스왑. 랜덤 간격(3~7초)마다 0.1초간 눈 감음.
- "살아있음" 신호 — 뇌가 깜빡임을 의식 있음으로 해석.

**Hierarchy:**
```
Slime (SlimeController, Rigidbody2D, CircleCollider2D)
└─ SlimeVisual (SlimeVisual.cs, transform = identity)
   ├─ Body (SpriteRenderer — body.png)
   └─ Face (빈 GameObject)
      ├─ Eyes (SpriteRenderer — eyes.png / eyes_closed.png 스왑)
      └─ Mouth (SpriteRenderer — mouth.png)
```

파일: `Assets/Scripts/Visual/SlimeVisual.cs`
에셋: `Assets/Art/Slime/eyes_closed.png`
설정 (`SlimeVisualSettings`):
- 변형 축: `deformAxisSlerpSpeed`
- Face 추종: `faceOffsetScale`, `faceOffsetMax`, `faceSmoothTime`, `faceChargingScale`, `faceLingerThreshold`, `faceLingerDecay`
- 차징 Body: `bodyChargingAimPull`
- Idle 드리프트: `faceDriftAmplitude`, `faceDriftFreqX`, `faceDriftFreqY`, `faceDriftSharpness`
- 깜빡임: `blinkDuration`, `blinkIntervalMin`, `blinkIntervalMax`

추가된 API: `SlimeController.AimDirection`, `SlimeController.ChargingProgress`

### Phase C-2: 충격 squash ✅ 완료

Airborne→Attached/Charging 전환 시 착지 충격을 시각화.

**구현:**
- Visual이 매 프레임 velocity를 캐싱. Controller가 FixedUpdate에서 velocity를 0으로 만든 후 LateUpdate에서 상태 변화를 감지하므로, `lastNonZeroVelocity` fallback 사용.
- `prevState == Airborne && currentState != Airborne` 감지 시 impact 트리거
- 충격 강도: 법선 성분 속도 사용 `Clamp01(Abs(Dot(lastNonZeroVelocity, surfaceNormal)) / impactSpeedReference)` — 빗맞는 충돌은 약하게, 정면 충돌은 강하게
- 곡선: 감쇠 코사인 `e^(-decay * t) * cos(freq * PI * t)` — 초기 squash → 탄성 overshoot → settle
- SmoothDamp 바깥에서 직접 더해짐 (날카로움 유지)
- 부피 보존: `(+squash, -squash)` 패턴 (body.up = surfaceNormal이므로 Y = 법선 방향 squash)

설정: `impactSquashIntensity`, `impactDuration`, `impactDecayRate`, `impactOscFreq`, `impactSpeedReference`, `impactMinThreshold`

### Phase C-3: 관성 지연 → C-4에 흡수

별도 항으로 두지 않고 C-4의 비대칭 pivot offset으로 통합. 이동 시 body center가 진행 방향 반대로 밀려서 "앞은 제자리, 뒤가 끌려옴" 효과 발생.

### Phase C-4: 속도 기반 stretch + 비대칭 pivot ✅ 완료

이동/낙하 중 속도 방향으로 늘어나고 수직 방향으로 눌림.

**구현:**
- Velocity stretch: `speed / velocityStretchSpeedRef`에 비례. 최대치 `velocityStretchMax`로 클램프.
- 축 비대칭: 표면에서는 body.up=surfaceNormal → velocity가 X축 방향이므로 `(+stretch, -stretch)`. Airborne에서는 body.up=velocity 방향이므로 `(-stretch, +stretch)`.
- 비대칭 pivot (velocity lean): body center를 velocity 반대 방향으로 오프셋. "앞은 고정, 뒤가 끌려옴" 효과.
- Slow layer에 속하므로 SmoothDamp 통과.

설정: `velocityStretchIntensity`, `velocityStretchSpeedRef`, `velocityStretchMax`, `velocityLeanDistance`, `velocityLeanMax`, `velocityAxisThreshold`

### Phase C-5: 표면 squash + 중력 sag ✅ 완료

표면 접촉 시 중력에 눌린 기본 형태 + 벽에서의 처짐.

**구현:**
- 중력 벡터를 surfaceNormal 기준으로 분해:
  - 법선 성분 `Dot(gravity, normal)`: 표면을 누르는 힘 → 법선 방향 squash 강도. 평지=최대, 벽=0, 천장=0.
  - 접선 성분 `Dot(gravity, tangent)`: 표면을 따라 흘러내리는 힘 → pivot offset (sag). 평지=0, 벽=최대(아래로 처짐).
- Surface squash: `(+squash, -squash)` 패턴. body.up=surfaceNormal이므로 Y=법선 방향 squash.
- Gravity sag: `tangent * sagStrength * gravitySagDistance`. world space offset → body.localPosition.
- `squashStrength`를 별도 SmoothDamp로 관리: surface squash scale과 shader asymmetry가 동일 곡선을 따라 시각적 desync 방지.
- Airborne에서는 둘 다 0으로 복원 (SmoothDamp 통해 부드럽게).

설정: `surfaceSquashIntensity`, `surfaceSquashAsymmetry`, `gravitySagDistance`

### Phase C-6: 호흡 ✅ 완료

가만히 있을 때도 "살아있음" 표현.

**구현:**
- `sin(breathPhase * 2PI) * breathAmplitude`의 미세 scale 진동
- `(+value, -value)` 부피 보존 패턴
- 모든 상태에서 항상 활성, SmoothDamp 바깥에서 직접 더해짐

설정: `breathAmplitude`, `breathFrequency`

### 비대칭 셰이더 (C-5 확장) ✅ 완료

Transform 연산(translate/rotate/scale)은 원에서 타원만 만들 수 있음 — 달걀 모양은 불가. 비대칭 변형을 위해 fragment shader에서 UV.y를 리매핑.

**구현:**
- Shader Graph (`Assets/Art/Shader/SlimeBody.shadergraph`) — Sprite Lit 기반.
- `_Asymmetry` Float property: 출력의 아래쪽 절반이 원의 적도(가장 넓은 부분)에서 샘플링 → 평평+넓은 바닥 + 둥근 윗부분 = 달걀 모양.
- UV.y 리맵 공식: 아래 절반(v<0.5)은 `lerp(bottomSampleStart, 0.5, v*2.0)`으로 압축, 윗 절반은 그대로.
- `body.up = surfaceNormal`이 "아래"를 항상 표면 방향으로 정렬하므로 모든 표면 각도에 작동.
- C# 코드가 `smoothedSquashStrength * surfaceSquashAsymmetry`를 MaterialPropertyBlock으로 매 프레임 전달. scale의 SmoothDamp와 동일 곡선을 따라 desync 없음.
- 평지=최대 비대칭, 벽=대칭(squashStrength=0), Airborne=대칭.

**Deformation axis 180도 방지:**
- Airborne에서 velocity가 body.up과 반대(>90도)이면 축을 반전: 대칭 원이므로 동일 타원, 짧은 경로로 Slerp.
- 표면에서는 반전 없음: shader 비대칭의 위/아래 방향이 surfaceNormal에 의존하므로 정확한 방향 필요.

설정: `surfaceSquashAsymmetry`
파일: `Assets/Art/Shader/SlimeBody.shadergraph`, material on Body SpriteRenderer

**Charging-specific deformation**: 미구현, 나중에 추가 가능. Aim pull (위치 오프셋)은 덧셈 파이프라인에 깨끗하게 삽입 가능. Aim stretch (비균일 스케일)는 aim 방향이 body.up과 다를 수 있어 별도 설계 필요.

## 변형 합성 공식

```
// Slow layer: SmoothDamp 통과
targetScale = (1,1) + surfaceSquash(C-5) + velocityStretch(C-4)
smoothedScale = SmoothDamp(prev, targetScale, deformSmoothTime)

// Fast layer: SmoothDamp 바깥에서 직접 더함
finalScale = smoothedScale + impactOverlay(C-2) + breathing(C-6)
finalScale = Clamp(finalScale, 0.4, 1.8)

// Offset: SmoothDamp 통과
targetOffset = gravitySagOffset(C-5) + velocityLeanOffset(C-4)
smoothedOffset = SmoothDamp(prev, targetOffset, offsetSmoothTime)

// Shader 비대칭 (scale과 동일 SmoothDamp 곡선)
_Asymmetry = -smoothedSquashStrength * surfaceSquashAsymmetry

// 적용
body.up = Slerp toward deformAxis
body.localScale = (finalScale.x, finalScale.y, 1)
body.localPosition = (smoothedOffset.x, smoothedOffset.y, 0)
MaterialPropertyBlock → _Asymmetry
```

- 각 항은 "중립 대비 오프셋"으로 표현 (0 = 변화 없음)
- 부피 보존: `(+d, -d)` 패턴 → `(1+d)(1-d) ≈ 1`
- impact/breathing은 SmoothDamp 바깥 → 날카로움 유지
- surfaceSquash/velocityStretch는 SmoothDamp 안 → 부드러운 전환

## 상태 전환 시 자연스러움 확보

### 대응

1. **SmoothDamp 기반 보간**: targetScale이 순간적으로 바뀌어도 smoothedScale은 6~9프레임에 걸쳐 부드럽게 따라감.

2. **Impact overlay로 착지 덮기**: Airborne→Attached/Charging 전환 시 impact squash가 트리거되어 "강하게 눌린" 상태로 시작. 어색한 중간 상태가 감춰짐.

3. **Deformation axis Slerp**: body.up도 SmoothDamp가 아닌 Slerp로 부드럽게 보간. 표면 전환 시 squash 방향도 점진적으로 회전.

## Phase 2 (프로덕션) 장기 계획 — 참고용

현재 Phase C로 충분하다 판단되면 건너뛰어도 됨.

- 본체를 실제 소프트바디(노드-스프링 또는 본 기반 메시 디폼)로 교체

- 얼굴 레이어는 Phase C에서 만든 구조 그대로 재사용
- `SlimeVisual` 인터페이스(위치/상태/법선 입력)는 동일 유지 → 하부 구현만 교체
- 본체 디자인에 방향성이 생기면 (위아래 구분, 반점 등) 회전 로직을 시각적 정렬 용도로 재도입 검토
