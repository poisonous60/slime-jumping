# SlimeJumping — 핵심 메커닉 설계 v3

## 컨셉

**점성 슬라임** — 모든 표면에 달라붙는 것이 자연 상태. 이동은 크롤링과 차징 발사로 수행.  
WASD + Space 키로 조작. 모든 시간 단위는 **초(seconds)** 기준.

**장르 지향**: 점프킹, Egging On, 셀레스트, 구구피자 계열의 정밀 플랫포머.  
슬라임의 소프트바디 비주얼은 게임플레이에 영향을 주지 않는다. 조작 반응성과 예측 가능성이 최우선.

---

## 1. 구현 아키텍처 — 2단계 분리

### Phase 1: 단일 원형 콜라이더 플랫포머 (핵심)

게임플레이 전체가 **원 하나**로 동작한다.

- 충돌 판정, 이동, 차징, 발사, 에어 컨트롤, 벽 부착, 드리프트 — 전부 단일 원형 콜라이더 기반.
- 소프트바디 없이도 모든 메커닉이 완전히 동작함.
- 점프킹/셀레스트와 동일한 구조.

### Phase 2: 소프트바디 비주얼 오버레이 (후순위)

Phase 1이 완성된 후 비주얼로 얹는 레이어.

- 중심 1개 + 주변 6개 노드가 스프링으로 연결된 링 구조.
- 주변 노드는 중심 노드의 Position을 읽어서 스프링으로 따라감. **중심 → 주변 단방향.**
- 바닥에서 퍼지고, 벽에서 처지고, 공중에서 늘어나는 비주얼 연출.
- **게임플레이 수치(발사력, 방향, 상태 전환)에는 일절 관여하지 않음.**
- Phase 1의 게임플레이 코드를 건드리지 않고 추가 가능.

이하 문서는 **Phase 1 (단일 원형 콜라이더)** 기준으로 작성.

## 2. 표면 부착 & 드리프트

### 부착 판정

- 원형 콜라이더가 표면에 접촉하면 **Attached 상태** 진입.
- 부착 판정은 `Physics2D.OverlapCircle` 또는 충돌 콜백으로 처리.

### 벽/천장 드리프트

Attached 상태에서 표면이 수직/천장에 가까울수록 중력 방향으로 흘러내린다.

```
surfaceUp = dot(surfaceNormal, Vector2.up);        // 바닥=1, 벽=0, 천장=-1
driftMultiplier = 1 - clamp01(surfaceUp);            // 바닥=0, 벽=1, 천장=1
centerDrift = baseDriftSpeed * driftMultiplier * dt;
position += gravity.normalized * centerDrift;
```

- **바닥**: 드리프트 없음. 안정적.
- **벽**: 중력 방향으로 흘러내림. 빨리 쏘면 높은 위치에서 발사, 늦으면 낮아짐.
- **천장**: 벽과 동일하게 드리프트. 부착 유지 시간이 더 짧음.
- **경사면**: 기울기에 비례하여 연속적으로 드리프트. 급할수록 빨리 미끄러짐.

드리프트로 표면 끝에 도달하면 Attached 해제 → Airborne 전환.

### 불안정한 표면의 페널티

**발사력 공식에 페널티 계수는 없다.** 파워는 플레이어 조작으로만 결정.

불안정한 표면에서의 난이도는 **물리적 시간 제한**으로 발생:
- 벽/천장에서 흘러내리므로 차징 시간이 제한됨.
- 경사면에서는 차징 중에도 미끄러짐.
- 별도의 안정도 시스템 없이, 물리 상황 자체가 난이도를 만든다.

## 3. 표면별 상호작용

### 바닥

- 드리프트 없음. 안정적.
- 차징 시간 제한 없음 (판정원 가장자리 도달만 존재).
- 여유롭게 조준 가능.

### 벽

- 중력 방향으로 드리프트.
- 빨리 쏘면 높은 위치에서 발사. 늦으면 낮아짐.
- 자연스러운 시간 압박.

### 천장

- 벽과 동일하게 드리프트. 부착 유지 시간이 더 짧음.
- 천장 발사는 고급 테크닉.

### 좁은 플랫폼

- 크롤링으로 위치 미세 조정이 중요.
- 가장자리에서 떨어지기 쉬움.

### 경사면

- 기울기에 비례하여 드리프트.
- 차징 중에도 미끄러짐 — 경사 위에서 정밀 조준이 어려움.

---

## 4. 이동

### 표면 크롤링

- 스페이스를 누르지 않은 상태에서 **WASD**로 천천히 기어다님.
- 바닥: A/D 좌우. 벽: W/S 위아래. 천장: A/D 좌우.
- 이동 속도는 느림 — 위치 미세 조정용이지 주 이동 수단이 아님.
- **스페이스 홀드 중에는 WASD가 판정원 내 조준점 조작으로 전환.** 크롤링 중단.

### 주 이동 수단: 차징 발사

- 표면에서 표면으로의 이동은 전부 차징 발사로 수행.

## 5. 차징 & 발사 — 판정원 모델

### 원리

스페이스를 누르면 슬라임 중심에 **판정원(charge circle)**이 생성되고, 그 안에 **조준점(aim point)**이 나타난다.  
조준점은 시간에 따라 자동으로 바깥쪽으로 밀려나며, 플레이어는 WASD로 조준점의 위치를 조절한다.  
발사 시 **슬라임 중심에서 조준점까지의 벡터**가 발사 방향과 파워를 동시에 결정한다.

### 판정원 구조

```
         판정원 (고정 반지름)
        ╱                  ╲
      ╱    조준점 ●→          ╲     ← 시간에 따라 바깥으로 밀려남
    ╱       ↑WASD로 조절        ╲
   │      슬라임 중심 ○           │
    ╲                            ╱
      ╲                        ╱
        ╲                    ╱
```

- **판정원 중심** = 슬라임 위치 (고정).
- **조준점 초기 위치** = 판정원 중심 (파워 0, 방향 미정).
- **자동 드리프트**: 조준점은 매 프레임 **표면 법선 반대 방향**(= 표면 안쪽)으로 밀려남. 바닥이면 아래로, 벽이면 벽 안쪽으로.
- **조준점 위치가 발사를 결정**: 중심에서 조준점까지의 거리 = 파워, 방향 = 발사 반대 방향 (압축-발사 모델).

### WASD 조준점 조작

차징 중 WASD로 조준점에 **2D 가속도**를 준다.

- **바깥쪽**: 드리프트 방향과 같으면 가속. 빨리 강해지지만 방향 잡을 시간 줄어듦.
- **안쪽**: 드리프트에 역행. 차징을 늦추면서 방향 조정 시간 확보.
- **좌우**: 발사 각도 조절.
- 네 방향 조합으로 판정원 내 모든 위치에 도달 가능.

```
// 매 프레임
aimPoint += driftDirection * autoDriftSpeed * dt;     // 자동 드리프트
aimPoint += wasdInput * inputAcceleration * dt;        // 플레이어 조작

// 판정원 경계 클램프
if (distance(aimPoint, center) >= chargeRadius)
    발사 트리거;
```

### 파워와 방향

```
offset = aimPoint - slimeCenter;
power = (offset.magnitude / chargeRadius) * baseLaunchPower;
launchDirection = -offset.normalized;   // 압축 반대 방향으로 발사
```

- 조준점이 중심 근처 → 약한 파워, 방향 자유.
- 조준점이 가장자리 근처 → 강한 파워, 방향 전환 어려움 (원호를 크게 돌아야 하므로).
- **조준 관성이 기하학적으로 발생.** 별도의 resistFactor 불필요.

### 발사 트리거 (2가지)

1. **스페이스 릴리즈** — 원하는 타이밍에 수동 발사. 그 순간의 조준점 위치로 발사.
2. **조준점이 판정원 가장자리 도달** — 자동 발사. 풀파워.

### 차징 규칙

- **차징 캔슬 불가.** 스페이스를 누르면 무조건 발사까지 진행. 커밋.
- **발사 후 입력 무시 윈도우: 0.05초.** 잔여 키 입력 무효화.
- 큐빅 커브 불필요 — 플레이어가 WASD로 파워 타이밍을 능동적으로 조절.

### 트레이드오프 구조

| 선택 | 결과 |
|------|------|
| 바깥쪽으로 가속 | 빠르게 강해짐. 방향 잡을 시간 줄어듦. |
| 안쪽으로 버팀 | 조준 시간 확보. 벽에서는 드리프트로 위치 잃음. |
| 일찍 릴리즈 | 약한 파워, 정확한 방향. |
| 가장자리까지 대기 | 풀파워, 자동 발사 타이밍 제어 불가. |

## 6. 벽 충돌 — 바운스 없음, 에너지 전환

### 핵심 원칙

**벽에 부딪히면 튕겨나오지 않는다.** 무조건 벽에 붙는다.  
바운스 메커니즘은 전면 삭제.

### 두 가지 충돌 모드

| 충돌 시 스페이스 상태 | 결과 |
|----------------------|------|
| **안 누르고 있었음** | 철퍼덕 붙음. 운동에너지 전부 소멸. 이후 일반 차징으로 발사. |
| **누르고 있었음** | 충돌 속력이 차징 에너지로 전환. 조준점이 가장자리 근처에서 시작. |

### 운동에너지 전환 규칙

```
normalSpeed = max(0, dot(velocity, -wallNormal));  // 법선 방향 성분만 사용
initialOffset = min(normalSpeed * conversionRate, chargeRadius);
```

- 전환된 에너지는 **조준점의 초기 위치**로 세팅. 판정원 중심에서 벽 법선 안쪽 방향으로 initialOffset만큼 떨어진 곳에서 시작.
- 빠르게 박으면 조준점이 가장자리 근처에서 시작 → 자동 발사 임박 + 방향 전환 어려움.
- 느리게 닿으면 중심 근처에서 시작 → 여유 있지만 파워 약함.
- 비스듬히 닿으면 법선 성분만 전환. 스치듯 지나가는 것은 전환량이 적음.
- 벽에 붙은 후 자동 드리프트 + WASD 조작으로 이어짐.

### 난이도의 종류 분화

같은 벽 구간을 두 가지 방식으로 공략 가능:
- **안전 루트**: Space 안 누르고 붙음 → 에너지 소멸 → 일반 차징. 중심에서 시작, 여유 있는 조준.
- **스피드 루트**: Space 누르고 빠르게 박음 → 가장자리 근처 시작 → 풀파워에 가깝지만 조준 어려움.

### 설계 의도

**사전 커밋 원칙의 일관성**: 차징도 캔슬 불가, 벽 충돌도 "부딪히기 전에 스페이스를 누를지 말지 미리 결정해야 한다." 예측하고 커밋한 플레이어가 보상받는 구조.

## 7. 공중 제어

- **A/D**: 속도 벡터의 **방향만 회전.** 총 속력 보존.
- 완전한 U턴 불가능, 완만한 곡선 보정만 가능.

```
float originalSpeed = velocity.magnitude;
float currentAngle = atan2(velocity.y, velocity.x);
float maxDelta = airControlAngularSpeed * dt / originalSpeed;
currentAngle += input.x * maxDelta;
velocity = angleToVector(currentAngle) * originalSpeed;
```

### 대칭 중력

- **상승/하강 동일한 중력 적용.** 비대칭 중력(fallMultiplier) 삭제.
- 키네마틱 방식: 매 프레임 `velocity.y += gravity * dt`.
- 대칭 포물선으로 궤적 예측 가능성 극대화.
- 체공감이 과하면 기본 gravity 값을 올려서 조절.

## 8. 프로토타입 초기 수치 (튜닝 출발점)

| 항목 | 수치 |
|------|------|
| **콜라이더** | |
| 충돌 형태 | 단일 원형 콜라이더 |
| **중력** | |
| 중력 | 대칭. 키네마틱 적용 (`velocity.y += gravity * dt`) |
| **벽/천장 드리프트** | |
| 기본 드리프트 속도 (baseDriftSpeed) | 튜닝 필요 |
| 드리프트 = baseDriftSpeed × (1 - surfaceUp) | surfaceUp = dot(normal, up) |
| **공중 제어** | |
| 에어 컨트롤 | 속도 벡터 방향 회전 (속력 보존) |
| 에어 컨트롤 각속도 (airControlAngularSpeed) | 튜닝 필요 |
| **판정원 차징** | |
| 판정원 반지름 (chargeRadius) | 튜닝 필요 |
| 자동 드리프트 속도 (autoDriftSpeed) | 튜닝 필요 |
| WASD 가속도 (inputAcceleration) | 튜닝 필요 |
| 기본 발사력 (baseLaunchPower) | 튜닝 필요 |
| 발사 방향 | 슬라임 중심 → 조준점 벡터의 반대 방향 |
| 자동 발사 | 조준점이 판정원 가장자리 도달 시 |
| 발사 후 입력 무시 윈도우 | 0.05초 |
| **벽 충돌 에너지 전환** | |
| 전환 비율 (conversionRate) | 튜닝 필요 |
| 최대 전환량 | 판정원 반지름 (= 풀파워) |
| 속도 임계값 | 없음 (Space 홀드 여부만으로 분기) |
| **크롤링** | |
| 표면 이동 속도 | 느림 (튜닝 필요) |

## 9. 입력 요약

### 표면 (바닥/벽/천장 공통)

| 입력 | 동작 |
|------|------|
| WASD | 표면 위 크롤링 |
| Space 홀드 | 차징 시작 (판정원 생성, 조준점 중심에서 출발) |
| Space + WASD | 조준점 2D 조작 (바깥=가속, 안쪽=감속, 좌우=각도) |
| Space 릴리즈 | 발사 (수동, 현재 조준점 위치 기준) |
| 조준점 가장자리 도달 | 발사 (자동, 풀파워) |

### 공중

| 입력 | 동작 |
|------|------|
| A / D | 궤도 방향 회전 (속력 보존) |
| Space 홀드 | 벽 충돌 시 운동에너지 전환 준비 |

### 벽 충돌

| 충돌 시 상태 | 결과 |
|-------------|------|
| Space 안 누름 | 붙음. 에너지 소멸. 일반 차징 시작 가능. |
| Space 누르고 있음 | 붙음. 법선 속력 → 조준점 초기 위치 전환. |

## 10. 설계 원칙 요약

1. **원 하나가 게임 전부**: 단일 원형 콜라이더로 모든 게임플레이 동작. 소프트바디는 비주얼 오버레이로 나중에 추가.
2. **점성 슬라임**: 모든 표면에 달라붙는다. 바운스 없음.
3. **파워와 방향은 하나의 점이 결정**: 판정원 내 조준점 위치 = 파워 + 방향. 별도 계수 없음.
4. **불안정함은 시간이 만든다**: 벽/천장/경사면에서 드리프트로 시간 제한. 별도 페널티 시스템 불필요.
5. **입력 단순**: WASD + Space. 5개 키로 모든 조작.
6. **차징은 커밋**: 캔슬 불가. 파워와 방향은 발사 순간까지 능동적으로 조절 가능.
7. **파워-조준 트레이드오프**: 기하학적으로 발생. 가장자리에서는 같은 입력으로 각도를 바꾸기 어려움. 별도의 관성 파라미터 불필요.
8. **사전 커밋 보상**: 벽 충돌 전 스페이스를 미리 누른 플레이어가 에너지 전환 보상을 받음. 높은 전환량 = 조준점이 가장자리 근처에서 시작.
9. **대칭 중력**: 포물선 예측 가능성. 키네마틱 방식.
10. **시스템 분리**: 중력 → 수직, 에어 컨트롤 → 방향 회전. 차징은 판정원 내부 로직으로 표면과 독립. 드리프트는 표면 법선만으로 결정.
