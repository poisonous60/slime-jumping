근데 점프킹이나 Egging On은 입력 구조가 완전히 다르잖아. 차징해서 쏘면 끝이야. 공중에서 플레이어가 할 수 있는 게 없거나 극히 적어. 이 구조에서 중요한 건 반응성이 아니라 궤적 예측 가능성이야. 내가 이만큼 차징하면 이 포물선을 그린다는 걸 몸으로 익히는 게 게임의 핵심이거든. 비대칭 중력을 넣으면 올라가는 궤적과 내려오는 궤적이 비대칭이 돼서 포물선이 아니라 찌그러진 호가 되고, 그걸 직관적으로 읽기가 훨씬 어려워져.
지금 설계 문서를 보면 차징은 캔슬 불가에 방향도 시작 시 확정이고, 에어 컨트롤도 수평 보정만 약하게 가능하잖아. 점프킹 쪽에 훨씬 가까워. 그러면 대칭 중력으로 깨끗한 포물선을 유지하는 게 플레이어가 "이 차징 세기면 저기 닿겠다"를 학습하기 훨씬 쉬워.
셀레스트가 비대칭 중력을 쓰는 건 맞는데, 셀레스트는 점프 중간에 대시가 있고, 벽점프가 있고, 공중에서 방향 전환이 자유롭잖아. 매 순간 입력이 의미 있으니까 하강 가속이 "다음 입력을 빨리 하게 만드는" 긴장감으로 작동해. 차징-커밋 구조에서는 그 긴장감이 필요 없어 — 이미 쏜 순간 커밋한 거니까.
다만 하강이 느리다는 느낌 자체는 실제로 문제일 수 있어. 그건 비대칭 중력이 아니라 기본 중력값을 올려서 해결하는 게 낫고. 전체 중력을 높이면 포물선이 더 납작해지면서 상승도 하강도 빨라지고, 대칭은 유지돼. 점프킹이 실제로 이렇게 해 — 중력이 꽤 세서 체공 시간이 짧고, 그래서 긴장감이 있는 거지.

스페이스바 누르고 있었으면 충돌 순간 속력이 차징 에너지로 전환돼. 이미 차지가 차있는 상태로 벽에 붙으니까, WASD로 방향 잡고 스페이스 떼면 바로 발사. 빠르게 온 만큼 세게 나가는 거야.
이게 좋은 이유가, 사전 커밋 구조가 게임 전체 철학이랑 일관돼. 차징도 캔슬 불가, 방향도 시작 시 확정이잖아. 벽 충돌도 "부딪히기 전에 미리 결정해야 한다"는 같은 원칙이야. 스페이스를 미리 안 눌렀으면 에너지를 잃는 게 당연하고, 미리 눌렀으면 보상받는 거고.
구현 관점에서 생각해볼 것 하나:
전환 비율을 어떻게 잡느냐야. 충돌 속력을 그대로 차징 파워로 1:1 매핑하면, 높은 곳에서 떨어지면서 벽에 박으면 풀차징보다 센 발사가 나올 수 있어. 그게 의도된 거라면 상관없는데, 아니라면 캡을 걸거나 곡선을 넣어야 해.
storedPower = min(impactSpeed * conversionRate, maxChargePower)
아니면 일반 차징의 풀파워를 상한으로 잡아서, 운동에너지 전환은 "차징 시간을 단축시켜주는 것"으로 포지셔닝할 수도 있어. 빠르게 박으면 거의 풀차지 상태로 붙고, 느리게 닿으면 반차지 정도에서 시작하는 식으로. 이러면 일반 차징과 보상 스케일이 통일돼서 레벨 디자인이 편해져.
방향 입력 타이밍도 정해야 해. 지금 일반 차징은 스페이스 누르는 순간 WASD로 방향 확정이잖아. 운동에너지 전환일 때는 벽에 붙는 순간이 차징 시작점이 되는 건지, 아니면 스페이스를 먼저 누른 시점에 이미 방향이 잡혀있는 건지. 벽 충돌 순간에 방향을 읽는 게 자연스러울 것 같은데, 이건 테스트해봐야 알겠지.아, 차징 방향은 스페이스바 누르고 차징이 풀로 차서 발사되거나 스페이스바를 놓아서 발사하기 전까지 wasd로 계속 조절할 수 있게 만들고 싶어.오전 11:24차징 중 방향 조절 메커닉 변경사항을 검토했다차징 중 방향 조절 메커닉 변경사항을 검토했다그게 훨씬 나은 것 같아. 기존의 "방향 시작 시 확정"은 슬라임이 바닥에서만 쏘던 초기 설계에서 나온 건데, 벽/천장에서 붙어서 흘러내리는 동안 방향을 못 바꾸면 답답하거든.
다만 이러면 입력 구조가 바뀌는 부분이 하나 있어.
지금은 스페이스 안 누른 상태에서 WASD가 크롤링이고, 스페이스 누르면 WASD가 조준이잖아. 방향을 계속 바꿀 수 있으면 차징 중에 크롤링은 완전히 멈추는 게 맞고, 그건 기존 설계랑 동일하니까 충돌 없어.
그리고 풀차지 자동 발사는 새로 들어가는 거지? 이건 좋은 압박 장치야. 벽에서 흘러내리면서 안정도 떨어지는 압박이 있는데, 거기에 차지 게이지도 차오르는 이중 압박이 생기니까. 빨리 방향 잡고 적당한 타이밍에 놓을 건지, 풀차지까지 기다릴 건지 판단해야 하는 거잖아.
운동에너지 전환이랑 조합하면 이런 흐름이 돼 — 스페이스 누른 채로 벽에 박으면, 충돌 속력만큼 게이지가 이미 차있는 상태로 붙어. WASD로 방향 조절하면서, 스페이스 놓으면 그 시점 파워로 발사, 계속 들고 있으면 게이지가 올라가다가 풀차지되면 자동 발사. 빠르게 박았으면 거의 풀차지니까 방향 잡을 시간이 짧고, 느리게 닿았으면 여유가 있는 대신 파워가 약한 거야.일단 지금까지 말한 매커니즘을 문서로 써줘.오전 11:27문서 작성을 위해 메커니즘 정리했습니다문서 작성을 위해 메커니즘 정리했습니다v2에서 바뀐 부분을 전부 반영했고, 마지막에 v2 대비 변경사항 표도 넣어뒀어. 방향 입력 버퍼 0.1초는 차징 중 자유 변경으로 바뀌면서 더 이상 필요 없어져서 빠졌어.Slimejumping 메커닉 설계 v3문서 · MD 다운로드내가 생각하던 wasd 방향 조절이랑 좀 결이 다른데.
나는 포고스틱처럼 wasd로 차징 중에 방향을 각도 단위로 미세조정하는 걸 생각했어. 그리고 방향 조절하는 건 슬라임이 그쪽으로 압축하는 방향이라서 날아가는건 반대 방향으로 나가게. as로 차징을 하면 슬라임이 왼쪽아래로 몸을 압축했다가 발사할 때 몸이 늘어나면서 오른쪽 위로 날아가는거야.
그런데 포고스틱이랑 지금 시스템의 차이가 있는데, 포고스틱의 경우에는 착지하는 점이 포고스틱의 끝부분이라서 좌우 회전으로 방향을 조절할 수 있었어. 그런데 이 슬라임에서는 따로 착지 점 기준이 애매한 거 같아오전 11:32슬라임 착지점을 점착 중심으로 설정하여 포고스틱 회전 메커니즘 적용했다슬라임 착지점을 점착 중심으로 설정하여 포고스틱 회전 메커니즘 적용했다피봇 포인트가 이미 시스템 안에 있어. **부착 노드들의 평균 위치(부착 중심)**가 그거야.
포고스틱은 막대 끝이 땅에 닿은 점이 피봇이잖아. 슬라임에서는 표면에 붙어있는 주변 노드들의 무게중심이 그 역할을 해. 바닥이면 아래쪽에, 벽이면 벽쪽에, 천장이면 위쪽에 피봇이 자연스럽게 생기는 거야.
차징하면 중심 노드가 부착 중심 쪽으로 압축돼. WASD로 각도를 틀면 압축 방향이 부착 중심 기준으로 회전하고, 발사는 그 반대 방향. 포고스틱이랑 구조적으로 동일해지는 거지.
바닥에서 예를 들면:
부착 중심이 슬라임 아래쪽에 있어. 아무 방향 입력 없이 차징하면 중심 노드가 아래로 눌리고, 발사는 위로. 여기서 A를 누르면 압축 방향이 왼쪽 아래로 기울고, 발사는 오른쪽 위로 나가. A를 계속 누르고 있으면 각도가 점점 더 왼쪽으로 돌아가는 거야.
벽에서는:
오른쪽 벽이면 부착 중심이 슬라임 오른쪽에 있어. 기본 차징은 오른쪽으로 눌리고 발사는 왼쪽. W를 누르면 압축 방향이 오른쪽 위로 기울고 발사는 왼쪽 아래, S를 누르면 반대.
이게 좋은 이유가, 표면 종류에 따라 입력을 다르게 매핑할 필요가 없어. "부착 중심 방향으로 기본 압축, WASD로 각도 회전"이라는 하나의 규칙이 바닥이든 벽이든 천장이든 자동으로 맞아떨어져.
좁은 플랫폼에서 재밌는 점은, 부착 노드가 한쪽에 몰려있으면 부착 중심도 치우쳐져 있잖아. 그러면 기본 발사 방향 자체가 한쪽으로 편향돼. 똑바로 위로 쏘고 싶으면 WASD로 보정해야 하는 거야. 안정도 시스템이랑 자연스럽게 맞물려.
구현은 이런 식이 될 거야:
// 차징 시작 시 초기 각도: 중심 → 부착 중심 방향
baseAngle = atan2(adhesionCenter - centerNode.Position);

// 매 프레임 WASD 입력으로 각도 회전
currentAngle += inputDirection * rotationSpeed * dt;

// 압축 방향 = currentAngle, 발사 방향 = currentAngle + 180°
compressDirection = Vector2(cos(currentAngle), sin(currentAngle));
launchDirection = -compressDirection;
WASD를 어떻게 각도 회전에 매핑할지는 정해야 해. A/D가 좌우 회전이고 W/S는 안 쓰는 게 가장 직관적일 것 같은데, 아니면 WASD 전부를 2D 방향으로 써서 압축 방향을 직접 지정하는 것도 가능하고. 어떤 느낌을 생각하고 있어?흠. 부착된 곳으로 자동 차징 괜찮네. 그런데 걱정되는점이 지금 6개 링으로 했을 때는 바닥에 2개 점 붙을 때가 있고 살짝 회전에서 3개 점 붙을 때도 있는데, 이게 실제 플레이에서는 각 노드가 어디있는지 몰라서 어디 기준인지 직관적이지 않을 것 같아오전 11:34중심 노드 접촉점을 기준으로 회전축 단순화했다중심 노드 접촉점을 기준으로 회전축 단순화했다그 걱정이 맞아. 부착 노드 2개일 때와 3개일 때 평균 위치가 달라지는데 플레이어는 그걸 모르니까, 같은 상황인 줄 알고 쐈는데 각도가 미묘하게 다른 경험을 하게 돼. 정밀 플랫포머에서 치명적이야.
근데 중심 노드를 키네마틱으로 바꿨잖아. 중심 노드의 접촉점을 피봇으로 쓰면 돼.
중심 노드가 단일 원형 콜라이더니까 표면과 닿는 점이 항상 하나야. 바닥이면 원의 맨 아래, 오른쪽 벽이면 원의 맨 오른쪽. 노드가 몇 개 붙어있든 상관없이 접촉점은 항상 같은 위치에 있고, 플레이어도 "슬라임이 표면에 닿은 곳"을 직관적으로 알 수 있어.
기본 압축 방향은 중심 → 접촉점이 되는 거야. 바닥이면 아래, 벽이면 벽쪽. 여기에 WASD로 각도를 돌리고, 발사는 반대.
contactPoint = centerNode.Position + (-surfaceNormal * radius);
baseAngle = atan2(contactPoint - centerNode.Position);
주변 노드 부착 상태는 원래 역할대로 안정도와 파워에만 영향을 줘. 2개 붙었으면 약하고, 3개 붙었으면 강하고. 하지만 방향은 건드리지 않아. 이러면 역할이 깔끔하게 나뉘어:
접촉점 → 발사 방향의 기준점 (예측 가능, 항상 동일)
부착 노드 수 → 발사 파워 (안정도)
CoM 오프셋 → 방향 편향은 삭제하거나 극소량만 남김
CoM 오프셋 편향은 사실 이 구조에서는 빼는 게 나을 수 있어. 방향 불확실성이 두 군데(피봇 위치 + CoM 편향)에서 오면 플레이어가 뭘 보정해야 하는지 혼란스러워지거든. 파워만 안정도에 영향받고, 방향은 순수하게 플레이어 입력으로만 결정되는 게 정밀 플랫포머 철학에 맞아.근데 지금 중심점이 직접 바닥에 안 닿고 있는데, 어떻게 바꾼다는거야? 지금은 주변 노드랑 중심 노드가 스프링으로 연결된 구조야오전 11:35중심점을 표면에 투영하여 가상 접촉점 설정 제안중심점을 표면에 투영하여 가상 접촉점 설정 제안맞아, 중심 노드는 주변 노드들 사이에 떠있는 구조지. 실제로 표면에 닿는 건 주변 노드들이고.
근데 물리적으로 닿을 필요가 없어. 표면까지의 최단점을 가상 접촉점으로 쓰면 돼.
중심 노드 위치에서 현재 붙어있는 표면 콜라이더에 ClosestPoint를 찍으면, 중심 노드 바로 아래(바닥일 때)나 바로 옆(벽일 때) 점이 나오잖아. 그게 피봇이야. 주변 노드가 어떻게 붙어있든 중심 노드 위치와 표면 형상만으로 결정되니까 항상 같은 결과가 나와.
virtualContact = surface.ClosestPoint(centerNode.Position);
baseAngle = atan2(virtualContact - centerNode.Position);
플레이어 입장에서도 직관적이야. 슬라임 덩어리 한가운데에서 바닥 방향으로 눌린다는 건 눈으로 봐도 자연스럽고, 표면이 바뀌어도 "표면 쪽으로 눌렸다가 반대로 튀어나간다"는 하나의 규칙만 알면 돼.그럼 두 개 이상의 벽에 동시에 닿고 있을 때는 어떡해오전 11:36다중 표면 접촉 시 가장 가까운 표면 선택 방식을 검토했다다중 표면 접촉 시 가장 가까운 표면 선택 방식을 검토했다가장 가까운 표면을 쓰면 돼.
중심 노드에서 각 접촉 표면까지 거리를 재고, 제일 가까운 게 현재 피봇 표면. 코너에 앉아있으면 바닥이 더 가깝고, 크롤링으로 벽 쪽에 붙으면 벽이 더 가까워지면서 피봇이 전환되는 거야.
다만 두 표면 거리가 거의 같은 경계에서 피봇이 프레임마다 왔다갔다하면 조준이 덜덜 떨릴 수 있어. 히스테리시스를 넣어서, 현재 피봇 표면에서 다른 표면으로 전환되려면 거리 차이가 일정값 이상 벌어져야 바뀌게 하면 돼.
if (currentPivotSurface != nearestSurface 
    && distanceDiff > switchThreshold)

Airborne에서 Space를 들고 있었는데 벽에 붙으면, Attached를 건너뛰고 바로 Charging으로 가면서 초기 차지량을 에너지 전환값으로 세팅해야 해. 이때 초기 조준 각도도 벽 법선에서 시작해야 하고, chargeRatio가 0이 아닌 상태에서 시작하니까 조준도 이미 뻑뻑한 상태야. 차징 시간 계산도 주의해야 해 — t를 0에서 시작하면 큐빅 커브가 처음부터 다시 올라가서 전환된 에너지 위에 중복 적용돼. 전환된 chargeRatio에 해당하는 t값을 역산해서 거기서부터 시작해야 해. t_start = cbrt(storedRatio) * maxDuration.
표면 법선 안정성. 초기 조준 각도가 법선에서 오는데, 코너 근처에서는 법선이 프레임마다 뒤집힐 수 있어. 특히 박스 콜라이더 모서리에서. 차징 시작하는 순간에 법선이 한 번 튀면 기본 발사 방향이 엉뚱한 쪽으로 잡혀. 차징 진입 시 법선을 여러 프레임 평균내거나, 히스테리시스에서 확정된 표면의 법선을 쓰는 게 안전해.
풀차지 직전 피드백. 큐빅 커브 특성상 0.7초에서 1.0초 사이에 chargeRatio가 0.34에서 1.0으로 급등해. 마지막 몇 프레임에서 갑자기 자동 발사되면 플레이어가 "아직 안 쐈는데" 느낌을 받아. 90% 이상 도달하면 시각/청각 경고를 줘야 해. 구현 자체는 쉬운데 까먹기 쉬워.
크롤링과 중심 드리프트 합산. 벽에서 W로 위로 기어가는데 중심 드리프트가 아래로 끌어내리잖아. 이 두 개가 어떻게 합쳐지는지 명확하게 정해야 해. 단순 합산이면 안정도가 높을 때는 크롤링이 이기고 안정도가 낮아지면 드리프트가 이겨서 위로 올라가다가 결국 미끄러지는 느낌이 나는데, 그게 의도한 거면 괜찮고 아니면 별도 처리가 필요해.
조준 회전 속도 클램핑. rotationSpeed = baseRotationSpeed * (1 - chargeRatio * resistFactor)에서 resistFactor가 1보다 크면 rotationSpeed가 음수 돼. 음수면 입력 반대로 돌아가니까 반드시 max(0, ...)로 클램핑해야 해. 0이면 완전히 잠기는 건데, 풀차지 근처에서 아예 못 돌리는 게 맞는지도 정해야 하고.
