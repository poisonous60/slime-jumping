## 최근 변경 하이라이트 (2026-04)

- **2026-05-09**: `SnowSettings.slopeToDragScale` 추가 — plow drag 의 표면-각도 감쇠 + stop-snap 의 decay 게이팅 ([snow-field.md §Plow drag](features/platforms/snow-field.md#plow-drag-슬라임이-눈을-밀고-들어감), [Scripts/Platforms/Snow/SnowSettings.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/Snow/SnowSettings.cs), [Scripts/Controller/SlimeController.SurfaceModifiers.cs](../SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.SurfaceModifiers.cs)). `slopeToHeightScale` 와 동일한 AnimationCurve 패턴 (X = 컨택트 노멀의 수평 대비 각도°, Y = 배율). `ApplySnowDrag` 가 `SurfaceProbe.GetSurfaceAngle(surfaceNormal, gravityUp)` 로 각도 산출 후 `plowDragK *= curve.Evaluate(angleDeg)` 적용. Default 키프레임 `(0,1)(60,1)(90,0)` — 60°까지 풀 drag, 90°에서 0. 추가로 `SnowDragStopSpeed` (0.3 m/s) snap 을 `1 - decay >= 0.05` (= K·depth·dt 가 의미 있는 크기) 일 때만 fire 하도록 게이트 — 그러지 않으면 slope-faded K 가 거의 0인 수직 벽에서 inertial slide 모드의 `slideVelocity` 가 매 프레임 gravity 로 ~0.4 m/s 누적되자마자 snap 이 0 으로 죽여서 슬라임이 영원히 매달리는 버그가 났음. 거의 수직인 벽에 묻은 눈에서 슬라임이 자연스럽게 미끄러짐.

- **2026-05-09**: `TautLine` 점프 boost — magnitude 캡 폐기 + pre-bonus speed falloff 도입 ([taut-line.md §점프 boost (Effect-mode)](features/platforms/taut-line.md#점프-boost-effect-mode), [Scripts/Platforms/TautLine.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/TautLine.cs)). 동기: 기존 `maxLaunchSpeed` (PostprocessLaunchVelocity 의 최종 magnitude clamp) 가 "TautLine 으로 더 높이 올라가는 거 막기" 의도였지만 EnergyConversion 발사 (= 슬라임이 높은 곳서 떨어져 줄에 착지하면서 누적된 power 로 발사) 까지 같이 깎음 → 사용자 의도는 "슬라임 자체 power 는 그대로, rope bonus 만 깎기". (1) **`maxLaunchSpeed` 필드 + PostprocessLaunchVelocity 의 magnitude clamp 제거** — `minLaunchVerticalSpeed` 만 남음. (2) **`boostFalloffStartSpeed` (default 12) / `boostFalloffEndSpeed` (default 18) 두 필드 신설** — pre-bonus 슬라임 launch 속도 (`slime.Velocity.magnitude` at GetLaunchBonus 시점, EnergyConversion power + carrier inheritance + hyperdash 다 포함, **rope bonus 만 미포함**) 가 start 이하면 full boost, end 이상이면 boost 0, 사이는 `1 - InverseLerp(start, end, speed)` 선형 감쇠. end ≤ start 면 hard cutoff. (3) **`GetLaunchBonus` 끝부분만 변경** — `clamp(bonus, 0, maxCap) × speedMul` 반환. 기존 timing × chargeRatio × upwardComponent 식, maxCap clamp 모두 그대로. (4) **결과**: 일반 charge 발사 (pre-bonus ≈ 9 m/s) → full boost / EnergyConversion 강한 발사 (pre-bonus ≥ 18 m/s) → boost 0, 슬라임은 자기 변환된 운동에너지 그대로 쓰며 자연스럽게 그 높이까지 올라감. baseLaunchPower 9 m/s 에 맞춘 default 라 designer 가 인스펙터에서 자유 튜닝.

- **2026-05-08**: `Snowball ↔ SnowField` Phase 9 상호작용 — carve / grow / splash ([snowball.md §SnowField 상호작용](features/mechanisms/snowball.md#snowfield-상호작용-phase-9), [snow-field.md §heightMax / Splash / RaiseLocal](features/platforms/snow-field.md#heightmax--splash--raiselocal-phase-9), [Scripts/Mechanisms/Snowball.cs](../SlimeJumping_v2/Assets/Scripts/Mechanisms/Snowball.cs), [Scripts/Platforms/Snow/SnowField.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/Snow/SnowField.cs), [Scripts/Platforms/Snow/SnowStrip.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/Snow/SnowStrip.cs), [Scripts/Platforms/Snow/SnowSettings.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/Snow/SnowSettings.cs)). 동기: Stage 2 의 Snowball 이 SnowField 위를 그냥 굴러갈 뿐 표면 변형도 / 시각 변화도 / 입자 이펙트도 없음 — 그라나잇 블래스트가 한 점에 dent 를 파듯 굴러가면서 길게 도랑을 파고, 굴러갈수록 점점 커지고, 떨어져 착지하면 분화구 + 둔덕이 생기는 연출이 필요. (1) **연속 carve** — 매 FixedUpdate `field.Carve(snapHit.point, carveDepthPerSec * dt, radius * carveRadiusMultiplier)` 호출. 그라나잇 블래스트가 쓰는 동일 채널을 누적해 매끈한 도랑 생성. carve 폭이 ball 반경에 비례하므로 큰 공이 더 굵게 팜. (2) **per-meter 성장** — `radius += growthPerMeterByRadius.Evaluate(radius) * step.magnitude`. AnimationCurve x 축 = raw 반경 (m, 정규화 X), y 축 = 미터당 자라는 양. designer 가 작은 공일수록 빠르게 / 큰 공이면 둔화 같은 곡선 직접 그림. `maxRadius` 하드캡. **순수 visual + collider 스케일** — `maxSpeed`/`gravity`/`breakSlopeDelta` 게임플레이 튜닝은 손대지 않음 (사용자 결정 — 그래도 collider 가 커지면서 stomp/knockback footprint 는 자연 변화).
