## 최근 변경 하이라이트 (2026-04)

- **2026-05-04**: `RopeV3` — 트램폴린 결합 로프 추가 ([rope-v3.md](features/platforms/rope-v3.md), [Scripts/Platforms/RopeV3.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/RopeV3.cs), [Scripts/Platforms/IRopePlatform.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/IRopePlatform.cs), [Scripts/Platforms/Rope.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/Rope.cs), [Scripts/Platforms/RopeV2.cs](../SlimeJumping_v2/Assets/Scripts/Platforms/RopeV2.cs), [Scripts/Controller/SlimeController.cs](../SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.cs), [Scripts/Editor/RopeTestSetup.cs](../SlimeJumping_v2/Assets/Scripts/Editor/RopeTestSetup.cs)). 동기: V2 의 `ApplyRiderImpact` 가 한 FixedUpdate 안에 슬라임의 pre-attach 속도를 통째로 `pos[i] += impulse` 로 써넣어 노드를 0.3-0.5 m 가라앉힘. 슬라임의 surface-detection budget (`slimeRadius + surfaceCheckDistance × attachedCheckMultiplier = 0.55 m`) 이 그 dip 을 못 따라가 다음 프레임에 detach → 슬라임은 멈춰 있고 로프만 튀어나가 "트램폴린이 같이 내려갔다 같이 올라온다" 감각이 안 남. (1) **`IRopePlatform.ConsumeRiderCarryDelta(worldContact)` 추가** — V3-only positional coupling. v1/v2 는 `Vector2.zero` stub. (2) **`RopeV3` (sibling class)** — V2 의 시뮬 코어 (Verlet/Jakobsen/elastic/EdgeCollider sync/Catmull-Rom) 를 그대로 복사하되 `impactGain`/`riderForceMul` 제거 + `Rider Spring (V3)` 인스펙터 헤더 신설. 라이더 무게는 Hookean spring — 매 substep `accel = k × (targetDepth - currentDepth) - 2ζ√k × vDown` 을 ropeDownDir 로 적용. attachPos 는 `ApplyRiderImpact` 에서 snapshot, 이후 spring 의 reference frame. activeImpactDepth 는 `dot(impactVel, ropeDownDir) × impactCompressionFromVelocity` 로 1-shot 누적, `√k × ζ` 비율로 지수 감쇠. (3) **Carry channel** — `FixedUpdate` 가 substep 직전에 `prevContactSampled = SamplePosAt(seg, t)` 로 baseline 잡고 모든 substep 후 delta 누적, [SlimeController.cs:~675](../SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.cs#L675) 의 새 블록이 `rb.position += currentRope.ConsumeRiderCarryDelta(rb.position)` 로 매 FU 적용. Multi probe mode 의 teleport branch 가 `rb.linearVelocity = Vector2.zero` 처리하므로 carry 가 유일한 tracking 채널 — `ropeVel` velocity inheritance 와 이중 적용 없음 (단 V3 GameObject 에 `SurfaceProbeModeOverride` (mode=Multi) 자동 부착으로 강제). (4) **Launch 보너스: V2 그대로** — `timingBonusCurve(proj) × chargeMultiplierCurve(chargeRatio)` 식 unchanged. V3 의 변화는 식이 아니라 *느낌* — V2 는 슬라임이 정지한 채 로프만 움직였지만 V3 는 슬라임이 dip-rebound 사이클을 로프와 함께 도므로 "트램폴린에서 발 굴러 점프" 같은 직관적 타이밍 감각. 수동 (charge 없는) rebound 자동 점프는 미구현 — Attached 유지하며 사이클 무한 반복. (5) **테스트 씬** — `SlimeJumping/Mechanism/Setup Rope Test V3 (Trampoline)` 메뉴, 3개 프리셋: Soft (얕은 dip / 빠른 안정화), Trampoline (default — 깊은 dip + 활발한 rebound), HeavyHammock (깊은 정상 sag + 느린 rebound). 기존 V1/V2 메뉴 무수정 — V1/V2 stub 1줄 추가뿐.

(1) **`IRopePlatform` 인터페이스** — v1 Rope 와 v2 RopeV2 가 공유. SlimeController 의 `currentRope` 필드를 인터페이스로 변경, `GetComponentInParent<IRopePlatform>()` 로 폴리모픽 attach. v1/v2 분기 코드 0. 새 멤버 `GetLaunchBonus(launchDir, worldContact, chargeRatio)` 가 모든 attach/inheritance/launch 경로의 단일 진입점. v1 의 `GetLaunchBonus` 는 기존 sag 공식을 그대로 wrapping (chargeRatio 무시), v2 는 두-곡선 공식 평가. 두 구현 모두 `[0, MaxReboundSpeed]` 로 internally clamp. (2) **RopeV2 = sibling class** — Rope.cs (692 LoC) 가 monolithic 이고 virtual 멤버 0, partial 아님. 베이스 클래스 추출은 v1 코드를 건드리는 scope 폭주 → 정공법인 sibling 으로 진행. RopeV2 는 v1 의 시뮬 루틴 (Verlet 적분 / Jakobsen / elasticFactor / Laplacian 평활화 / EdgeCollider sync / Catmull-Rom LineRenderer / Preview Max Sag 컨텍스트 메뉴) 을 동일 코드로 복사. 차이는 `Header("Rebound — Timing Bonus")` 블록뿐. (3) **두 AnimationCurve 필드** — `timingBonusCurve` (x = `max(0, ropeVelAtAttach · launchDir)` m/s, y = 보너스 speed m/s, default `Linear(0,0)→(20,20)`) × `chargeMultiplierCurve` (x = `aimOffset.magnitude / chargeRadius` 0..1, y = scalar, default flat 1.0). 곱한 후 `maxReboundSpeed` 캡. 라이브 핫리로드 가능 (AnimationCurve 는 매 발사마다 evaluate). (4) **컨트롤러 변경** — `SlimeController.Launch.cs:117-128` 의 sag block 을 `currentRope.GetLaunchBonus(launchDir, rb.position, ratio)` 한 줄로 교체. `ratio` 는 line 91 에서 이미 계산되어 scope 안. `UpdateRopeReference` 가 `Rope` 대신 `IRopePlatform` 으로 캐시 + `ReferenceEquals` 비교 (인터페이스라 Unity null check 우회). 기존 v1 회로 (raycast → attach → ReportRiderContact → SampleVelocityAt 인계 → Launch 보너스) behavior-preserving. (5) **테스트 씬** — `SlimeJumping/Mechanism/Setup Rope Test V2 (Timing)` 메뉴가 RubberRebound 시뮬 베이스 + 세 가지 곡선 프로필 (TimingOff / LinearTiming / ChargeGated) 로 V2 로프 셋업, 기존 V2 Rebound 씬의 height marker (+4/+6/+8/+10/+12) 재사용. v1 RubberRebound 씬은 그대로 남아 v1↔v2 비교 가능. (6) **타이밍 감각의 출처** — 명시적 phase tracker 없음. `SpringyBranchPlatform` 처럼 순수 물리: 처지는 동안 ropeVel↓ → proj~0, 반동 시작하면 ropeVel↑ → proj 피크. 곡선은 그 proj 를 보너스로 매핑하는 응답 함수. SpringyBranch 의 angular momentum 직접 transfer 와 동치, 단 디자이너가 응답 모양을 자유 작성.
