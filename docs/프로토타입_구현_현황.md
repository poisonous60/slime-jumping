- **Unity 6000.3.11f1**, URP.
- 단일 `CircleCollider2D` 기반 2.5D 플랫포머. 소프트바디 없음.
- `Rigidbody2D` + `gravityScale = 0` + 수동 velocity 관리.
- ScriptableObject 기반 튜닝 (`SlimeSettings`, `SlimeVisualSettings`, `SurfaceMaterial`).
- 슬라임 비주얼: **3D 메쉬 기반** (`Slime/SlimeVisual3d`). 2D 스프라이트 구성은 아카이브(비활성).

## 최근 변경 하이라이트 (2026-04)

- **2026-07-26**: **corpse를 rider가 아니라 external load로 재배선 + 2초 자동 재생성** — "corpse가 얹힌 대나무를 밟으면 잘 안 휜다"의 근본 원인: `BambooPlatformV3`의 **라이더 슬롯이 1개**(`firstAttach = !riderAttached`)인데 corpse가 매 FU `ApplyRiderInfluence`로 그 슬롯을 영구 점유 → 슬라임이 착지해도 `firstAttach=false`라 **랜딩킥 0**(무게 토크만), 게다가 차징 freeze가 읽는 arm·질량도 corpse 것, 접촉 끊길 때마다 `RemoveRider`가 리랜드 락아웃을 슬라임에 등록(이번 세션 두 버그의 뿌리). 수정: 신규 stock API `ApplyExternalLoad(worldPoint, mass)` — 무게 토크는 기존 `pendingRiderTorque` **같은 누적기**에 가산(토크는 가산이라 슬라임 무게와 자연 합산), 관성은 별도 `pendingExternalInertia`로 모아 `ComputeSpringCoeffs`의 `ITotal`에 더하고 `ComputeMotion`에서 함께 리셋. **라이더 슬롯은 손대지 않는다.** corpse는 이제 매 FU `ApplyExternalLoad(접촉점, bambooMass + ridingSlimeMass/N)` + 신규 접촉 프레임에만 `ApplyExternalImpact(접촉점, rb.linearVelocity, bambooMass)`(장대가 쿵 떨어지는 슬램 = 옛 firstAttach 킥 대체). **해제 코드 전량 삭제**(`ReleaseStalk`/`influencedStalks`/`influencedOffSeconds`/`OnDestroy` 루프/`stalkContactGraceSeconds` 노브) — 안 부르면 그게 해제라 플리커가 무해해졌고 반창고가 필요 없어짐. codex 리뷰 반영 2건: (1) 관성 커밋 시점 — `pendingExternalInertia`를 `ComputeMotion` 끝에서 0으로 지우면 `OnAfterMotion`의 `CheckSpringThrow`/`ThrowCapable`이 "장대 무게는 든 `lastWeightTorque` + 장대 없는 강성"으로 평형을 계산하는 불일치가 생겨, `externalInertia`로 프레임 시작에 커밋하고 프레임 내내 유지; (2) 신규 접촉 킥이 다중 받침 플리커로 재발화(임펄스는 corpse에 반작용이 없어 반복 = 공짜 에너지) → 스탈크별 `landingDebounce` 동안 "최근 접촉" 유지 + 킥 속도를 `rb.linearVelocity` → `rb.GetPointVelocity(접촉점)`으로 교체(다른 받침에서 흔들리는 장대는 중심은 움직여도 접촉점은 거의 정지). 같이 추가: **`respawnDelaySeconds`(2)** — 붕괴 2초 뒤 `ice.RequestRegen()`(존 이탈 경로와 같은 멱등 호출, 먼저 오는 쪽이 이김)로 얼음·대나무 동시 복구. **`crackHealSeconds`(2)** — 스탈크 접촉이 2초간 없으면 부분 금이 회복(카운트 0 + 얼음 Idle이면 `_CrackProgress` 0). 판정에는 랜딩 디바운스가 쓰던 `offStalkSeconds`를 그대로 재사용하고, 리셋 본문은 존 이탈 경로와 공유(`ResetCracks`). 리셋 후 `offStalkSeconds = MaxValue`라 다음 접촉이 디바운스에 먹히지 않고, `landingCount == 0` 가드가 매 프레임 재발화를 막는다.
- **2026-07-26**: **쓰러진 대나무 → 받침 대나무 하중/충격 전달** (`ridingSlimeMass` 1) — corpse가 살아있는 대나무 위에 다리처럼 걸쳐 있을 때, 그 위의 슬라임이 받침에 아무 영향도 못 주던 문제. 받침은 Kinematic + 자체 ODE라 Box2D 접촉으로는 힘이 안 들어가고, 유일한 입력인 `ApplyRiderInfluence`는 **랜딩킥이 `firstAttach` 엣지에서만** 발화하는데 corpse가 라이더 슬롯을 계속 점유하므로 어떤 충격도 통과 못 함. 그래서 corpse가 3채널을 명시 전달: (1) **무게** — 슬라임 탑승 중이면 매 FU coupling mass에 `ridingSlimeMass` 가산, (2) **착지 충격** — 슬라임이 corpse에 부착되는 엣지에서 `ApplyExternalImpact(접촉점, 착지 충격 속도, mass)`. 엣지는 `landingDebounceSeconds`(얼음 착지 집계와 같은 노브)로 디바운스 — 겹친 캡슐 위 어태치 플리커가 같은 착지를 반복 주입하는 것 차단(codex 지적). 속도는 `slime.ImpactNormalSpeed/ImpactTangentSpeed`(SlimeController가 착지 순간 캡처)로 재구성 — PlatformMotor(-100)가 SlimeController(0)보다 먼저 돌아 `slime.Velocity`는 이미 0이고, 직전 프레임 값을 캐싱하면 한 틱 낡은 속도가 됨, (3) **발사 반동** — `OnSlimeLaunched`에서 `-vel`로 같은 경로. 받침이 여럿이면 **접촉 수로 분할**(다리 양단이 절반씩). 신규 stock API `BambooPlatformV3.ApplyExternalImpact` = 라이더 계약 밖 외부 충격 입력: 착지 임펄스 수학(`impactSoftCap` 로그 압축 → `dOmega=(r×J)/I` → `LandingImpulseRampTime` 램프)을 private `InjectImpactImpulse`로 추출해 착지 분기와 공유하고, **팁 보너스(`landingImpulseGain`)는 안 태운다**(그건 슬라임이 그 스탈크 스위트스폿을 맞힌 보상인데 여기 접촉점은 장대가 얹힌 자리). 접촉점 표면 속도는 여전히 차감 → 반복 착지로 공짜 에너지 안 생김. corpse가 땅에 Static 안착하면 접촉 스탈크가 없어 전 채널 no-op.
- **2026-07-26**: **Bamboo V3 밑면 매달림 = throw 가능성 판정** (`underhangClingTime` 0.2초) — 슬라임이 대나무 밑면에 붙으면 영원히 매달리던 버그. 원인은 `BambooV3_Surface`의 `overrideCeilingAngle=1, ceilingAngle/ceilingReattachAngle=180`: 임계값이 `cos(180°) = -1`이라 [Attached.cs](../SlimeJumping_v2/Assets/Scripts/Controller/SlimeController.Attached.cs)의 천장 detach 조건 `dot(n,up) < thr`가 **수학적으로 성립 불가**(다른 표면은 글로벌 150°/thr -0.866이라 뒤집히면 떨어짐). 이 override 자체는 의도된 것 — 없으면 밑에서 때린 슬라임이 부착조차 안 돼(reattach 임계 -0.766) 스프링 로드→throw 반동이 통째로 사라진다. **1차 시도(고정 0.7초 타이머)는 임시방편이라 폐기**, 대신 `BambooPlatformV3.ThrowCapable`이 `CheckSpringThrow`의 게이트 2개(peak bend ≥ `ejectBendDeg`, 사출 속도 ≥ `MinEjectSpeed`)를 현재 스프링 상태로 예측한다: 감쇠 무시 SHO 진폭 `A = √((θ−θeq)² + (ω_total/ωn)²)`, `ω_total = angularVel + rampOmegaRemainingDeg`(착지 임펄스가 0.1초 램프로 들어가므로 큐 잔량을 안 더하면 강타를 착지 직후 "못 던짐"으로 오판), 0 기준 게이트에 맞춰 `|θeq| + A` 비교, 사출 속도는 half-return 발화점 기준 `A_rad·ωn·(√3/2)·|arm|`. **던질 수 있으면 타이머가 안 돌아 throw가 끝낼 때까지 매달리고, 못 던지면 0.2초 후 미끄러진다.** 링다운하면 A가 줄어 판정이 저절로 뒤집히므로 별도 만료 규칙이 없다. 해제는 throw와 같은 `ForceAirborneWithVelocity` + **장대 전체 콜라이더** `relandLockoutTime` 재부착 가드(한 세그먼트만 풀면 옆 캡슐이 받음). 차징 중엔 타이머 리셋(차지는 반드시 발사로 종료). 규칙은 중첩 struct `BambooPlatformV3.UnderhangSlip`이라, 스프링이 없는 쓰러진 장대(`FallingBambooCorpseMotor`, 스폰 시 `bamboo.Settings` 주입)가 `throwCapable: false`로 같은 코드를 쓴다.
