# 플랫폼 씬 배치 가이드

Unity Editor에서 플랫폼을 직접 Scene에 추가하는 방법.

---

## 현재 구조

- 모든 플랫폼은 Hierarchy의 **GrayBox** 오브젝트 하위에 위치. 현재 GrayBox 여러개임.
- Prefab 없음 — 전부 Scene에 직접 배치된 GameObject
- **2D 물리** 사용 (Rigidbody2D, BoxCollider2D 등)
- 모든 플랫폼은 **Layer 7** 사용

---

## 정적 플랫폼 (사각형)

기본 구성 컴포넌트:

| 컴포넌트 | 역할 |
|---|---|
| Transform | 위치, 회전, 크기 (scale.x = 너비, scale.y = 두께) |
| MeshFilter | Unity 내장 Cube 메시 |
| MeshRenderer | 렌더링 (회색 머티리얼) |
| BoxCollider2D | 2D 충돌 |

### 만드는 순서

1. Hierarchy에서 **GrayBox** 우클릭 → **3D Object → Cube**
2. Inspector에서 Layer를 **7**로 변경
3. Transform 조정:
   - Position: 원하는 위치 (Z = 0)
   - Scale: 예) `(3, 0.3, 1)` → 너비 3, 두께 0.3
4. **기본 BoxCollider (3D) 삭제** — 이 프로젝트는 2D 물리 사용
5. **Add Component → BoxCollider2D** 추가

---

## 원형 플랫폼

1. GrayBox 우클릭 → **3D Object → Sphere** (또는 Cylinder)
2. Layer를 **7**로 변경
3. Transform 조정:
   - Position: 원하는 위치 (Z = 0)
   - Scale: 예) `(1, 1, 1)` → 반지름 0.5짜리 구
4. **기본 3D 콜라이더 삭제** (Sphere Collider 또는 Capsule Collider)
5. **Add Component → CircleCollider2D** 추가
6. CircleCollider2D의 Radius를 비주얼에 맞게 조정

> 납작한 원반 형태: Cylinder 사용 → X축 90도 회전 → CircleCollider2D 사용

---

## 움직이는 플랫폼

정적 플랫폼 만든 후 추가 작업:

1. **Add Component** → 원하는 스크립트 추가
2. `PlatformMotor` 기반 스크립트는 Rigidbody2D를 자동 추가함 (`[RequireComponent]`)
3. Inspector에서 파라미터 설정

### 사용 가능한 모터 스크립트

| 스크립트 | 동작 |
|---|---|
| `RotatingPlatform` | 회전 (연속 또는 왕복) |
| `WaypointPlatform` | 경유점 이동 |
| `PendulumPlatform` | 진자 운동 |
| `TiltPlatform` | 플레이어 무게로 기울어짐 (스프링 = 평형 각도로 수렴) |
| `TiltPlatformV2` | 시소 — 무게가 토크, 각도가 그걸 적분. 관성으로 밟은 쪽으로 계속 기울어짐 |
| `SpringyBranchPlatform` | 한쪽 끝 고정된 탄력 가지 (착지/펌핑으로 휘었다가 스프링 복원) |

### RotatingPlatform

한 방향으로 계속 회전하거나, oscillate 켜면 지정 범위 안에서 왕복 회전.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| axis | Z | 회전축. Z = Rigidbody2D 회전 (콜라이더 포함). X/Y = visualRoot만 회전 |
| visualRoot | — | X/Y 축일 때 돌릴 Transform. 2D 물리에 X/Y 회전이 없으므로 콜라이더는 고정 |
| degreesPerSecond | 45 | 회전 속도 (°/s). oscillate 모드에서는 왕복 주기에 영향 |
| oscillate | false | true면 왕복 회전, false면 한 방향 연속 회전 |
| oscillateRange | 90 | oscillate 모드에서 ±범위 (°). sin파로 왕복 |

### WaypointPlatform

로컬 오프셋으로 지정한 경유점들을 순서대로 이동. Scene 뷰에서 cyan 기즈모로 경로 표시.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| localWaypoints | — | Vector2 배열. 플랫폼 시작 위치 기준 로컬 오프셋 (최소 2개) |
| timingMode | Speed | Speed=속도 기반(거리에 따라 소요시간 가변), Duration=구간별 시간 기반 |
| speed | 2 | (Speed 모드) 이동 속도 (units/s) |
| segmentDurations | — | (Duration 모드) 구간별 이동 시간(초) 배열. 인덱스 = 두 경유점 중 작은 쪽 → ping-pong은 양방향 동일 값 재사용. 필요 개수 = (경유점-1) |
| defaultSegmentDuration | 1 | (Duration 모드) segmentDurations 비었거나 짧을 때 / 0일 때 폴백 (초) |
| waitTime | 0.5 | 경유점 도착 시 대기 시간 (초) |
| loop | true | true=마지막→처음 순환, false=끝에서 방향 반전 (ping-pong) |
| startIndex | 0 | 출발 경유점 인덱스. ping-pong에서 마지막을 고르면 역방향으로 시작 |
| easeCurve | Linear | 구간별 이동 보간 커브 (AnimationCurve) |

### PendulumPlatform

피벗 점에서 줄로 매달린 진자 운동. Scene 뷰에서 yellow 기즈모로 피벗~플랫폼 연결선 표시.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| localPivot | (0, 3) | 피벗 위치 (플랫폼 기준 로컬 오프셋) |
| ropeLength | 3 | 줄 길이. 길수록 진동 주기 느림 |
| gravity | 10 | 진자 전용 중력. 클수록 빠르게 흔들림 |
| damping | 0.02 | 각속도 감쇠. 0이면 영원히 흔들림, 클수록 빨리 멈춤 |
| startAngleDeg | 30 | 시작 각도 (°). 클수록 초기 진폭 큼 |
| swayRatio | 0.3 | 플랫폼 자체 회전 비율. 0=수평 유지, 1=진자 각도 그대로 |
| maxTiltAngle | 15 | 라이더 무게로 기울어지는 최대 각도 (°) |
| tiltStiffness | 20 | 기울기 복원 스프링 강도 |
| tiltDamping | 5 | 기울기 진동 감쇠 |

### TiltPlatform

플레이어가 올라타면 위치에 따라 시소처럼 기울어짐. 내려오면 원래로 복원.

**콜라이더**: 자식(자신 포함) 아무 `Collider2D` 하나면 됨 — Box / Polygon 무관. 그 콜라이더의 월드 AABB x 반폭이 시소 팔 길이. 메시 베이크 콜라이더(`MeshCollider2DWrapper` 생성 `PolygonCollider2D`) 에도 그대로 붙음.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| maxTiltAngle | 15 | 최대 기울기 (°) |
| stiffness | 20 | 복원 스프링 강도. 클수록 빠르게 기울어짐 |
| tiltDamping | 5 | 진동 감쇠. 클수록 흔들림 빨리 멈춤 |

### TiltPlatformV2

진짜 시소. v1 은 라이더 위치에 비례한 **목표 각도**로 수렴하는 스프링이라, 라이더가 중앙을 지나는 순간 목표가 0 이 되어 즉시 복원한다 — 반대쪽 끝까지 건너갈 시간이 없다. v2 는 목표 각도를 없애고 **토크를 적분**한다: 라이더 팔 길이 → 각가속도 → 각속도 → 각도. 각속도가 상태로 남으니 라이더가 반대쪽으로 이동하는 동안에도 처음 밟은 쪽으로 계속 기울고, 토크가 뒤집혀도 그 각속도를 먼저 죽여야 방향이 바뀐다.

`leverLag` 가 여기에 게임플레이용 지연을 하나 더 얹는다 — 유효 팔 길이가 라이더 실제 위치를 지수 추종하므로, 반대쪽 끝을 밟아도 토크가 즉시 뒤집히지 않는다.

**콜라이더**: v1 과 동일 (자식 아무 `Collider2D` 의 월드 AABB x 반폭 = 시소 팔 길이).

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| maxTiltAngle | 15 | 최대 기울기 (°). 도달하면 각속도 0 (하드 스톱이 스윙을 먹음) |
| tiltAccel | 45 | 라이더가 끝단·질량 1 일 때 각가속도 (°/s²). **작을수록** 반대쪽 도착 시점에도 아직 내려가는 중 |
| angularDamping | 1.5 | 각속도 초당 감쇠. 0 = 무마찰, 계속 흔들림 |
| centerDeadZone | 0.15 | 이 팔 비율 이내는 피벗 위로 취급 (토크 0) |
| leverLag | 0.35 | 유효 팔 길이가 라이더 실제 위치를 따라잡는 시간 (초). 클수록 건너갈 시간 벌어줌 |
| levelReturnStiffness | 0 | 수평 복원 스프링. **`(1-|lever|)` 로 페이드인** — 라이더 이탈 프레임에 계단으로 켜지지 않음. 0 = 라이더가 떠난 각도 유지 (진짜 시소) |

**튜닝 순서**: `tiltAccel` 로 바닥까지 걸리는 시간 → `leverLag` 로 반대쪽 밟았을 때 뒤집히기까지의 유예 → `angularDamping` 은 마지막. 기본값 조합에서 끝단 밟고 바닥까지 약 0.9s, 반대쪽 끝 밟고 완전히 뒤집히기까지 약 1.2s.

**"점프하면 바로 원래대로 돌아온다"**: 원인 둘.
1. `levelReturnStiffness` 가 0 이 아니고 라이더 유무로 껐다 켜지면, detach 프레임에 `-θ·k` 가 계단으로 들어온다. θ=15°·k=6 이면 +90 °/s² 로 라이더 토크(−45)의 2배 → 첫 프레임에 반전. 그래서 페이드인 + 기본값 0.
2. `|θ| > maxTiltAngle` 하드 스톱이 `ω=0` 으로 만든다. 슬라임이 끝단에서 차징하는 동안 판자가 이미 바닥에 닿으면 **남길 각속도 자체가 없다.** 발사 후 계속 도는 게 보이려면 차징이 끝나기 전에 바닥에 닿지 말아야 함 → `tiltAccel` 을 낮추거나 `maxTiltAngle` 을 올린다. 잔여 스윙이 얼마나 오래 가는지는 `angularDamping` (1.5 = 반감기 0.46s, 0.3 = 2.3s).

### SpringyBranchPlatform

한쪽 끝(피벗)이 고정된 탄력 가지. 라이더 슬램·몸흔들기로 휘고 스프링 복원. 발사 시 `AngularVelocity × arm` 이 발사 속도에 자동 합산 → 타이밍 퍼즐 메커닉. 메뉴 `SlimeJumping/Setup SpringyBranch Test` 로 5종 프리셋 씬 생성.

**계층** (수동 배치 시): `BranchPivot`(월드 고정, Rigidbody2D Kinematic + `SpringyBranchPlatform`) → 자식 `BranchBody`(로컬 +halfLength 오프셋, BoxCollider2D) + `Bone_0..N`(피벗 직접 자식, 비주얼 휨 체인). 피벗은 제자리에서 회전만 해야 함 (속도 이중계산 방지).

**방향 설정**: BranchBody 는 **항상 피벗의 로컬 +X 방향** 으로 둠 (`localPosition = (+halfLength, 0, 0)`, `localRotation = identity`). 가지가 향할 방향은 **BranchPivot 의 transform rotation** 으로 조절 (씬 뷰에서 그냥 피벗 오브젝트를 회전). Awake 에서 `rb.rotation` 을 `baseRotation` 으로 캡처해 스프링이 그 방향으로 복원함. Scene 뷰 cyan 기즈모 선은 BranchBody 의 실제 위치를 가리킴 — 기즈모가 Body 와 일치해야 정상.

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| branchLength | 4 | 피벗→팁 거리(m). 지레 팔, 런치 부스트에 직접 영향 |
| naturalFreqHz | 1.0 | 초당 진동 횟수. **타이밍 퍼즐 난이도의 핵심 노브**. 높을수록 창 좁아짐 |
| dampingRatio | 0.2 | 스프링-댐퍼 자연 감쇠 비율. 0=영구 진동, 1=1회에 정착 |
| maxDeflectionDeg | 60 | 하드 각도 클램프 (안전망) |
| clampRestitution | 0.3 | 각도 한계 부딪힐 때 반사 계수 |
| riderPumpGain | 1.0 | 라이더 Δp→각속도 변환 배율. 슬램/몸흔들기 공통. 높을수록 펌핑 쉬움 |
| chargePumpScale | 1.0 | 차지 중 `riderPumpGain` 추가 배율. 0=차지 중 차단, >1=보상. (현재 실효성 낮음) |
| riderTorqueScale | 1.0 | 라이더 중력 토크 배율. 정적 처짐 정도만 조절 |
| passiveDecayRate | 0.0 | 라이더 없을 때 각속도 지수 감쇠(1/s). 주파수와 독립 |
| riderDecayRate | 0.0 | 라이더 있을 때 각속도 지수 감쇠(1/s) |
| maxTipSpeed | 18 | 팁 선속도(m/s) 하드 캡. **런치 보너스 절대 천장** |
| slamMinDownSpeed | 3 | 재착지 펌핑 방지 하한 속도 (m/s) |
| slamReattachLockout | 0.15 | 재착지 슬램 억제 시간 (s) |

**튜닝 순서 추천:** ① `maxTipSpeed` 로 최대 점프 높이 결정 → ② `naturalFreqHz` 로 타이밍 창 난이도 결정 → ③ `riderPumpGain` 으로 천장 도달 용이성 → ④ `dampingRatio` 로 진동 지속시간.

## 무너지는 플랫폼 (Crumbling Platform)

슬라임이 부착하면 일정 시간 뒤 충돌 판정이 사라지는 플랫폼. 비주얼을 자식 오브젝트로 분리하여 셰이크 연출이 PlatformMotor와 충돌하지 않음.

### 구조

```
CrumblingPlatform (부모 GameObject)
├─ [Layer 7]
├─ BoxCollider2D (또는 CircleCollider2D)
├─ CrumblingPlatform.cs
├─ (선택) PlatformMotor 계열 스크립트
└─ Visual (자식 GameObject)
   ├─ MeshFilter (Cube 등)
   └─ MeshRenderer
```

### 만드는 순서

1. GrayBox 우클릭 → **Create Empty** → 이름: 원하는 이름 (예: `CrumblePlatform_01`)
2. Layer를 **7**로 변경
3. Transform → Position 조정 (Z = 0)
4. **Add Component → BoxCollider2D** → Size를 원하는 플랫폼 크기로 설정
5. **Add Component → CrumblingPlatform**
6. 자식 오브젝트 만들기:
   - 부모 우클릭 → **3D Object → Cube**
   - 이름을 **Visual**로 변경
   - 3D BoxCollider 삭제 (자식에 콜라이더 불필요)
   - Scale로 비주얼 크기를 부모 BoxCollider2D.Size에 맞춤
7. CrumblingPlatform Inspector에서:
   - `Visual Root` → 자식 Visual 드래그
   - `Visual Renderer` → 자식의 MeshRenderer 드래그
   - 파라미터 조정

> **Tip**: Reset 버튼 (Inspector 컴포넌트 ⋮ → Reset)을 누르면 "Visual"이라는 이름의 자식을 자동으로 찾아서 할당.

### 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| Trigger Delay | 0.5 | 부착 후 무너지기 시작까지 (초) |
| Crumble Duration | 0.2 | 무너지는 연출 시간 (초) |
| Respawn Time | 3.0 | 사라진 뒤 복구까지 (초). **음수면 영구 소멸** |
| Use Angle Limit | false | true면 아래 각도 범위 내 부착에서만 트리거 |
| Min Surface Angle | 0 | 트리거 최소 각도 (0° = 바닥) |
| Max Surface Angle | 180 | 트리거 최대 각도 (180° = 천장) |
| Blocking Layers | Everything | 리스폰 시 겹침 체크에 사용할 레이어 |

### 레벨 디자인 예시

| 용도 | 설정 |
|---|---|
| 기본 (어디 붙든 무너짐) | Use Angle Limit = false |
| 바닥만 무너짐 | Use Angle Limit = true, Min = 0, Max = 30 |
| 벽 전용 트랩 | Use Angle Limit = true, Min = 60, Max = 120 |
| 천장 전용 트랩 | Use Angle Limit = true, Min = 150, Max = 180 |
| 한 번만 무너짐 | Respawn Time = -1 |
| 즉시 무너짐 | Trigger Delay = 0, Crumble Duration = 0 |

### 움직이는 플랫폼과 조합

PlatformMotor 계열 스크립트 (WaypointPlatform, RotatingPlatform 등)와 같이 사용 가능. 부모에 모터 스크립트를 추가하면 됨. 셰이크는 자식 Visual의 `localPosition`만 흔들기 때문에 모터의 `MovePosition`과 충돌하지 않음.

### Prefab으로 저장

구조가 있어서 Prefab으로 저장해두면 재사용 편리.

## 밀어서 여는 문 (PushDoor)

살롱 도어 스타일. 슬라임이 접촉하면 콜라이더가 X축으로 밀리고, 분리된 3D 비주얼이 힌지 기준으로 회전. 충분히 밀면 콜라이더 비활성 → 통과 가능 → 스프링 복원.

### 구조

```
PushDoor (부모 GameObject)
├─ [Layer 7]
├─ Rigidbody2D (Kinematic, 자동 추가)
├─ BoxCollider2D
├─ PushDoor.cs
└─ VisualPivot (자식, 빈 GameObject)
    └─ Mesh (자식, 3D Cube — Z 방향으로 문판 표현)
```

### 만드는 순서

1. GrayBox 우클릭 → **Create Empty** → 이름: `PushDoor_01`
2. Layer를 **7**로 변경
3. Transform 조정:
   - Position: 문이 서 있을 위치 (Y = 문 높이 절반 위)
   - Z: 자유 (doorDepth 자동 계산에 반영됨)
4. **Add Component → BoxCollider2D** → Size: `(0.15, 문높이)` (얇은 단면)
5. **Add Component → PushDoor**
6. 자식 만들기 — VisualPivot:
   - 부모 우클릭 → **Create Empty** → 이름: `VisualPivot`
   - Position: `(0, 0, 0)` — PushDoor.cs가 hingeOffset으로 런타임에 배치
7. VisualPivot 자식으로 Mesh:
   - VisualPivot 우클릭 → **3D Object → Cube** → 이름: `Mesh`
   - **3D BoxCollider 삭제**
   - Scale: `(0.15, 문높이, 문깊이)` — X=두께, Y=높이, Z=깊이(문 폭)
   - Position: `(0, 0, -문깊이*0.5)` — 힌지에서 카메라 쪽으로 뻗어나감
8. PushDoor Inspector에서:
   - `Visual Transform` → VisualPivot 드래그
   - `Hinge Offset` → `(0, 0, 문깊이)` — 힌지를 문 뒤쪽(Z+)에 배치
   - 나머지 파라미터 조정

### 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| Push Accel | 15 | 접촉 시 문이 밀리는 가속도 |
| Push Max Speed | 3 | 밀림 최대 속도 |
| Return Stiffness | 10 | 닫히는 스프링 강도. 클수록 빠르게 닫힘 |
| Return Damping | 3 | 닫힘 진동 억제. 클수록 흔들림 빨리 멈춤 |
| Open Angle Deg | 60 | 이 각도 이상 밀리면 콜라이더 비활성 (통과 가능) |
| One Way | false | 한 방향만 밀림 |
| Hinge Offset | (0,0,2) | 힌지 위치 (로컬 오프셋). Z가 클수록 문이 깊음 |
| Rotation Axis | (0,1,0) | 비주얼 회전축. Y=좌우 살롱도어, X=위아래 차고문 |
| Min Open Time | 1 | 콜라이더 비활성 최소 유지 시간 (초) |

### 핵심 개념

- **doorDepth** = `transform.position.z + hingeOffset.z` (자동 계산). 문의 Z 위치를 바꾸면 자동 반영.
- **openThreshold** = `doorDepth × sin(openAngleDeg)` (자동 계산). 각도 설정만 하면 됨.
- **Push/Return 분리**: pushAccel은 열림만, returnStiffness/returnDamping은 닫힘만 결정. 서로 독립.
- **힌지 기즈모**: Scene 뷰에서 노란색 구로 힌지 위치 표시.

### 배치 팁

- **Z Scale은 항상 1** — 부모 Scale Z를 바꾸면 자식 메시가 이중 스케일됨. 문 깊이는 Mesh Scale Z로 조절.
- **Mesh 앞쪽 여유** — 메시가 Z=0까지 오면 슬라임과 겹쳐 보임. 메시 깊이를 hingeOffset.z보다 약간 짧게 해서 앞쪽 여유를 둠.
- **Hinge Offset 조정** — Inspector에서 값 바꾸면 실시간 반영. Mesh Position/Scale도 맞춰서 조정.

### 자동 생성

메뉴 **SlimeJumping → Setup PushDoor Test**로 테스트 씬 자동 생성 가능 (바닥 + 벽 + 문 + 접근 램프).

## 모래 볼륨 (DragZone)

점프킹 스타일 모래. 고체 콜라이더 없이 trigger volume만으로 동작. 어디서든 진입/탈출 가능, 안에서 차징 가능.

### 구조

```
SandVolume (GameObject)
├─ [Layer 8: DragVolume]
├─ BoxCollider2D (isTrigger = true)
└─ DragZone.cs
```

### 만드는 순서

1. GrayBox 우클릭 → **Create Empty** → 이름: `SandVolume_01`
2. **Layer를 8 (DragVolume)으로 변경**
3. Transform → Position 조정 (Z = 0)
4. **Add Component → BoxCollider2D** → Is Trigger 체크, Size를 원하는 크기로
5. **Add Component → DragZone**
6. Inspector에서 파라미터 조정

### 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| Entry Multiplier | 0.3 | 진입 시 속도에 곱하는 값 (0.3 = 30%로 감속) |
| Exit Multiplier | 3.33 | 탈출 시 속도에 곱하는 값 (하향 Y 제외) |
| Launch Multiplier | 0.3 | 모래 안 발사 시 속도에 곱하는 값. Exit와 조합되어 최종 속도 결정 |
| Drag Factor | 0.3 | 안에 있는 동안 매초 남는 속도 비율 (0.3 = 1초 후 30%) |
| Max Fall Speed | 5 | 안에서 낙하 속도 상한 (0 = 제한 없음) |
| Allow Charging | false | 체크하면 Airborne에서 볼륨 내 차징 가능 |

### 동작 시나리오

| 상황 | 동작 |
|---|---|
| 옆에서 진입 | 속도 × entryMultiplier, 안에서 dragFactor로 계속 감쇠 |
| 위에서 낙하 진입 | 속도 × entryMultiplier, maxFallSpeed cap 적용 |
| 아래에서 점프 진입 | 속도 × entryMultiplier, 상승 중 dragFactor로 감쇠 |
| 스페이스 홀드로 진입 | 즉시 볼륨 차징 시작 (allowCharging=true일 때) |
| 안에서 차징 → 발사 | velocity × launchMultiplier, 탈출 시 × exitMultiplier |
| 탈출 (위/옆) | 속도 × exitMultiplier (운동량 복원) |
| 탈출 (아래) | 하향 Y는 복원 안 됨 (중력 가속 부스트 방지) |

### 주의사항

- **Layer 8 (DragVolume)** 필수 — Layer 7에 두면 SurfaceProbe가 감지
- **Physics2D Layer Matrix**에서 DragVolume(8) ↔ SlimeNode(6) collision 활성화 필요
- **DragZone끼리 겹치지 말 것** — 단일 참조 모델이라 겹치면 동작 미정의
- Launch Multiplier × Exit Multiplier = 모래 밖 최종 발사 속도 비율

### 튜닝 가이드

| 원하는 느낌 | 조정 |
|---|---|
| 더 끈적한 모래 | entryMultiplier ↓, dragFactor ↓ |
| 가볍게 저항만 | entryMultiplier ↑ (0.7~0.9), dragFactor ↑ (0.8~1.0) |
| 발사 후 강하게 튀어나감 | launchMultiplier ↓ + exitMultiplier ↑ |
| 발사력 손실 | launchMultiplier ↓, exitMultiplier 낮게 유지 |
| 느린 낙하 | maxFallSpeed ↓ (1~2) |

## 바람 구간 (WindZone2D)

특정 영역에 들어가면 슬라임이 일정 방향으로 밀리는 환경 기믹. 트리거 볼륨 방식으로 DragZone과 동일한 구조.

### 구조

```
WindZone_01 (GameObject)
├─ [Default 또는 전용 레이어 — Layer 7 금지]
├─ BoxCollider2D (isTrigger = true)
├─ WindZone2D.cs
├─ (선택) SpriteRenderer — 영역 시각화용 반투명 틴트
└─ WindParticles (자식 GameObject)
   └─ ParticleSystem — 바람 방향 시각 이펙트
```

### 만드는 순서

1. GrayBox 우클릭 → **Create Empty** → 이름: `WindZone_01`
2. **Layer는 Default 유지** (Layer 7에 두면 SurfaceProbe가 감지하여 슬라임이 부착함)
3. Transform → Position 조정 (Z = 0)
4. **Add Component → BoxCollider2D** → Is Trigger 체크, Size를 바람 영역 크기로
5. **Add Component → WindZone2D**
6. Inspector에서 `Wind Acceleration` 설정 (예: `(15, 0)` = 오른쪽 15 units/s²)
7. 파티클 추가:
   - 부모 우클릭 → **Effects → Particle System** → 이름: `WindParticles`
   - WindZone2D Inspector의 `Wind Particles` 필드에 드래그
   - **콜라이더 크기나 바람 방향을 바꾸면 파티클 형상이 자동 동기화됨** (OnValidate)
   - 수동 설정 필요한 항목: Start Size (0.05~0.15), Start Color (흰색 알파 30%), Renderer → Stretched Billboard (Length Scale 3), Noise 모듈 (Strength 0.4, Frequency 0.5)

### 파라미터

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| Wind Acceleration | (15, 0) | 바람 방향 + 세기 (Vector2, units/s²). X=수평, Y=수직 |
| Terminal Speed | 15 | 바람 방향 최대 속도. 이 속도에 가까워지면 가속 감쇠. 0 = 무제한 |
| Airborne Multiplier | 1 | 공중 상태 배율 |
| Attached Multiplier | 0.7 | 크롤/슬라이드 상태 배율 |
| Charging Multiplier | 0.2 | 차징 상태 배율 |
| Particle Speed | 8 | 파티클 이동 속도 (비주얼 전용, 물리와 무관) |
| Stripe Bounds | None | 줄무늬가 보이는 영역을 정하는 별도 BoxCollider2D. 비었으면 존 전체. 컴포넌트 우클릭 → **Create Stripe Bounds** 로 자식 생성 후 Edit Collider 핸들로 드래그. 비주얼만 좁힘 (밀어내는 범위는 존 콜라이더 그대로) |

### 동작 원리

- **Airborne**: `windDir × acceleration × airborneMultiplier × falloff × dt`를 velocity에 직접 가산
- **Attached/Charging**: 위 값을 surfaceTangent에 투영 후 가산 (법선 성분 제거 → 표면 스냅 지터 방지)
- **Terminal Speed falloff**: `falloff = clamp01(1 - dot(velocity, windDir) / terminalSpeed)` — 바람 방향 속도가 높을수록 추가 가속 감소

### 튜닝 가이드

| 원하는 느낌 | 조정 |
|---|---|
| 강한 돌풍 (공중 거의 저항 불가) | Wind Acceleration 40~60, Terminal Speed 20+ |
| 가벼운 산들바람 | Wind Acceleration 5~10, Terminal Speed 8 |
| 상승 기류 | Wind Acceleration = (0, 15) — 위쪽 방향 |
| 대각선 바람 | Wind Acceleration = (10, 5) — 방향 자유 |
| 크롤 중 강하게 밀림 | Attached Multiplier ↑ (0.8~1.0) |
| 차징 중 무시 | Charging Multiplier = 0 |

### 주의사항

- **Layer 7 금지** — Layer 7에 두면 슬라임이 바람 영역 콜라이더에 붙음
- **Physics2D Layer Matrix**에서 슬라임 레이어 ↔ 바람 레이어 교차가 체크되어 있어야 트리거 동작
- **Terminal Speed는 반드시 설정** — 0이면 긴 구간에서 무한 가속되어 카메라 튕김
- 여러 방향 바람은 같은 스크립트로 존을 여러 개 배치
- `WindParticle.mat`은 `SlimeJumping/WindStripe` 셰이더 — 스텐실로 픽셀당 1회만 블렌드해서 줄무늬가 겹쳐도 알파가 안 쌓인다. Start Color 알파/색은 자유롭게 조절해도 됨. 다른 셰이더(URP Particles 등)로 바꾸면 겹침 누적이 돌아온다

### 자동 생성

메뉴 **SlimeJumping → Setup Wind Zone Test**로 테스트 씬 자동 생성 가능 (바닥 + 벽 + 바람 영역 + 파티클 + 발판).

## 표면 속성 (Surface Material)

플랫폼에 얼음, 진흙 같은 표면 재질을 부여하는 시스템.

### 구조

```
SurfaceMaterial (ScriptableObject 에셋)
  └─ SurfaceTag (MonoBehaviour, 플랫폼에 부착)
       └─ SlimeController가 접촉 시 SurfaceModifiers 구조체로 읽어감
```

모든 속성값은 `AngleScaledValue` 타입 — 표면 각도(0°=바닥, 90°=벽)에 따라 값을 보간할 수 있음.

### 에셋 만들기

1. Project 창에서 우클릭 → **Create → SlimeJumping → Surface Material**
2. 생성된 에셋 이름 변경 (예: `Ice`, `Mud`)
3. Inspector에서 파라미터 설정

> 기존 에셋 위치: `Assets/Settings/SurfaceMaterials/` (Ice, Mud 이미 있음)

### 플랫폼에 적용하기

1. 플랫폼 GameObject 선택
2. **Add Component → SurfaceTag**
3. Material 필드에 SurfaceMaterial 에셋 드래그

SurfaceTag가 없는 플랫폼은 모든 값이 기본(1.0 또는 0.0)인 Default로 동작.

### 파라미터 레퍼런스

| 카테고리 | 파라미터 | 기본값 | 설명 |
|---|---|---|---|
| **Carrier** | carrierFriction | 1 | 움직이는 플랫폼에 얼마나 따라갈지. 0 = 빙판(안 따라감), 1 = 완전 따라감 |
| **Crawl** | crawlSpeedMultiplier | 1 | 크롤 속도 배율 |
| | crawlAccelerationMultiplier | 1 | 크롤 가속 배율 |
| | crawlDecelerationMultiplier | 1 | 크롤 감속 배율 |
| **Slide** | slideResistanceMultiplier | 1 | 슬라이드 저항. 0 = 얼음, 2+ = 진흙 |
| | slideGravityMultiplier | 1 | 슬라이드 중 중력 배율 |
| | slideRampUpTime | 0 | 착지 후 슬라이드가 0에서 풀까지 걸리는 시간(초). 0 = 즉시 |
| **Landing** | landingVelocityRetention | 0 | 착지 시 접선 속도 유지율. 0 = 즉시 멈춤, 1 = 전부 유지 |
| | stickDurationMultiplier | 1 | 붙기 지속시간 배율 |
| | impactRedirectRatio | 0 | 법선 충격을 접선 방향으로 전환하는 비율. 0.5 = 50% 전환 |
| **Wall Attach** | wallAttachSpeedDampen | 1 | 벽 부착 시 속도 감쇠. 1 = 감쇠 없음, 0.5 = 반감 |

### AngleScaledValue 사용법

각 파라미터는 4개의 필드를 가짐:

| 필드 | 의미 |
|---|---|
| baseValue | angleMin 이하에서의 값 |
| fullValue | angleMax 이상에서의 값 |
| angleMin | 보간 시작 각도 (°) |
| angleMax | 보간 끝 각도 (°) |

바닥과 벽에서 같은 값이면 `baseValue = fullValue`로 설정 (Constant).
각도에 따라 다르게 하려면 예: `baseValue=1, fullValue=0.5, angleMin=15, angleMax=80` → 15°까지 1.0, 80° 이상 0.5, 사이는 선형 보간.

### 기존 에셋 참고값

**Ice** — 미끄러지는 표면:
- `landingVelocityRetention`: 0.8 (착지해도 속도 80% 유지)
- `impactRedirectRatio`: 0.8 (충격을 접선 방향으로 전환)
- `slideGravityMultiplier`: 1.3 (경사면에서 더 빨리 미끄러짐)
- `stickDurationMultiplier`: 0 (붙지 않음)
- `wallAttachSpeedDampen`: 벽에서 0.5 (15°~80° 보간)
- `slideRampUpTime`: 벽에서 0.3초 딜레이 (15°~80° 보간)

**Mud** — 끈적이는 표면:
- `crawlSpeedMultiplier`: 0.5 (크롤 절반 속도)
- `crawlAccelerationMultiplier`: 0.5 (가속도 반감)
- `crawlDecelerationMultiplier`: 2 (감속 2배 — 빨리 멈춤)
- `slideResistanceMultiplier`: 3 (미끄러짐 강력 저항)
- `slideGravityMultiplier`: 0.5 (경사면에서 천천히 미끄러짐)

## 플랫폼 색 변경

현재 그레이박스 단계에서 플랫폼 색을 바꾸는 방법:

### 방법 1: 머티리얼 색 직접 변경 (공유)

같은 머티리얼을 쓰는 모든 오브젝트가 함께 바뀜.

1. 플랫폼 선택 → MeshRenderer의 Material 클릭하여 머티리얼 에셋 선택
2. 머티리얼 Inspector에서 **Base Map** (또는 **Base Color**) 색상 변경

### 방법 2: 새 머티리얼 만들어서 적용 (개별)

특정 플랫폼만 다른 색으로 하고 싶을 때.

1. Project 창 우클릭 → **Create → Material**
2. Shader가 `Universal Render Pipeline/Lit`인지 확인
3. **Base Map** 색상을 원하는 색으로 설정
4. 플랫폼의 MeshRenderer → Materials 슬롯에 드래그

> 표면 타입별로 머티리얼을 분리하면 시각적으로 구분 가능.
> 예: `Mat_Ice` (하늘색), `Mat_Mud` (갈색), `Mat_Default` (회색)
