1. 비주얼 문서를 다른 애니메이션까지 포함하게 바꿀까?

바꾸지 마. 지금 슬라임 비주얼 문서는 "슬라임 본체의 절차적 변형" 하나에 집중돼 있고, 그 집중도가 이 문서의 강점이야. 거기에 뱀 삼킴 애니메이션, 세탁기 회전, TV 치지직, 비 파티클, 번개 텔레그래프 같은 걸 다 넣으면 문서가 산만해지고 "변형 합성 공식" 같은 핵심 내용이 묻혀.
대신 두 가지로 나누는 게 깔끔해:
(a) 지금 문서는 그대로 두고 제목/서두만 미세 조정 — "슬라임 본체 비주얼"이라고 스코프 명시. 이러면 나중에 다른 비주얼 문서가 생겨도 충돌 안 함.
(b) 기능별 비주얼 노트는 기능_구현_가이드.md에 인라인으로 — 각 기능의 비주얼 요구사항은 그 기능에만 국한된 로컬 정보야. 뱀 삼킴 애니메이션은 뱀 구현할 때만 필요하고, 그때 가이드의 "27. 뱀" 섹션 옆에 있는 게 한참 떨어진 비주얼 문서에 있는 것보다 훨씬 찾기 쉬워. 한 줄~세 줄짜리 "비주얼 노트" 항목을 각 기능에 추가하는 정도면 충분.
(c) 진짜 cross-cutting한 비주얼 컨벤션만 별도 문서로 — 이건 나중에 필요해지면 만들면 돼. 예: 파티클 스타일 가이드(바람·물·불이 같은 게임에서 나온 것처럼 보이게), 셰이더 컨벤션, URP 머티리얼 규칙. 지금은 만들 만한 거리가 없음.


비주얼 부분을 Claude한테 조사시킬까?

시켜. 단, 한꺼번에 말고 시스템별로.
슬라임 물리 때 했던 워크플로우(여러 접근법 비교 → 근거 있는 선택 → 구현)가 비주얼에서도 똑같이 가치 있어. 특히 구현 방식이 여러 개 있는 시스템들이 그래:

Verlet 줄/덩쿨/전봇대 줄 — LineRenderer / mesh strip / sprite chain 중 뭐가 나은지, 슬라임 무게로 휘는 표현은 어떻게 할지
물 표면 렌더링 — sprite + shader / mesh vertex displacement / 파티클 라인. 슬라임이 들어갈 때 ripple은?
천 시뮬레이션 — Unity Cloth / mass-spring grid / shader-only fake
번개 텔레그래프 — 2D 플랫포머의 번개 연출 패턴 (Celeste, Hollow Knight 등 참고)
레인월드식 카메라 전환 — 이건 거의 확실히 조사가 필요. 구현 패턴이 게임마다 천차만별이고, 레인월드 자체가 특이한 구현이라 일반적인 Cinemachine으로 바로 안 됨
환경 파티클 톤 통일 — 바람/물/불/먼지가 같은 미술 언어로 보이게 하는 컨벤션

반대로 조사 안 해도 되는 것:

슬라임 sit/sleep 포즈 (그냥 sprite + 기존 변형 파이프라인 일시정지)
세탁기 회전, CCTV 머리 돌아가기 (단순 transform tween)
TV 치지직 (기존 셰이더/플러그인)
침대·벤치 같은 정적 인테리어 (그냥 스프라이트)
메모 UI (Canvas + TMP)

이런 건 굳이 비교 분석 안 해도 답이 정해져 있어서 조사 시키면 시간 낭비.
추천 흐름

지금 비주얼 문서는 "슬라임 본체" 스코프로 명확화 (한 줄 수정).
기능_구현_가이드.md의 30개 기능마다 "비주얼 노트" 한 줄 추가 — 어떤 비주얼 요소가 필요한지, 자체 구현인지 / 조사 필요인지 / 자명한지 표시.
위 6개 시스템(Verlet, 물 표면, 천, 번개, 레인월드 카메라, 환경 파티클 톤)은 해당 기능 구현 직전에 별도 대화에서 Claude한테 조사 시킴. 슬라임 물리 조사할 때처럼 "여러 접근법 → 비교 → 근거 있는 선택" 패턴으로.
조사 결과는 그 기능 구현 후 기능_구현_가이드.md의 해당 섹션에 결정 사항만 짧게 기록 (전체 조사 내용은 보관할 필요 없음).

이렇게 하면 비주얼 의사결정이 코드 의사결정과 같은 흐름으로 굴러가고, 문서가 비대해지지도 않아.
