# 기능 구현 가이드

각 기능을 구현할 때 어떤 카테고리에 속하는지, 어떤 인터페이스를 구현하고, 어떤 기존 코드를 참고해야 하는지 정리.

---

## 카테고리 요약

| 카테고리 | 인터페이스/베이스 | SlimeController 접점 | 대표 구현체 |
|----------|------------------|---------------------|------------|
| 위험 | `IHazardSource` | `ApplyHazardEffect()` → Stunned | `SpikeHazard.cs` |
| 플랫폼 효과 | `IPlatformEffect` | `OnSlimeAttach/Stay/Detach`, `ForceAirborneWithVelocity()`, `AddExternalVelocity()` | `JumpPad.cs`, `ConveyorBelt.cs` |
| 환경 존 | `EnvironmentalZone` (abstract) | `AddExternalVelocity()`, `MultiplyVelocity()`, `ClampFallSpeed()`, `PushBlockAttach()` | `WaterZone.cs` |
| 인터랙터블 | `IInteractable` | 없음 (InteractionDetector가 중계) | 미구현, 새로 작성 |
| 오버라이드 | `IExternalController` | `SetOverride()` / `ReleaseOverride()` | 미구현, 새로 작성 |
| 자체 시뮬 | 없음 | 없음 | 없음 |

## 1. 물 (Water)

**카테고리**: 환경 존
**상태**: 기본 구현 완료 (WaterZone). 수면 이동/차징은 미구현.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `WaterZone.cs` | `Scripts/Mechanisms/WaterZone.cs` | 부력, 드래그, 낙하 캡, blockAttach — 이미 구현됨 |
| `EnvironmentalZone.cs` | `Scripts/Mechanisms/EnvironmentalZone.cs` | 트리거 추적 베이스 |
| `DragZone.cs` | `Scripts/Mechanisms/DragZone.cs` | 볼륨 차징 패턴 (`allowCharging`, `EnterVolumeCharging`) |
| `SlimeController.cs` | `Scripts/Controller/SlimeController.cs` | `PushBlockAttach/PopBlockAttach`, `MultiplyVelocity`, `AddExternalVelocity` |
| `SlimeController.Airborne.cs` | `Scripts/Controller/SlimeController.Airborne.cs` | `blockAttachCount` 체크, air control 코드 |

**추가 구현 필요**:
- 수면 감지: 물 트리거 상단 경계에서 슬라임 위치 비교. 수면 근처일 때 AD 이동 + 차징 허용.
- 수면 차징: `DragZone.allowCharging` 패턴 참고. WaterZone에 수면 판정 추가 후 `EnterVolumeCharging` 호출하거나, 수면을 별도 solid collider로 구현.
- 가라앉았다 올라옴: 현재 부력으로 자연 구현됨. 부력 > 중력이면 자동 부상.

## 2. 가시 (Spike)

**카테고리**: 위험
**상태**: 구현 완료.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `SpikeHazard.cs` | `Scripts/Mechanisms/SpikeHazard.cs` | 완성된 구현. 3가지 방향 모드 |
| `HazardEffect.cs` | `Scripts/Interfaces/HazardEffect.cs` | 넉백/기절 데이터 구조체 |
| `SlimeController.cs` | `Scripts/Controller/SlimeController.cs` | `ApplyHazardEffect()` — 기절 진입 |
| `SlimeController.Stunned.cs` | `Scripts/Controller/SlimeController.Stunned.cs` | 기절 물리 |

**방향 모드 정리**:
- `useLocalUp = true`: 가시의 `transform.up` 방향. 가시 회전으로 방향 제어.
- `useLocalUp = false`, `redirectTarget = null`: 가시 중심 → 슬라임 방향 자동 계산.
- `useLocalUp = false`, `redirectTarget = Transform`: 슬라임 → 타겟 좌표 방향.

## 3. 원형톱날 (Saw Blade)

**카테고리**: 위험 + 특수 (통과 + 가속도)
**상태**: 미구현.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `SpikeHazard.cs` | `Scripts/Mechanisms/SpikeHazard.cs` | IHazardSource 패턴, OnTriggerEnter2D |
| `HazardEffect.cs` | `Scripts/Interfaces/HazardEffect.cs` | `DamageType.SawBlade` 이미 정의됨 |
| `SlimeController.Stunned.cs` | `Scripts/Controller/SlimeController.Stunned.cs` | 기절 물리 (조작불가 상태) |
| `RotatingPlatform.cs` | `Scripts/Platforms/RotatingPlatform.cs` | 회전 모션 패턴 |
| `SlimeController.cs` | `Scripts/Controller/SlimeController.cs` | `AddExternalVelocity()` — 회전 방향 가속도 |

**구현 방향**:
- `SawBladeHazard : MonoBehaviour, IHazardSource`. 트리거 콜라이더 (통과).
- 닿으면 `ApplyHazardEffect` (stunDuration = 조작불가 시간).
- 회전 방향 가속도: `OnTriggerStay2D`에서 톱날 회전 접선 방향으로 `AddExternalVelocity` 호출. `RotatingPlatform`의 각속도 계산 참고.
- 시각: 슬라임 갈라짐은 `SlimeVisual.cs`에서 `LastDamageType == SawBlade`일 때 특수 변형.

## 4. 고무줄 / 전봇대 줄 (Elastic Rope)

**카테고리**: 자체 시뮬 (Verlet rope) + 플랫폼 효과
**상태**: 미구현.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `PlatformMotor.cs` | `Scripts/Platforms/PlatformMotor.cs` | 키네마틱 베이스, Velocity/AngularVelocity 추적 |
| `PlatformCarrier.cs` | `Scripts/Platforms/PlatformCarrier.cs` | 슬라임-플랫폼 속도 연결 |
| `TiltPlatform.cs` | `Scripts/Platforms/TiltPlatform.cs` | `ApplyRiderInfluence` — 슬라임 무게로 눌리는 패턴 |
| `PendulumPlatform.cs` | `Scripts/Platforms/PendulumPlatform.cs` | 줄 기반 진자 + 탑승자 영향 |

**구현 방향**:
- Verlet 노드 체인. 각 노드의 position/prevPosition 저장, FixedUpdate에서 거리 제약 반복.
- 슬라임이 올라타면 가장 가까운 노드에 하향 힘 적용 (`ApplyRiderInfluence` 패턴).
- 점프 시 반동: `ForceAirborneWithVelocity` 호출 시점에 로프 노드에 반대 방향 impulse.
- EdgeCollider2D로 렌더링 연동하면 `SurfaceProbe`가 표면으로 인식 가능.
- Unity Joint 사용하지 말 것 — 체인 시 불안정. Verlet 직접 구현 권장.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `TiltPlatform.cs` | `Scripts/Platforms/TiltPlatform.cs` | **핵심 참고**. `ApplyRiderInfluence`로 슬라임 위치 기반 회전. 스프링-댐퍼 물리. |

## 10. 자동점프/대시 점 (Air Pickup)

**카테고리**: 픽업 (ICollectible 또는 트리거)
**상태**: 미구현.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `SlimeController.Launch.cs` | `Scripts/Controller/SlimeController.Launch.cs` | `Hop()` — 강화 hop 패턴. `ForceAirborneWithVelocity()` — 외부 발사. |
| `JumpPad.cs` | `Scripts/Mechanisms/JumpPad.cs` | `ForceAirborneWithVelocity` 호출 패턴 |
| `SlimeController.cs` | `Scripts/Controller/SlimeController.cs` | `AddExternalVelocity()` — 대시 impulse |

**구현 방향**:
- 트리거 콜라이더. `OnTriggerEnter2D`에서 슬라임 감지.
- 자동 점프: `ForceAirborneWithVelocity(gravityUp * force)` 호출.
- 특정 방향 대시: `ForceAirborneWithVelocity(dashDirection * force)`.
- 소비 후 비활성화 (쿨다운 or 일회성). 비주얼 피드백.
- charging이 아니라 hop 강화 → `ForceAirborneWithVelocity` 사용 (Charging 진입 안 함).

## 15. 인터랙터블 오브젝트 (침대, TV, 세탁기 등)

**카테고리**: 인터랙터블 + 오버라이드 (앉기류)
**상태**: 미구현.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `IInteractable.cs` | `Scripts/Interfaces/IInteractable.cs` | 상호작용 인터페이스 |
| `IExternalController.cs` | `Scripts/Interfaces/IExternalController.cs` | 앉기/세탁기 등 슬라임 제어 탈취 |
| `SlimeController.cs` | `Scripts/Controller/SlimeController.cs` | `SetOverride()` / `ReleaseOverride()` |
| `SignalSource.cs` | `Scripts/Mechanisms/SignalSource.cs` | UnityEvent 패턴 |

**구현 순서**:
1. `InteractionDetector` 컴포넌트 (슬라임에 부착): `Physics2D.OverlapCircleAll`로 주변 `IInteractable` 스캔, W키로 Interact 호출.
2. `InteractableBase` 추상 MonoBehaviour: 프롬프트 UI, 쿨다운.
3. 개별 구현:
   - 침대/벤치/신사/화톳불: `IExternalController` 구현. `SetOverride` → 앉기 애니메이션 → W로 `ReleaseOverride`.
   - 세탁기: `IExternalController`. 빙글빙글 애니메이션.
   - 축음기: `Interact`에서 AudioSource 변경. override 불필요.
   - TV: `Interact`에서 WebView 플러그인 활성화. override 불필요.
   - 폭죽/스피커: `Interact`에서 `AddExternalVelocity` (약간 밀림) + 파티클/사운드.

## 16. 통과되는 천 (Passable Cloth)
