# 기능 구현 가이드

각 기능을 구현할 때 어떤 카테고리에 속하는지, 어떤 인터페이스를 구현하고, 어떤 기존 코드를 참고해야 하는지 정리.

---

## 카테고리 요약

| 카테고리 | 인터페이스/베이스 | SlimeController 접점 | 대표 구현체 |
|----------|------------------|---------------------|------------|
| 위험 | `IHazardSource` | `ApplyHazardEffect()` → Stunned | `SpikeHazard.cs` |
| 플랫폼 효과 | `IPlatformEffect` | `OnSlimeAttach/Stay/Detach`, `ForceAirborneWithVelocity()`, `AddExternalVelocity()` | `JumpPad.cs`, `ConveyorBelt.cs` |
| 환경 존 | `EnvironmentalZone` (abstract) | `AddExternalVelocity()`, `MultiplyVelocity()`, `ClampFallSpeed()`, `PushBlockAttach()` | `WaterZone.cs` |
| 인터랙터블 | `IInteractable` | 없음 (InteractionDetector가 중계) | 미구현, 새로 작성 |
| 오버라이드 | `IExternalController` | `SetOverride()` / `ReleaseOverride()` | 미구현, 새로 작성 |
| 자체 시뮬 | 없음 | 없음 | 없음 |

## 인프라 API 시그니처

### HazardEffect (struct, `Scripts/Interfaces/HazardEffect.cs`)

```csharp
public enum DamageType { Generic, Spike, SawBlade, Lightning, Fire, CameraFlash }
```

### IPlatformEffect (`Scripts/Interfaces/IPlatformEffect.cs`)

```csharp
public interface IPlatformEffect {
    void OnSlimeAttach(SlimeController slime);   // 착지 시퀀스 완료 후 호출
    void OnSlimeDetach(SlimeController slime);   // 분리 시 호출
```

- `CheckPlatformEffect`는 착지 시퀀스(velocity/state 설정) **완료 후** 호출. JumpPad처럼 `ForceAirborneWithVelocity`로 상태를 되돌릴 수 있음.
- `OnSlimeStay`에서 `ForceAirborneWithVelocity` 호출은 안전. 직접 velocity 쓰기는 비권장.

### InteractionDetector (`Scripts/Interaction/InteractionDetector.cs`)

```csharp
// Slime child GameObject에 부착. 자체 Kinematic RB2D + trigger CircleCollider2D 보유.
// Layer: InteractionSensor (11) — Interactable layer(10)만 충돌, 환경 존과 간섭 없음.
public class InteractionDetector : MonoBehaviour {
    public bool HasInteractable { get; }   // 현재 상호작용 가능한 대상 존재 여부
    public void TryInteract();              // 가장 가까운 후보의 Interact() 호출
    public void ClearCandidates();          // 텔레포트/오버라이드 시 stale entry 제거
}
```
- **후보 관리**: `OnTriggerEnter2D`/`Exit2D`로 `HashSet<IInteractable>` 유지. 매 `Update()`에서 `CanInteract` 통과 + 최근접 1개 선택.
- **S키(Interact) 라우팅**: `SlimeController.Input.cs`의 `HandleInteractPressed()`에서 Attached 상태 + `HasInteractable == true`이면 `TryInteract()` 호출. Interact 액션은 VerticalUp(W, hop)과 완전히 분리된 별도 액션. S키는 VerticalDown과 동일 키를 공유하지만 Interact 발화는 HasInteractable 게이트로 제한되므로 상호작용 대상이 없을 때 Interact는 no-op. `BoxSleepInteractable`/`SitPoseInteractable`의 깨어나기·일어나기도 `OnInteractPressed`로 라우팅.
- **게이트 조건**: Charging, Stunned, HasOverride, Airborne 상태에서는 상호작용 불가.
- **Stale entry 방지**: `SlimeController.TeleportTo()`와 `SetOverride()`에서 `ClearCandidates()` 호출. Unity가 텔레포트 후 `OnTriggerExit2D`를 발화하지 않기 때문.
- **Physics Layer 구성**: InteractionSensor(11) ↔ Interactable(10)만 충돌 활성. Default/DragVolume/GravityField/Water 등과는 충돌 비활성 — 환경 존이 detector를 슬라임으로 오인하는 문제 방지.

### IExternalController (`Scripts/Interfaces/IExternalController.cs`)

```csharp
public interface IExternalController {
    void OnTakeControl(SlimeController slime);
    void OnReleaseControl(SlimeController slime);
    void ExternalUpdate(SlimeController slime);
    void ExternalFixedUpdate(SlimeController slime, float dt);
}
```
- `SetOverride` 시 charging 정리, carrier 분리, blockAttach/stunTimer 리셋, `InteractionDetector.ClearCandidates()` 호출.
- `ReleaseOverride` 시 gravity stack 클리어, Airborne 복귀.
- **주의**: ReleaseOverride 시 GravityField가 orphan될 수 있음. IExternalController 구현체가 gravity zone 밖으로 슬라임을 이동시킨 후 release하거나, release 후 슬라임 위치에 맞게 gravity zone 재진입 처리 필요.

### Override 전용 API (`SlimeController.cs`)

```csharp
// HasOverride==true일 때만 호출 가능. 그 외 호출 시 LogError.
public void OverrideVelocity(Vector2 v);
// NOTE: OverridePosition은 미구현. #5/#27/#31 (경로 기반 슬라임 이동) 구현 시 추가 예정.
```
- `AddExternalVelocity`/`MultiplyVelocity`는 일반 채널, `OverrideVelocity`는 override 전용 직접 쓰기.
- 구현체 예시: `KnockdownController` — `ExternalFixedUpdate`에서 `OverrideVelocity(Vector2.zero)`로 슬라임 고정.

### EnvironmentalZone (`Scripts/Mechanisms/EnvironmentalZone.cs`)

```csharp
public abstract class EnvironmentalZone : MonoBehaviour {
    protected SlimeController trackedSlime;
    protected virtual void OnSlimeEnter(SlimeController slime) { }  // 진입 시 1회
    protected virtual void OnSlimeExit(SlimeController slime) { }   // 탈출 시 1회
    protected abstract void ApplyEffect(SlimeController slime, float dt);  // 매 FixedUpdate
}
```
- 멀티 콜라이더 중복 진입 방지 (`overlappingColliderCount` 카운터 내장).
- `OnTriggerEnter2D`/`OnTriggerExit2D` 자동 처리. 서브클래스는 3개 메서드만 오버라이드.

### SlimeController 공개 API

```csharp
// --- 위치/속도 ---
public Vector2 Position { get; }              // rb.position (보간 아닌 물리 위치)
public Vector2 Velocity { get; }
public void AddExternalVelocity(Vector2 dv);  // 가산 채널 (바람, 부력, 컨베이어)
public void MultiplyVelocity(float factor);   // 곱셈 채널 (드래그, 물 저항)
public void ClampFallSpeed(float max);        // 하향 속도 캡
public void ForceAirborneWithVelocity(Vector2 vel);  // 외부 발사 (JumpPad, Catapult 등)

// --- 위험 ---
public void ApplyHazardEffect(HazardEffect effect);  // → Stunned 상태 진입

// --- 환경 존 ---
public void PushBlockAttach();   // attach 차단 카운터 +1
public void PopBlockAttach();    // attach 차단 카운터 -1 (0 미만 방지)

// --- 중력 ---
public void PushGravityField(GravityField f);
public void PopGravityField(GravityField f);
public Vector2 GravityUp { get; }
public Vector2 GravityRight { get; }
public Vector2 GravityVector { get; }

// --- 오버라이드 ---
public void SetOverride(IExternalController controller);
public void ReleaseOverride(IExternalController controller);
public void OverrideVelocity(Vector2 v);      // override 전용 직접 쓰기 (HasOverride 필수)
public bool HasOverride { get; }

// --- 텔레포트 ---
public void TeleportTo(Vector2 worldPos, Vector2 newVelocity);  // 전체 상태 리셋

// --- 상태 조회 ---
public SlimeState CurrentState { get; }
public bool IsStunned { get; }
public bool BlockAttach { get; }

// --- 이벤트 ---
public event Action<Vector2, Vector2> OnLanded;  // (position, surfaceNormal) 착지 시 발화
```

## 공용 VFX 인프라

여러 기능이 공유하는 비주얼 이펙트 인프라. 개별 기능 구현 전에 이 인프라가 먼저 잡혀야 함. **Tier 3 인프라 — 구현 완료**.

### 1. 파티클 시스템

- **방식**: Shuriken (Built-in Particle System). VFX Graph는 Synty 에셋 호환성/모바일 지원 이슈로 탈락.
- **메시 파티클 주력**: 아이코스피어, 삼각형, 다이아몬드 등 극저폴리 메시. 빌보드는 보조(반짝임/먼지 모트), 트레일은 선형 이펙트(바람 줄기/물줄기)에 한정.
- **`VFXType` enum** (`Scripts/Rendering/VFXType.cs`) — `Wind, Fire, Water, Dust, Lightning, Pipe`. **Append-only 규칙**: 새 값은 끝에 추가만, 기존 값 삭제/이름변경 금지 (Binder가 int로 직렬화).
- **`VFXColorPalette` ScriptableObject** (`Scripts/Rendering/VFXColorPalette.cs`, 에셋: `Settings/VFX/DefaultVFXPalette.asset`) — 단일 진실 공급원. 요소별 Primary/Secondary 색상. `GetPrimary(VFXType)`, `GetSecondary(VFXType)`, `TryGetColors(VFXType, out, out)`.
- **`ParticlePaletteBinder` 컴포넌트** (`Scripts/Rendering/ParticlePaletteBinder.cs`) — 각 ParticleSystem에 부착, `VFXType` enum 지정. `[ExecuteAlways] OnValidate()`에서 팔레트 색상 자동 적용. 인스펙터에서 팔레트 교체 시 즉시 프리뷰 갱신.
- **파티클 머티리얼** (`Art/Materials/VFX_Particle_Mat.mat`) — URP Particles/Unlit 셰이더. Vertex Color 활성. 공용 Shader Graph(Unlit + Step 디졸브)는 필요 시 별도 추가.
- **프리팹 구조**: `Prebs/VFX/Base_Particle.prefab` + Prefab Variant로 요소별 파생. `Prebs/VFX/Dust_Landing.prefab` (착지 먼지) 구현 완료. 베이스 변경이 모든 변형에 자동 전파.
- **`LandingDustSpawner`** (`Scripts/Rendering/LandingDustSpawner.cs`) — Slime에 부착, `SlimeController.OnLanded` 이벤트 구독. 착지 시 `Dust_Landing` 프리팹을 표면 법선 방향으로 회전하여 생성. 프리팹은 local up 기준 cone, 회전은 spawner 담당.
- **블렌딩 규칙**: Alpha Blend 기본. Additive는 글로우/번개/마법 이펙트에만 한정.
- **소팅 레이어**: 전용 VFX 레이어 3개 — `Background_VFX`, `Character_VFX`, `Foreground_VFX`. ParticleSystemRenderer의 Sorting Layer + Order in Layer 명시 필수.
- **크기/타이밍 컨벤션**: 캐릭터 높이의 5~20% 범위. Start Size 랜덤은 Random Between Two Constants 0.7x~1.3x. 주요 액션은 수명의 첫 1/4에 완료 (스냅감 있는 타이밍).
- **방출 밀도**: 5~15/초 기본. 50+/초는 오버드로우 + 로우폴리 미학 위반.

### 2. HDR Emission + URP Bloom

- **URP Pipeline Asset**: HDR 활성화 + Global Volume에 Bloom override (threshold 1.0, intensity 0.5~1.5, scatter 0.5~0.7).
- 발광이 필요한 모든 비주얼이 공유: 번개(#20), 파이프 점선(#31), 카메라 플래시(#25), 모닥불(#15), 폭죽(#15) 등.
- HDR intensity 가이드: 일반 발광 1.5~3, 강한 발광(번개 코어, 폭발) 3~5.

### 3. 카메라 셰이크

- **Cinemachine 3.x 설치 완료** (SampleScene Main Camera: `CinemachineBrain`, SlimeVCam: `CinemachineCamera + PositionComposer + CinemachineImpulseListener`).
- **`ImpulseEmitter` 래퍼** (`Scripts/Effects/ImpulseEmitter.cs`) — `CinemachineImpulseSource` 필수 동반. `Emit(float force)` 호출로 `GenerateImpulseWithForce` 실행. Amplitude/Duration은 ImpulseSource 인스펙터에서 prefab별 설정.
- **Listener는 VCam에 부착** (CM 3.x 규칙 — Brain이 있는 Main Camera엔 `CinemachineExternalImpulseListener` 사용). 현재 SlimeVCam에 일반 ImpulseListener 부착됨.
- **튜닝 프리셋**: 점프스케어 amp 1.5/dur 0.5s (Emit 1.5), 카메라플래시 amp 0.2/dur 0.15s (Emit 0.2), 폭죽 0.3/0.2s (Emit 0.3), 번개 1.0/0.4s (Emit 1.0).
- 사용처: 점프스케어(#19, 구현됨), 카메라플래시(#25, 구현됨), 번개(#20, 예정), 폭죽(#15, 예정), 큰 슬라임 충격(#5, 예정).

### 4. 풀스크린 UI 이펙트 (공용 Canvas)

트리거 기반 풀스크린 오버레이(페이드, 점프스케어, 플래시, 피해 비네트 등) 공용 인프라. **단일 루트 Canvas** + 이펙트별 자식 GameObject 패턴.

- **씬 구조**: `FullscreenEffectCanvas` (씬 루트, `Canvas` + `CanvasScaler` + `GraphicRaycaster`, sortingOrder 9000) 하나만 배치. 각 이펙트는 그 자식 GameObject(`CanvasGroup` + 컨트롤러 + 고유 UI 자식)로 구성. 싱글톤/DontDestroyOnLoad 도입 안 함.
- **베이스 클래스** (`Scripts/UI/FullscreenOverlayCanvas.cs`): 추상. `CanvasGroup` 알파 페이드 제공(`RunFade(display, fade)` 코루틴 헬퍼). `fullscreenImage`(Image, 옵션), `audioSource`(옵션), `impulseEmitter`(옵션) 필드 노출.
- **서브클래스 컨벤션**: `Trigger(...)` 메서드에서 per-effect 셋업(sprite 스왑, 사운드, 임펄스) 후 `RunFade` 호출. 자식 UI 요소는 CanvasGroup으로 자연스럽게 같이 페이드.
- **기존 서브클래스**:
  - `JumpscareCanvasController` (`Scripts/UI/`): sprite + sound + impulse 1.5. 풀스크린 흰색 페이드 (alpha 1).
  - `FlashCanvasController` (`Scripts/UI/`): sprite 없이 디머 흰색(`whiteTintAlpha` 기본 0.5) + 뷰파인더 자식 UI(L 브래킷 10개). Audio/impulse는 hazard 본체에서 담당(3D positional) → 캔버스는 시각만.
- **이펙트 추가 절차**: `FullscreenOverlayCanvas` 상속 → per-effect `Trigger` 작성 → 에디터 setup에서 `FullscreenCanvasSetupUtility.GetOrCreateRoot()` + `GetOrCreateEffectChild(root, "이름")` + 필요 UI 구성 + 컨트롤러 와이어링. 코드 3~5줄.
- **에디터 헬퍼** (`Scripts/Editor/FullscreenCanvasSetupUtility.cs`): 루트 Canvas + 이펙트 자식 find-or-create, 풀스크린 Image 헬퍼. `SceneVisibilityManager.Hide`로 씬 뷰 자동 숨김.
- **동시 이펙트**: 각 자식이 독립 CanvasGroup이라 겹쳐 발동 가능 (예: 플래시 중 데미지 비네트).
- 사용처: 점프스케어(#19, 구현됨), 카메라플래시(#25, 구현됨), 폭죽 화면번쩍(#15, 예정), 번개 화면번쩍(#20, 예정), 씬 전환 페이드(예정), 피해 비네트(예정).

**Tier 3 검증 결과**: ① VFXType enum 6개가 현재 알려진 사용처를 커버 (추후 append-only로 확장) ② Bloom (threshold 1.0, intensity 0.25) — 슬라임/환경 셰이더와 충돌 없음 확인 ③ Cinemachine 3.x + ImpulseEmitter 래퍼 도입 완료 (묶음 A 범위에서 SampleScene 마이그레이션 실행). ④ 풀스크린 UI 공용 Canvas 패턴 확립 (JumpscareCanvasController/FlashCanvasController로 검증).

## 튜닝 철학

이 게임의 핵심은 **commitment (헌신)**. 한번 발사하면 되돌릴 수 없음.

- **즉발 회피 메커닉 없음**: air dash, double jump, jump cancel, wall jump 등 추가하지 않음. 슬라임은 발사 후 중력과 air control만으로 궤도를 조절.
- **차징은 항상 발사로 끝남**: 차징 상태에서 취소하여 Attached로 돌아가는 것 없음. 반드시 발사.
- **점성 슬라임**: 표면에 닿으면 붙음 (바운스 없음). 충돌 에너지를 전부 흡수. stick 시스템으로 착지 관성을 소화.
- **에너지 전환**: 착지 속도를 판정원 크기로 변환하여 연속 점프의 에너지를 보존. W/S 중력 조절로 인한 인플레이션 방지 (shadow speed 공식).
- **위험 오브젝트**: 기절 + 넉백. 체력 시스템 없음 (현재). 기절은 짧은 입력 잠금 + 궤도 이탈. pogostuck/Getting Over It처럼 "떨어지는 것 자체가 벌칙".

새 기능 제안 시 이 원칙과 충돌하는지 확인할 것. 특히 "공중에서 피할 수 있게 해주는" 메커닉은 commitment 원칙을 깨뜨림.

## 비주얼 변형 원칙

**플레이어와 상호작용하는 모든 오브젝트의 비주얼 변형은 물리/수학적으로 유도한다.** 외부 애니메이션 클립(FBX/GLB에 포함된 rig+keyframe)은 상호작용 오브젝트에 사용하지 않는다.

### 외부 애니메이션 클립 허용 범위

| 허용 | 예시 |
|------|------|
| AI 캐릭터의 자율 행동 | #5 큰 슬라임, #27 뱀 (자율 행동 주체라 입력 독립적 애니메이션이 자연스러움) |
| 배경 장식물 | 깃발 펄럭임, 배경 수면 출렁임, 멀리 있는 움직이는 구조물 |
| 시네마틱 연출 | #29 녹다운 등 Timeline 기반, 입력 차단 상태 |

### 상호작용 오브젝트의 비주얼 변형 3가지 메커니즘

| 메커니즘 | 설명 | 기존 구현체 |
|----------|------|-------------|
| Transform 기반 이동 | 좌우/수직 이동, 회전 | `WaypointPlatform`, `RotatingPlatform` |
| Shader/수학 기반 비대칭 변형 | 슬라임 squash/stretch 패턴 확장 | 슬라임 `SlimeVisual` egg-shape |
| 스프링-댐퍼 "보잉" 반응 | 착지 출렁, 발사 후 진동, 문 반동 | `TiltPlatform`, `PushDoor`, `PendulumPlatform` |

이 세 가지 조합으로 대부분의 "반응성 있는 변형"을 커버한다. 복잡한 rig 불필요.

### 이 원칙의 목적

1. **물리-비주얼 일치 자동 보장** — 물리에서 비주얼을 유도하면 동기화 문제가 원천 차단됨
2. **commitment 원칙 보호** — 애니메이션 클립은 시간 기반 재생이라 입력과 독립적. 물리 기반 변형은 플레이어 입력에 실시간 반응
3. **에셋 파이프라인 단순화** — 어떤 정적 모델이든 사용 가능. rig 포함 모델만 골라야 하는 제약 없음
4. **본 작업 단계 모델 교체 비용 최소화** — 회색박스 → 본 작업 전환 시 정적 모델만 교체, 비주얼 로직은 그대로

### 엘레베이터 (#11) 적용

엘레베이터는 통짜 메시 + `WaypointPlatform` + 스프링-댐퍼(도착 시 출렁)로 구현한다. rig+애니메이션 포함 모델(scissor lift 등)은 사용하지 않는다. 벽면 타고 위아래 이동하는 리프트도 동일 — 직사각형 플랫폼 + `WaypointPlatform`으로 충분.

**추가 구현 필요** (수면 렌더링 결정은 아래 별도 단락 참조):
- 수면 차징: `DragZone.allowCharging` 패턴 참고. swim 모드 내 서브상태로 처리 (아래 단락 참조).
- 가라앉았다 올라옴: 현재 부력으로 자연 구현됨. 부력 > 중력이면 자동 부상.
- 현재 물 내부 AD 움직임은 구현되어 있으나 수면 근처에서 위아래 진동 — swim 모드 도입 시 수면 곡선 lerp로 해결.

**수면 렌더링 및 swim 모드 통합 방식**:
- 렌더링/물리: **방식 A(CPU 스프링 + 단일 동적 Mesh)로 시작 → 폴리시 단계에서 D(하이브리드)로 확장**. A가 D의 부분집합이라 같은 CPU 코드 위에 1D RFloat 텍스처 업로드 + Shader Graph 레이어만 얹으면 D 완성. B(순수 셰이더)/C(스프라이트)는 슬라임의 빈번한 진입/이탈에 반응 부족. 2.5D(3D 렌더링)라 URP 2D Renderer 호환성 제약은 무관.
- 컴포넌트 분리: `WaterZone`(EnvironmentalZone — 드래그/외력 담당)과 **`WaterSurface`**(스프링 시뮬+렌더링 담당)로 분리, 같은 GameObject에 부착. 50~100개 스프링(월드 단위당 5개), FixedUpdate 실행, 전파 패스 프레임당 8회, `tension≈0.025 / damping≈0.06 / spread≈0.08`로 시작 후 튜닝.
- **수면 높이 단일 source of truth**: `WaterSurface.GetSurfaceHeightAt(float worldX)` 메서드가 보간된 스프링 높이 반환. **부력 시스템, swim 모드(#1), 비주얼 셰이더가 모두 이 메서드를 참조** — 비주얼과 물리의 불일치 방지. 기존 부력은 상수 수면 높이 대신 이 메서드 호출로 변경.
- swim 모드(#1)와의 책임 분리: 수면은 collider 표면이 아니라 trigger 영역의 상단 곡선. **SurfaceProbe는 물 안에서 비활성**, swim FSM이 직접 슬라임을 수면 곡선 위로 lerp. 물속 다른 collider(바위 등)와 만나면 SurfaceProbe 재활성화 규칙 별도 검증 필요.
- 수면 차징: swim 상태 내 서브상태로 처리. 차징 중 슬라임 위치 스프링에 정적 하향 임펄스 → 수면 패임 → 발사 시 스프링 복원력이 launch 속도에 소량 기여(물 트램폴린 느낌). commitment 원칙 유지(차징 진입하면 발사로만 종료). 발사 normal은 파인 지점의 접선 수직 사용.
- Splash: `OnTriggerEnter2D`에서 슬라임 `velocity.y × mass`를 슬라임 bounds 폭에 걸친 **여러 스프링에 분산 임펄스**(prime31 방식, 단일 포인트보다 자연스러운 V 파동). **이탈 시(`OnTriggerExit2D`)에도 반대 방향 임펄스** 적용 — 물 빠져나갈 때 수면이 솟는 느낌. 파티클은 별도 ParticleSystem으로 보강하되 점성 슬라임 톤에 맞춰 작은 물방울 + 두꺼운 숏-리브드 wave 강조.
- 렌더링 구현: 처음부터 **단일 동적 Mesh**(N×2 트라이앵글 스트립, 1 드로우콜) 사용. LineRenderer 세그먼트 방식 금지(드로우콜 폭증). D 확장 시 시뮬 50 스프링 + 비주얼 50×1~64×1 세분화 스트립 메쉬 + Shader Graph `Sample Texture 2D LOD`로 보간 (vertex stage는 **LOD 명시 필수**, 일반 `Sample Texture 2D`는 fragment 전용).
- D 단계 데이터 전달 (GC-free 패턴): `Texture2D(springCount, 1, TextureFormat.RFloat, false)` 생성 → 매 프레임 `GetPixelData<float>(0)`으로 NativeArray 직접 쓰기 → `Apply(false)`로 밉맵 없이 업로드. **매 프레임 배열 할당 0, GC 0**. 128 스프링 = 512바이트/프레임으로 무시 가능.
- D 단계 셰이더 레이어: vertex displacement(스프링 높이) + **작은 진폭 사인파 합성**(스프링 정지 상태에서도 ambient 잔물결 유지) + Scene Depth 기반 shallow/deep `Lerp` + 깊이 차이 기반 교차선 폼 + `_CameraOpaqueTexture` 굴절 + 상단 엣지 하이라이트 + 스크롤링 노이즈.
- **URP Pipeline Asset 체크리스트**: **Depth Texture ✅ 활성화**, **Opaque Texture ✅ 활성화** (안 켜면 깊이 색상/폼/굴절 셰이더 작동 안 함). 워터 머티리얼 **Surface Type = Opaque + Render Queue를 Transparent(3000)로 오버라이드** (투명 정렬 문제 회피).
- 금지 사항: `MaterialPropertyBlock.SetFloatArray`(SRP Batcher와 비호환). CPU→GPU 전달은 위의 GC-free Texture2D 패턴 사용.
- 시뮬레이션 정지 최적화: 모든 스프링 velocity가 임계값 이하로 떨어지면 **시뮬레이션과 텍스처 업로드 모두 중단**. 카메라 밖 수체는 시뮬 비활성화. 빈 풀이 여러 개 있는 씬에서 CPU 절약.
- 비직사각형 풀 확장 경로 (당장은 불필요): 1D 체인 대신 **2D 그리드(예: 32×32)** + 32×32 RFloat 텍스처로 확장하면 원형/다각형 풀 가능. 셰이더에서 월드 XZ 좌표를 UV로 매핑.
- Tier 3 선결 검증: ① `GetSurfaceHeightAt` 보간 방식(선형 vs 큐빅) ② 물속 SurfaceProbe 활성화 규칙 ③ swim 차징의 발사 normal 정의 ④ FixedUpdate 시뮬과 부력 쿼리의 호출 순서 ⑤ URP Pipeline Asset Depth/Opaque Texture 활성화 후 다른 셰이더에 미치는 부수효과 확인.

## 4. 고무줄 / 전봇대 줄 (Elastic Rope)

**카테고리**: 자체 시뮬 (Verlet rope) + 플랫폼 효과
**상태**: 미구현.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `PlatformMotor.cs` | `Scripts/Platforms/PlatformMotor.cs` | 키네마틱 베이스, Velocity/AngularVelocity 추적 |
| `PlatformCarrier.cs` | `Scripts/Platforms/PlatformCarrier.cs` | 슬라임-플랫폼 속도 연결 |
| `TiltPlatform.cs` | `Scripts/Platforms/TiltPlatform.cs` | `ApplyRiderInfluence` — 슬라임 무게로 눌리는 패턴 |
| `PendulumPlatform.cs` | `Scripts/Platforms/PendulumPlatform.cs` | 줄 기반 진자 + 탑승자 영향 |

**구현 방향**:
- Verlet 노드 체인. 각 노드의 position/prevPosition 저장, FixedUpdate에서 거리 제약 반복.
- 슬라임이 올라타면 가장 가까운 노드에 하향 힘 적용 (`ApplyRiderInfluence` 패턴).
- 점프 시 반동: `ForceAirborneWithVelocity` 호출 시점에 로프 노드에 반대 방향 impulse.
- EdgeCollider2D로 렌더링 연동하면 `SurfaceProbe`가 표면으로 인식 가능.
- Unity Joint 사용하지 말 것 — 체인 시 불안정. Verlet 직접 구현 권장.

**구현 방식 결정**:
- 물리: **Verlet Integration** (노드 15~25개, constraint iteration 30~50회, FixedUpdate 실행). HingeJoint2D 체인은 점성 슬라임이 노드에 붙는 순간 불안정해지므로 사용 금지. toqoz.fyi 블로그 코드를 레퍼런스로 자체 구현.
- 렌더링: 프로토타입 단계는 **LineRenderer**, 비주얼 완성 단계에서 **Procedural Mesh**로 교체. 이 게임은 2.5D(3D 렌더링)라 가이드의 "URP 2D Renderer 호환성" 제약은 무관 — Mesh가 오히려 URP Bloom/Lighting/depth sorting과 자연스럽게 통합됨.
- **SurfaceProbe 통합 (핵심)**: rope GameObject에 `EdgeCollider2D` 1개 부착, FixedUpdate 시뮬레이션 끝에서 Verlet 노드 위치를 `EdgeCollider2D.points`에 복사. SurfaceProbe는 평소처럼 ClosestPoint 기반 depenetration으로 처리 — **rope를 일반 표면으로 인식**, SurfaceProbe 코드 수정 0. 점성 슬라임 stick 시스템, 차징, 발사가 모두 기존 로직 그대로 동작.
- 슬라임 무게 sag: `IPlatformEffect.OnSlimeStay`에서 contact point 근처 Verlet 노드에 `slimeMass * gravity * dt²` 하향 힘 적용. constraint solving이 자동으로 부드러운 sag 곡선 생성 — 명시적 애니메이션 코드 불필요. 인접 노드에 influence radius 기반 감쇠된 힘으로 자연스러운 처짐.
- 발사 메커닉: 줄도 표면이므로 표면 normal(=sag된 줄의 접선 수직) 기반 발사 그대로 적용. "고무줄" 변형은 distance constraint에 elastic factor 추가하여 압축 시 복원력으로 launch 속도 보정(Umihara Kawase식). "전봇대 줄"은 elasticity 0, 단순 sag만.
- 양 끝점: 첫 노드와 마지막 노드를 pin (전봇대 anchor). 줄 길이는 양끝 거리의 1.05~1.2배로 초기 sag 여유 확보.
- 차징 중 동결: 슬라임이 Charging 상태일 때는 무게 적용 일시정지 (sag 갱신 중단) — `chargeEntryCrawl` 안정성 확보.
- Tier 3 선결 검증 항목: ① EdgeCollider2D 매 FixedUpdate 갱신과 SurfaceProbe ClosestPoint 호출 순서(`Physics2D.SyncTransforms` 타이밍) ② 차징 중 sag 동결 시 시각적 어색함 여부 ③ 발사 직후 줄과 슬라임의 즉시 분리 (재충돌 방지 짧은 ignore 타이머).
- 최적화: 노드 수가 25개 이하면 Burst 없이도 충분. 한 씬에 줄 5개 이상이면 그때 Burst+Jobs 적용 검토.
- 배경 장식 전선이 필요해지면 별도 시스템(Catenary + LineRenderer, Tier 1)으로 분리 — 인터랙티브 줄과 같은 코드 공유하지 말 것.

## 6. 회전 떨어지는 원형 플랫폼

**카테고리**: 플랫폼 (PlatformMotor 확장)
**상태**: 구현 완료 — `RollingDiskPlatform.cs`.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `RollingDiskPlatform.cs` | `Scripts/Platforms/RollingDiskPlatform.cs` | 구현체 |
| `TiltPlatform.cs` | `Scripts/Platforms/TiltPlatform.cs` | 참고 — `ApplyRiderInfluence`의 localX 패턴 |

**구현 방향**:
- `TiltPlatform` 구조 미러 — 원형 콜라이더(`CircleCollider2D`, `[RequireComponent]`) + `Rigidbody2D (Kinematic, 자동)`.
- `maxTiltAngle` 제한 없음, 스프링 복원 없음 → 360도 자유 회전.
- 라이더 영향은 **각가속도**로 누적 (`pendingAngAccel`), `ComputeMotion`에서 소비.
- **기준축 world-horizontal** (`riderWorldPos.x − rb.position.x`) — 디스크 자기 회전 영향 없음. 중력 방향(world-down)이 불균형의 물리적 원인.
- 각도 상태는 **도(deg)** 단위 — `rb.rotation`과 일치, Rad2Deg 변환 불필요.
- 탄젠셜 속도 점프 이탈: `PlatformCarrier.GetEffectiveVelocity` (크로스 곱)으로 자동 처리 — 캐리어 수정 없음.

**튜닝 노브** (인스펙터):
- `riderAngAccelScale` (deg/s² per kg·m, 기본 50) — 라이더 오프셋 대비 회전 민감도.
- `angularDamping` (s⁻¹, 기본 0.3) — 무한 가속 방지용 감쇠.
- `maxAngularSpeed` (deg/s, 기본 720) — 안전 상한.
- `deadZoneAngleDeg` (0~89°, 기본 15°) — 디스크 정점 기준 이 각도 내에 라이더가 서 있으면 토크 0. `stickSlopeThreshold`와 유사. 경계 밖부터 선형 페이드인.

**한계**:
- World-down gravity 가정 — `GravityField` 구역 내 배치 비추천.
- `basePosition`이 `Awake`에서 캐싱됨 — 런타임 부모 이동 미지원 (`TiltPlatform`과 동일).
- 얼음 슬라임(`carrierFriction = 0`)도 위치 기반 토크로 영향 줌 — 의도된 동작으로 간주.

## 7. 매달린 흔들리는 플랫폼

**카테고리**: 플랫폼 (PlatformMotor 확장)
**상태**: 구현 완료 — `PendulumPlatform.cs`에 착지 관성 + 라이더 토크 추가.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `PendulumPlatform.cs` | `Scripts/Platforms/PendulumPlatform.cs` | 구현체 (기존 진자 방정식 + 라이더 영향 확장) |
| `PlatformCarrier.cs` | `Scripts/Platforms/PlatformCarrier.cs` | `Attach` 시점에 `ApplyRiderInfluence` 즉시 호출 — 수정 없음 |

**구현 방향** (세 층의 라이더 영향):
- 직접 진자 방정식 유지 (HingeJoint2D 사용 안 함 — `PlatformMotor`의 Kinematic + MovePosition/MoveRotation 규약과 충돌).
- **(a) 착지 관성**: `ApplyRiderInfluence` 첫 호출(=attach 순간)에 `riderVelocity.x / ropeLength * landingImpulseScale`만큼 각속도에 임펄스 주입. `riderAttached` 플래그로 중복 방지.
- **(b) 라이더 위치 토크**: 매 프레임 `-gravity * mass * localX * riderPosAngAccelScale`를 `pendingRiderAngAccel`에 누적하여 진자 방정식에 합산. 줄 전체 스윙을 유발.
- **(c) 판자 flex (스프링-댐퍼)**: 라이더 위치로 `targetTilt` 설정 → `tiltStiffness/tiltDamping`으로 `currentTilt`가 수렴 → 출력 회전에 가산. 줄 스윙과 독립된 판자 자체의 즉각적 기울기.
- (a)와 (b)의 방향은 **의도적으로 반대** — (a) 운동량 전달은 라이더 진행 방향, (b) 중력 토크는 라이더 반대 방향. 정상 물리.
- 각도 상태는 **라디안(rad)** 내부 유지, 출력만 `Rad2Deg`.

**출력 수식**:
```
rotDeg = angle · Rad2Deg · swayRatio + currentTilt
```
- `swayRatio` (0~1, 기본 1.0): 판자가 줄 스윙을 얼마나 따라갈지. 1이면 실제 진자처럼 함께, 0.3이면 그네 좌석처럼 상대적으로 수평 유지.
- `currentTilt`는 swayRatio 영향 없음 — 별도 DOF.

**튜닝 노브** (인스펙터):
- `Header("Rider Inertia")`: `landingImpulseScale` (기본 1.0), `riderPosAngAccelScale` (기본 0.1).
- `Header("Cosmetic Board Tilt")`: `maxTiltAngle` (기본 15°), `tiltStiffness` (기본 20), `tiltDamping` (기본 5). `tiltStiffness = 0`으로 판자 flex 완전 비활성화 가능.
- `swayRatio` (0~1, 기본 1.0).

**의존 조건 (중요)**:
- `riderAttached` 플래그는 `SlimeController`가 같은 surfaceCollider에 대해 `Attach` 중복 호출을 방지한다는 전제(SlimeController.cs:319)에 의존. 가드 제거 시 임펄스 재발동 버그 — `PlatformCarrier` 식별 기반 추적으로 전환 필요.

**한계**:
- 단일 라이더 가정 — 두 슬라임이 동시 착지 시 임펄스는 첫 번째만 발동.
- World-down gravity 가정 — `GravityField` 구역 비추천.
- 부호는 플레이테스트 검증 필요 — (a) 착지 방향 반대면 `landingImpulseScale` 부호 반전, (b) 라이더 서 있는 쪽으로 기울면 `riderPosAngAccelScale` 부호 반전.

## 12. 칼 (Knife)

**카테고리**: 위험 + 플랫폼 (하이브리드)
**상태**: **부분 구현**. 관통 + 끌림 + 재타격 가드 완료, 썰리는 애니메이션 대기.

| 실제 구현 | 경로 |
|---|---|
| `KnifeHazard.cs` | `Scripts/Mechanisms/KnifeHazard.cs` |
| `KnifeTestSetup.cs` | `Scripts/Editor/KnifeTestSetup.cs` (메뉴: `SlimeJumping/Setup Knife Test`) |
| `IgnoredColliderList.cs` | `Scripts/Physics/IgnoredColliderList.cs` (`IgnoreMode.Passthrough` 모드 사용) |

**컴포넌트 배치**:
- `blade` 자식 GO: trigger `Collider2D` + `KnifeHazard` (같은 GO). 칼날(sharp side) 면적을 덮어야 양방향 진입 가능.
- `body` 자식 GO: non-trigger `Collider2D` (손잡이/등 부분). 일반 표면.
- `KnifeHazard.bodyRoot`: `body` GO (또는 공통 부모) 참조 — 하위 모든 Collider2D 자동 수집.

**주요 필드**:
- `velocityThreshold` — 이 이하 속도로 접촉 시 무효 (느린 접촉은 안전)
- `speedRetainRatio` (0~1), `pullForce` — Saw와 동일 의미 (진입 속도 × 유지비 + blade 방향 끌림)
- `stunDuration`, `hitCooldown`
- `passthroughDuration` — hit 직후 body 관통 허용 시간

**동작 시퀀스** (`TryHit` + `IgnoreBodyDuringStun` 코루틴):
1. `velocityThreshold` 검사 → 통과 시 hazard 적용
2. `slime.RegisterIgnoredCollider(bodyCols[b], passthroughDuration)` — 내부에서 `IgnoreMode.Passthrough`로 등록. IgnoredColliderList가 `Physics2D.IgnoreCollision` + SurfaceProbe 필터링을 생명주기 관리. blade 자체도 등록(트리거 → IgnoreCollision은 자동 스킵되어 trigger 이벤트 유지). Passthrough 모드는 분리 거리 체크 없이 타이머만으로 해제되어, blade 관통 중 거리가 흔들려도 중도 해제되지 않음.
3. `WaitForSeconds(duration)` 후 **slime이 body와 여전히 겹쳐있으면** 매 프레임 timer 연장 → 완전히 벗어날 때까지 관통 유지.
4. `passthroughActive` 플래그로 코루틴 진행 중엔 재타격 차단 (OnTriggerStay 루프 방지).

**남은 작업**: 썰리는 비주얼 (blade 방향 따라 `SlimeVisual` 분할 애니메이션).

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `EnvironmentalZone.cs` | `Scripts/Mechanisms/EnvironmentalZone.cs` | 트리거 진입/탈출 패턴 |

**구현 방향** (상세 결정은 아래 별도 단락 참조):
- 2D mass-spring grid (구조+전단+굽힘 스프링). 로프(#4)와 동일 원리, 2D 그리드로 확장.
- 트리거 콜라이더만 부착 (collider 없음). 슬라임 통과 가능, attach 불가.

- 단일 동적 Mesh로 시각화. **#4 로프 이후 진행** — Verlet 코드 재사용.

**구현 방식 결정**:
- 물리: **커스텀 Verlet 질점-스프링 2D 그리드** (8×12 ~ 10×16 질점, structural + shear + bend 스프링, FixedUpdate, 거리 구속 5~15회 반복). 내장 `Cloth`(3D 전용, Collider2D 비호환), Magica Cloth 2(자체 콜라이더 우회 부담), Obi Cloth($47, PolygonCollider2D 미지원 + 의존성) 모두 탈락.
- **#4 로프 이후 진행 — Verlet 코드 재사용**. 로프 작업 시 적분 스텝과 거리 구속 솔버를 `VerletField` 같은 공용 베이스로 일반화해두면 천은 토폴로지(1D 체인 → 2D 그리드)와 스프링 종류만 확장. 로프가 끝난 후 실질 난이도는 Tier 2 수준.
- 렌더링: **단일 동적 `Mesh` + `MeshRenderer`**. 2.5D(3D 렌더링) 환경이라 가이드 권장이 자연스럽게 맞음. `mesh.MarkDynamic()` 필수. Z축에 미세한 두께(또는 살짝 부풀린 형태) 줘서 parallax/3D 라이팅과 어울리게.
- **핵심 책임 경계 — collider 브릿지 없음 (로프와 정반대)**: 로프는 EdgeCollider2D를 깔아 SurfaceProbe가 surface로 인식했지만, **천은 어떤 collider도 부착하지 않음**. SurfaceProbe는 천의 존재 자체를 모름. 슬라임은 천을 통과 — 이게 "통과 천"의 본질.
- **표면 따라가기 (관통이 아닌 덮음 표현)**:
  - 천 GameObject에 천 영역 전체 trigger collider 1개. FixedUpdate 시뮬레이션 후처리 단계에서 trigger 안 슬라임의 원형 경계(SurfaceProbe와 동일한 통일 radius 사용) 내부에 들어간 천 질점들을 표면 위로 밀어냄: `node.position = slimePos + (node.position - slimePos).normalized * slimeRadius`. (delta가 0에 가까우면 임의 방향(예: gravityUp) 사용)
  - 일반 Verlet 천 충돌과 동일한 코드지만 천 질점 위치만 보정. Verlet 특성상 이 위치 보정이 자동으로 다음 프레임 속도에 반영되어 trailing wave가 자연 발생.
  - 시각적으로 "슬라임이 천을 관통"이 아닌 "천이 슬라임을 감싸며 흘러감"이 됨. 슬라임의 squash/stretch 변형까지 정확히 따라갈 필요는 없음 — 원형 근사로 충분.
  - **Z축**: 천 mesh를 슬라임보다 카메라 쪽으로 살짝 (예: Z = slimeZ - 0.05) 배치해야 "덮음"이 성립. 천 셰이더 alpha 0.85~0.95로 두면 뒤로 살짝 비치는 효과.
  - 통과 중 천 질점에 슬라임 속도의 5~10%를 더해 "끌려가는" trailing 효과 보강 (선택, 비주얼 폴리시 단계).
- **천 → 슬라임 약한 드래그 (천에 부딪치는 느낌 표현)**:
  - 단순 차감이 아닌 **속도 비례 드래그**: `dragForce = -slime.velocity * clothDragCoefficient * coverageRatio`, `slime.AddExternalVelocity(dragForce * dt)`로 적용. 기존 `WaterZone` 드래그 패턴과 동일한 채널 사용.
  - `coverageRatio`는 슬라임이 천 영역에 잠긴 정도 0~1 (trigger 중심 기반 감쇠). 천 푸시 임펄스(천 → 천 질점)와 **같은 source 사용** — 비주얼 출렁임과 슬라임 감속이 동조되어야 "천이 출렁이는 만큼 슬라임이 느려짐"이 성립.
  - **commitment 원칙 보호 안전장치 (필수)**:
    1. 최대 감속률 캡: `dragPerSecond <= 0.4` (천 한 장이 초당 40% 이상 빼앗지 못함)
    2. 최소 통과 속도 보장: 천 영역 체류 동안 누적 감속 ≤ 50%. 천이 슬라임을 멈추게 하는 일은 없어야 함 (점성 드래그라 자연스럽게 0에 수렴하지만 명시적 클램프 권장)
    3. 차징/Attached 상태에서 드래그 0: `IsCharging || IsAttached`일 때 비활성 — 천 가장자리에 표면 접촉 시 차징 거동이 깨지지 않게
  - 파라미터 시작값: 얇은 커튼 `clothDragCoefficient ≈ 0.5`, 두꺼운 천 ≈ 2.0. 점프 궤도의 결정적 지점에는 천 배치 금지 (장식적/약한 변수로만 활용).
  - 두께가 너무 크면 swim 모드(#1) 같은 별도 locomotion 영역처럼 느껴질 수 있음 — 보수적으로 튜닝.
- 이 설계의 단순성: 로프의 어려운 부분(EdgeCollider2D 동기화 타이밍, SurfaceProbe 책임 분할, stick/charging/launch 통합)이 전부 사라짐. 천은 "슬라임 위치에 반응하는 시각 시뮬레이션 + 약한 단방향 드래그".
- 바람: 모든 질점에 Perlin 노이즈 기반 `Vector2` 외력. `WindZone2D`의 방향벡터 재사용해서 씬 내 다른 시스템과 일관성 유지.
- Pin 패턴으로 변형 표현: 상단 행 고정 = 커튼, 좌측 열 고정 = 깃발, 한 점 고정 = 넝마. 같은 `ClothField` 컴포넌트의 `pinMask` 파라미터 차이로 모두 처리.
- 성능: PC 전용이고 한 천 ~150 질점이면 Burst 없이도 충분. 한 씬 5장 넘으면 그때 `[BurstCompile] IJob`(거리 구속) + `IJobParallelFor`(위치 갱신) 적용. GPU compute shader는 이 규모에 과잉.
- 스킵할 것: 셀프 콜리전, 찢어짐 — 통과 천 컨셉에 불필요.
- **순수 배경 천**(슬라임 상호작용 없는 멀리 있는 깃발/커튼)은 별도 시스템 — Vertex Displacement Shader Graph(Time + Noise + 버텍스 컬러 마스크), CPU 비용 0, Tier 1로 강등. Verlet 천과 코드 공유 금지.
- Tier 3 선결 검증 항목: ① #4 로프 Verlet 코드를 `VerletField` 베이스로 일반화 가능 여부 ② 슬라임 푸시 공식(속도 직접 전달 vs 거리 감쇠) ③ 드래그 안전장치 3종(캡/누적 클램프/차징 예외)의 실제 commitment 원칙 보존 검증 ④ Z축 두께 처리 방식 (평면 vs 부풀린 메쉬, 3D 라이팅 받는 정도).

## 18. 탄력 나뭇가지 (Springy Branch)

**카테고리**: 플랫폼 (커스텀 각도 스프링)
**상태**: **완료**. `SpringyBranchPlatform` + `SpringyBranchVisual`.

**핵심 파일**:
- `Scripts/Platforms/SpringyBranchPlatform.cs` — 모터 (각도 스프링-댐퍼)
- `Scripts/Visual/SpringyBranchVisual.cs` — 본 체인 시각 휨 (에셋 무관)
- `Scripts/Editor/SpringyBranchTestSetup.cs` — 메뉴 `SlimeJumping/Setup SpringyBranch Test`

**구조**: HingeJoint2D 아님. PlatformMotor가 Kinematic Rigidbody2D를 강제하므로 HingeJoint2D와 호환되지 않음. 대신 커스텀 각도 스프링-댐퍼(PendulumPlatform 패턴)를 씀. 이렇게 하면 `PlatformCarrier.GetEffectiveVelocity()`가 `AngularVelocity × arm`으로 팁 속도를 자동으로 발사 속도에 더해주므로 `SlimeController` 수정 불필요.

**하이어라키 (중요)**:
```
BranchPivot   (월드 고정 위치, 회전만 함. Rigidbody2D + SpringyBranchPlatform)
  └─ BranchBody   (+halfLength 오프셋 자식, BoxCollider2D)
      └─ Bone_0, Bone_1 ...   (시각 체인)
```
피벗 오브젝트가 원호를 그리면 `motor.Velocity`와 `AngularVelocity × arm`이 둘 다 잡혀 이중 가산 버그가 남. 피벗은 반드시 제자리에서 회전만.

**펌핑 모델**: 슬램 임펄스와 차지 중 몸무게 이동이 같은 경로로 처리됨 (`Δp × riderPumpGain`, 2D cross 기반). 차지 중 기여는 `chargePumpScale`로 별도 배율 (0 = 공짜 타이밍 퍼즐, >1 = 고급 리듬 테크닉).

**디자이너 파라미터** (raw stiffness/damping 아님):
- `naturalFreqHz`, `dampingRatio` — 스프링 거동
- `riderPumpGain`, `chargePumpScale` — 에너지 유입
- `passiveDecayRate`, `riderDecayRate` — 지수 감쇠 (주파수와 독립)
- `maxTipSpeed` — 팁 선속도 하드 캡 = 런치 보너스 천장

**튜닝 규칙**: carrierVel은 벡터이므로 방향이 중요. 수직 방향 기준으로
- 단일 슬램 peak `|carrierVel.y|` ≥ 0.5 × 차지 폭
- N회 펌핑 정상상태 peak `|carrierVel.y|` ≥ 1.5 × 차지 폭
- `maxTipSpeed` = 절대 천장
탄력 나뭇가지는 기본적으로 **수직 타이밍 퍼즐**. 수평 이동 퍼즐이라면 휘는 방향을 발사 방향과 맞춰야 함.

**프리셋**:

| Preset | riderPumpGain | chargePumpScale | passiveDecay | riderDecay | 느낌 |
|---|---|---|---|---|---|
| Bouncy | 1.5 | 1.0 | 2.0 | 0.5 | 펌핑 빠름, 비우면 확 죽음 |
| Heavy | 0.7 | 0.5 | 0.2 | 2.0 | 펌핑 어려움, 올라타면 죽음 |
| PureTiming | 1.0 | 0.0 | 0.5 | 0.5 | 차지 중 펌핑 차단 |
| Rhythm | 1.2 | 1.5 | 0.3 | 0.3 | 차지-중-펌핑 보상 |

- VFX 인프라 사용: `ParticlePaletteBinder` Type=Lightning, HDR Emission + Bloom (코어 intensity 3~5), Cinemachine Impulse (0.15s).

**비주얼/텔레그래프 방식**:
- 볼트 렌더링: **Approach E (텍스처 + Shader Graph 하이브리드)**. 손그림 볼트 텍스처 2~3종 + Sprite Lit Shader Graph(HDR emission + sin flicker), URP Bloom으로 글로우. LightningHazard는 고정 위치 타격이므로 LineRenderer/procedural 불필요 (슬라임 추적형 변형이 생기면 그때 LineRenderer 추가).
- 텔레그래프: **DKC3 모델 — 1.5초 지면 마커 램프업**. T−1.5s 지면 스프라이트 마커(HDR intensity 1.0, cool color, 느린 펄스) → T−0.5s 펄스 가속 + warm color + intensity 3~4 + 크래클링 SFX → T=0 볼트(0.1~0.3s) + 풀스크린 흰색 플래시(0.3s 페이드) + 3D Point Light 플래시(2~4프레임, intensity 100~200).
- 충격감: **Cinemachine Impulse 사용** (수동 offset 금지). `CinemachineImpulseSource.GenerateImpulse()`, duration 0.15s, X/Y 축 한정, decaying intensity. ImpulseListener는 메인 VCam에 부착.
- Phase FSM: `WindZone2D`의 코루틴 없는 FixedUpdate 타이머 패턴 따르기 (Idle → Warning → Strike → Recovery). 타격 시점에만 1프레임 트리거 콜라이더 생성 → `ApplyHazardEffect(DamageType.Lightning)`.
- 타이밍 일관성: `telegraphDuration`은 인스펙터 노출하되, **같은 씬 내 LightningHazard들은 동일 값 사용** (Mike Stout 원칙 — 레벨 내 텔레그래프 타이밍 변동은 플레이어 학습을 깨뜨림).
- 사전 준비: URP Pipeline Asset에서 HDR 활성화 + Global Volume에 Bloom override(threshold 1.0, intensity 0.5~1.5) 설정 — 다른 발광 효과(#25 카메라 플래시, 점프패드 등)와 공유 인프라.

## 26. CCTV

**카테고리**: 자체 시뮬 (인테리어)

**슬라임 충돌**: 본체 BoxCollider2D(Z=0 variant)는 일반 surface로 작동, 어떤 효과도 없음.

## 28. 레인월드식 구역 카메라 (Rain World Zone Camera)

**카테고리**: 카메라 연출 (구역 한정 모드 오버라이드)
**상태**: 미구현.

**컨셉**: 베이스 카메라는 구구피자식 직접 추적(`SlimeCameraFollow` 그대로). 레인월드 느낌은 **특정 구역(zone)에 진입했을 때만 작동하는 모드 오버라이드**. 단일 카메라 + FSM 모드 전환 방식.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `SlimeCameraFollow.cs` | `Scripts/Camera/SlimeCameraFollow.cs` | 베이스 follow 로직 (그대로 유지) |
| `EnvironmentalZone.cs` | `Scripts/Mechanisms/EnvironmentalZone.cs` | trigger 진입/이탈 패턴 참고 |

**구현 방향**:
- **Cinemachine 도입 X**. 베이스가 이미 SmoothDamp 기반 직접 추적이라 Cinemachine으로 갈아엎으면 손해. 레인월드 lean이나 룸 클램프는 결국 커스텀 코드인데, 그러면 Cinemachine이 대신 해주는 게 거의 없음.
- `SlimeCameraFollow`에 **FSM 껍데기** 추가:
  - `Follow` (기본, 구구피자식 SmoothDamp 추적) — 현재 동작 그대로
  - `ZoneLocked` (레인월드 구역 진입 중) — 현재 sub-room의 bounds 안에 카메라 위치 클램프, sub-room 변경 시 하드 컷
  - `ZoneTransitioning` (진입/이탈 짧은 블렌드) — SmoothStep 0.3~0.5s
- **`RainWorldZone` 컴포넌트** (이 기능의 전부):
  - BoxCollider2D 트리거(zone 영역 전체) + 자식으로 **sub-room BoxCollider2D 배열** 보유
  - sub-room 1개면 단순 잠금 카메라, 여러 개면 스크린-바이-스크린 경험
  - 진입 시: `cam.EnterZone(this)` → `ZoneTransitioning` 짧은 블렌드 → 슬라임 위치 sub-room으로 `ZoneLocked` 진입
  - sub-room 간 이동: 슬라임이 다른 sub-room 영역에 들어가면 **하드 컷** (블렌드 없음)
  - 이탈 시: `cam.ExitZone()` → `ZoneTransitioning` → `Follow` 복귀
- **진입/이탈은 부드럽게, sub-room 간은 하드 컷** — 이 비대칭이 핵심. 베이스가 직접 추적이라 진입 순간 갑자기 잠기면 위화감이 큼. 하드 컷은 zone 안에서만 적용.
- `ClampToBounds(Vector3 pos, Bounds room)` 함수로 카메라 위치 제한. 룸이 카메라 뷰포트보다 작으면 중앙 고정.
- 파이프 전환은 #31 별도 기능. zone 안에서 #31을 호출하면 자동 통합됨.

## 31. 파이프 전환 (Pipe Shortcut)

**카테고리**: 오버라이드 + 월드 공간 비주얼 트래버설
**상태**: 미구현.

**컨셉**: 벽에 표시된 파이프 입구 마커(레인월드 가로줄 3개)에 슬라임이 **벽에 붙은 채로 안쪽으로 몸을 밀어넣으면** 흡수 모션과 함께 진입. 이후 슬라임 비주얼은 숨겨지고 **월드 공간에 점선 빛이 진행 방향으로 순차 점등**되어 벽 안에서 이동 중임을 시각화. 출구 마커에서 다시 등장. **화면 페이드 없음**, **카메라 변경 없음** — 같은 화면 내에서 처리. 결과적으로 슬라임 위치는 `TeleportTo`이지만 시간상으로는 점선 진행 시간만큼 걸림.

| 참고 코드 | 경로 | 용도 |
|-----------|------|------|
| `IExternalController.cs` | `Scripts/Interfaces/IExternalController.cs` | 트래버설 동안 슬라임 입력/물리 탈취 |
| `SlimeController.cs` | `Scripts/Controller/SlimeController.cs` | `SetOverride`/`ReleaseOverride`/`TeleportTo` |
| `Portal.cs` | `Scripts/Mechanisms/Portal.cs` | 페어 참조, 쿨다운 패턴 |
| `WaypointPlatform.cs` | `Scripts/Platforms/WaypointPlatform.cs` | 월드 공간 waypoint 경로 정의 패턴 참고 |

**구현 방향**:
- **`PipeEntrance` 컴포넌트** (페어 양쪽 끝 마커):
  - BoxCollider2D 트리거 + 자식으로 시각적 마커(가로줄 3개) + `pipeInwardDir` 인스펙터 벡터(입구 안쪽 방향)
  - `PipeEntrance pairedExit` 인스펙터 참조 (양방향 페어링)
  - **진입 조건 — 단순 트리거 진입 X, 의도 검증 필요**. 세 조건 모두 만족 시 진입 시작:
    1. 슬라임이 trigger 영역 안에 있음
    2. **입력 방향이 파이프 안쪽을 향함**: `Vector2.Dot(slime.AimDirection, pipeInwardDir) > 0.6`
    3. **슬라임이 Attached 상태로 입구 가장자리(벽)에 붙어 있음**: 공중에서 trigger를 스쳐 지나가는 케이스 자동 차단. 점성 슬라임의 stick 메커닉과 자연스럽게 맞물림 — "벽에 붙은 채 안쪽으로 미는" 동작이 진입 트리거.
- **`PipePath` 컴포넌트** (월드 공간 경로 정의):
  - `Vector2[] waypoints` — 두 입구 사이를 잇는 굴곡 경로. 직선이면 2점, 꺾인 파이프면 그 이상. Scene 뷰 핸들로 편집. 첫/마지막 waypoint는 두 PipeEntrance 위치에 자동 스냅.
  - 경로는 **벽 안쪽**에 그려져야 함 — 레벨 디자인 시 콜라이더 내부에 waypoint 배치.
- **`PipeDotTrail` 컴포넌트** (점선 비주얼, 월드 공간):
  - 경로를 따라 일정 간격의 작은 광점(`SpriteRenderer` 배열 또는 단일 `LineRenderer`)을 미리 배치. 평소에는 비활성/희미함, 트래버설 시작 시 활성화.
  - 진행 윈도우(동시 3~5개) 슬라이드 — 슬라임의 "현재 위치"를 따라 광점이 차례로 밝아졌다 어두워짐.
  - HDR emission으로 구현하면 URP Bloom과 자연스럽게 통합 (#20 번개와 같은 인프라 재사용).
- **`PipeTraversalController : IExternalController`** — 시퀀스 코루틴:
  1. **입력/물리 차단**: `slime.SetOverride(this)`. 차징 정리, 충돌 비활성. **이 시점부터 사용자 입력 완전 무시 — 흡수 모션 도중 취소 불가** (commitment 원칙).
  2. **흡수 모션** (0.4~0.6s): 점성 슬라임이 벽 안으로 스며드는 표현.
     - 슬라임 위치: 입구 가장자리 → 입구 중심으로 lerp
     - 비주얼 변형: `pipeInwardDir` 방향으로 stretch (안쪽 길이 1.0 → 1.4, 가로폭 1.0 → 0.7)
     - 후반부에 alpha fade out
     - Phase C 비주얼 시스템의 일반 deformation 비활성 — **`IsExternallyAnimated` 플래그** 필요. `PipeTraversalController`가 squash/stretch를 직접 주도.
  3. **점선 진행** (waypoint 경로 따라 균일 속도): `traversalSpeed` (월드 단위/초, 시작값 8~12)에 따라 progress 0→1 보간. 짧은 파이프(거리 5유닛) ~0.5s, 긴 파이프(거리 20유닛) ~2s. **카메라/화면 변경 없음** — 슬라임 시야 안에 점선이 그대로 화면에 보임.
  4. **출구 등장 모션** (0.2~0.3s, 흡수보다 짧게 — 빠른 게임 복귀 우선):
     - 출구 위치에 stretch된 모양으로 등장 (`pipeInwardDir` 반대 방향으로 길게)
     - 입구 가장자리로 lerp되며 정상 형태 복원
     - alpha fade in
  5. **위치 갱신**: `slime.TeleportTo(exit.position, exitVelocity)`. 출구 방향으로 작은 초기 속도 (점프 한 번 분량 이하).
  6. **입력 반환**: `slime.ReleaseOverride(this)`. `IsExternallyAnimated` 해제.
- **흡수/등장 모션의 비대칭**: 입구 0.4~0.6s, 출구 0.2~0.3s. 들어갈 때는 "몸을 밀어 넣는" 의도 표현이 중요해 길고, 나올 때는 빠른 게임플레이 복귀가 더 중요.
- **commitment 일관성**: 진입 의도 검증(3조건)을 통과한 시점부터 이미 commit. 흡수 → 트래버설 → 출구가 한 덩어리 시퀀스, 도중 취소 없음. 입구 근처에서 들락거리는 어색한 동작 방지.
- **출구 위치 제약**: 출구는 같은 카메라 화면 안에 있어야 함 — 단축 통로 용도가 본질. cross-room 이동이 필요하면 별도 기능. #28 zone 안에서 사용 시 출구가 같은 sub-room 안에 있도록 레벨 디자인.
- **연쇄 진입 방지**: 출구 도착 후 짧은 쿨다운(0.5s) 동안 양쪽 PipeEntrance 트리거 비활성. `Portal.cs` 쿨다운 패턴 차용.
